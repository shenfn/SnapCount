# 本地 AI 陪伴、记忆与 Planner 候选域开发交接

## 1. 本轮目标

围绕 App Store 首版，收口单设备本地 AI 表达链路：

```text
本地结构化事实
→ 本地记忆投影
→ 本地 AI 陪伴与 Planner 候选
→ 记录详情 / 收件箱 / 反馈卡片
→ 完整本地备份与换机恢复
```

本轮不做业务数据同步。`local_outbox_operations`、Supabase 同步 RPC、多设备冲突和远端记忆全部延期。现有同步代码保留，但新用户不启用同步，也不在本轮增加新的同步入口。

“本地化”指事实、记忆、Planner 候选和表达状态由本机编排并持久化；图片识别和文案生成仍可使用用户选择的 Hosted 或 BYOK Provider，但不因此建立后台业务同步。

## 1.1 当前实现进度

- 已完成：v32→v33 迁移、`local_companion_memories`、profile 级记忆 Repository、紧凑上下文 JSON、确定性 Planner 候选种子、完整备份 v29 兼容；本地消费、收入、四域详情和 Inbox 候选已接入确定性 Planner 卡片。
- 待完成：钱包详情适配、七域写入后刷新、记忆投影生成、Hosted/BYOK Companion 编排、导入后的记忆和表达结果回放。
- 当前验证：Swift parse 和 `git diff --check` 已通过；XCTest 和 macOS CI 尚未运行。

## 3. 产品与隐私边界

### 3.1 设置

| 设置 | 首版规则 |
| --- | --- |
| 云端同步 | 本轮不提供新功能入口。新 profile 保持 `sync_enabled = 0`；已有明确绑定不自动改写。 |
| 云端原图 | 新用户默认关闭；已有用户保留已有明确选择。 |
| AI 陪伴与记忆 | 默认开启，继续复用 `companion_enabled` 和 `companion_memory_enabled`。 |

不新增同义开关。`ai_logs_enabled`、`prompt_optimization_enabled`、`expression_improvement_enabled` 继续沿用现有服务端语义，不复制原始响应到本地业务库。

### 3.2 数据边界

- 记忆只保存结构化事实、偏好和聚合趋势，不保存原图、完整 Prompt 或未经处理的模型响应。
- AI 请求仍可访问用户选择的 Provider。若记忆开关关闭，AI 请求不得读取或更新本地记忆。
- 本地记忆不得通过 outbox 或后台任务上传 Supabase。
- 完整备份不得包含登录凭据、Supabase 访问令牌、API Key 或临时签名 URL。

## 4. 已有代码基础与缺口

- `local_records.payload_json` 已能保存域结构化内容和表达扩展字段。
- `local_expenses`、`local_income_records` 已有 `companion_message` 和 `ai_feedback` 字段。
- `LocalFactReader` 已能把消费、收入和四域正式记录统一成只读事实投影。
- `LocalRecordReadModel`、`LocalFactReadModel`、`LocalExpenseReadModel` 已能从本地数据恢复 `NativeAIFeedback`。
- 本地详情路径当前会提前返回，不会像远端详情一样请求 Planner；需要为本地记录接入本地 Planner。
- 远端 `getRecordExpressionPlan` 只适用于已登录云端记录，不能作为本地事实的唯一入口。

## 5. 开发切片

### 5.1 数据库与记忆 Repository

在 `LocalDatabase.migrator` 增加实际下一个迁移 `local-v33-*`，不得修改历史迁移。

新增 `local_companion_memories`，至少包含：

- `id`
- `profile_id`
- `memory_key`
- `memory_type`
- `content_json`
- `source_table`
- `source_id`
- `confidence`
- `updated_at`
- `deleted_at`

必须定义：

- `UNIQUE(profile_id, memory_key)`，保证 upsert 有确定目标；
- `profile_id / deleted_at / updated_at` 查询索引；
- `content_json` 合法 JSON 约束；
- `confidence` 的范围约束；
- `source_table`、`source_id` 的来源语义和软删除规则。

Repository 支持按 profile 读取有效记忆、按 key upsert、按来源删除、输出有大小上限的紧凑上下文 JSON。记忆失败不能回滚已经成功的业务事实；失败必须可通过重建投影再次处理。

### 5.2 本地表达上下文

新增统一的本地表达上下文，输入由以下部分组成：

1. 当前正式事实；
2. 近期本地事实摘要；
3. 当前有效记忆；
4. Planner 候选包；
5. Provider 能力和隐私策略。

当前事实拥有最高优先级。记忆只能改变表达角度和语气，不得创造当前事实中不存在的金额、时间、商户、频率或健康结论。

### 5.3 本地 AI 陪伴

- 正式记录写入成功后，异步生成或刷新本地 `companion_message` 与 `ai_feedback`。
- 消费、收入、food、sleep、sport、reading、wallet 都要走同一表达入口；待确认候选只在收件箱显示，确认后再进入正式事实统计。
- `companion_enabled = false` 时不生成新的 Companion 或 Planner；已持久化表达仍可展示。`companion_memory_enabled = false` 时不读取或更新记忆，同时不影响基于当前事实的确定性反馈。
- BYOK 或 Hosted Provider 可继续生成 Voice；本地编排负责提供结构化事实、记忆边界和 Planner 候选，不依赖同步状态。
- Provider 失败时保留结构化记录，并使用现有确定性反馈作为降级结果。

### 5.4 本地 Planner 候选域

本地 Planner 必须覆盖：

- `expense`
- `income`
- `food`
- `sleep`
- `sport`
- `reading`
- `wallet`

候选生成基于当前事实、近期事实和有效记忆，优先选择有直接证据的角度。候选至少携带：

- `candidate_id`
- `semantic_key`
- `claim_fingerprint`
- `presentation_target`
- `source = expression_planner`
- `dimension`
- `band`
- `emotion_line`
- `utility_line`
- `detail_reason`

复用 `NativeAIFeedback` 和 `NativeRecordExpressionFeedbackPolicy` 的展示、去重和事实覆盖规则：

- Planner 卡片不能覆盖已经展示的 Voice 事实；
- `presentation_target = feedback_card` 时作为独立卡片展示；
- `presentation_target = companion_message` 时必须与可见陪伴语的 claim 一致；
- 本地记录详情和收件箱都不能因为没有登录而失去 Planner 候选。

本地曝光确认只记录本机状态，不调用远端 acknowledge RPC。

### 5.5 写入接线

统一覆盖以下路径：

- `LocalRecordRepository.createRecord`、`updateRecord`、`deleteRecord`；
- `archiveStaging`；
- 消费、收入的创建、更新、删除；
- 待确认财务记录转正式消费或收入。

不能只在单一 Use Case 中接线，因为待确认财务路径会直接调用 Repository 静态插入方法。

### 5.6 导入导出

扩展 `LocalCompleteBackupPortability`：

- 完整备份格式从 `28` 升到 `29`；
- 加入 `local_companion_memories`；
- 保留记录、消费、收入、候选、钱包、图片和已持久化表达结果；
- 加入不含凭据的隐私设置和记忆开关；
- 导入旧版备份时记忆表缺失按空集合处理；
- 恢复后同步仍关闭，云端账户需要新会话重新绑定；
- 导出包继续排除凭据和临时 URL。

## 6. 明确延期

- 不新增 `record`、`income`、`companion_memory` outbox；
- 不修改生产 Supabase schema、RPC 或 Edge Function；
- 不实现多设备冲突和远端记忆；
- 不把 Hosted AI 的业务事实写入云端同步队列；
- 不先做设置页面大改版。

## 7. 上架验收顺序

1. 旧数据库从 v32 成功升级到 v33。
2. 新用户云端原图默认关闭，已有用户设置不被覆盖。
3. food、sleep、sport、reading、expense、income、wallet 各有一条本地正式事实时，均能生成本地 Companion 或确定性降级。
4. 本地详情和收件箱在未登录状态也能显示 Planner 候选域。
5. Planner 不重复覆盖 Voice，不生成无事实依据的金额、时间和趋势。
6. 关闭 AI 陪伴后记录仍保存；关闭记忆后不读不写记忆表。
7. 导出 → 新 profile 导入后，事实、记忆、表达结果、候选和图片引用保持一致。
8. 旧版完整备份仍可导入，导出包不含凭据、API Key 和签名 URL。
9. 现有本地记录、消费、收入、快捷指令和图片链路回归通过。
