### 1.3 三条必知的环境坑

**（a）SwiftPM 解析阶段直接失败**

```
Could not resolve package dependencies:
  sandbox-exec: sandbox_apply: Operation not permitted
```

这不是网络问题，是会话沙箱无法应用 SwiftPM 的 deny 型 profile。`-disableAutomaticPackageResolution`、换 `-clonedSourcePackagesDirPath`、`SWIFTPM_DISABLE_SANDBOX=1`、`env -i`、全新 derivedData **全部无效**。唯一有效的是 §1.2 第 2 步的 `defaults write`。

**（b）包解析过了，宏插件又失败**

```
SwiftMacros.TaskLocalMacro could not be found ... malformed response
```

`@State`、`@TaskLocal` 这类宏需要 `swift-plugin-server`，它自己也有沙箱。加 `OTHER_SWIFT_FLAGS='-disable-sandbox'` 即可。**这条参数要一直带着**，不要以为构建过了就可以去掉。

**（c）`xcodebuild test` 卡在签名**

```
Cannot code sign because the target does not have an Info.plist file
```

测试 bundle 之前没有 Info.plist 也没开自动生成。已在 `ios/project.yml` 的 `SnapCountTests.targets.settings.base` 补 `GENERATE_INFOPLIST_FILE: YES`（本次改动）。**这类修复必须落进 `project.yml`**，否则下一次 `xcodegen generate` 就没了。

### 1.4 云端配置：当前这份工程是「没配」的状态

事实（已核对）：

- `SnapCount/Info.plist` 里 `SupabaseURL` = `$(SNAPCOUNT_SUPABASE_URL)`，值来自 build setting。
- `ios/project.yml` **没有** `SNAPCOUNT_*` 任何一项，`project.pbxproj` 里也没有（`grep -c` 为 0）。
- `SnapCount/Services/GeneratedAppConfig.swift` 入库版本是空串。

结论：本地构建能跑、本机库与纯 UI 全部可用，但**登录、云同步、云端读取不可用**，单测里那条 `testEXP012NativeUploadRequestsStructuredResultAndPreservesFoodVoice` 会因 `SupabaseRemoteError.missingConfig` 失败。**这是配置缺失，不是代码缺陷。**

要临时打开云端能力，构建时按 CI 的方式传参（`ios-build.yml` 就是这么做的）：

```bash
xcodebuild ... build \
  SNAPCOUNT_SUPABASE_URL="https://<project>.supabase.co" \
  SNAPCOUNT_SUPABASE_FUNCTIONS_URL="https://<project>.supabase.co/functions/v1" \
  SNAPCOUNT_SUPABASE_ANON_KEY="<anon public key>"
```

anon public key 从 Supabase 控制台 Settings → API 取，**只用 anon，不要 service_role**。要长期生效：写进本地 `project.yml` 的 `settings.configs.Debug`（会进 git，注意密钥）或写进 `GeneratedAppConfig.swift`（已被跟踪，慎填）。

## 3. 本次改动清单

### 3.1 待处理页按 PWA 整页重构

**问题**：iOS 是「单列卡片 + 双列切换按钮 + 纯文字摘要」，PWA 是「页头范围切换 → 状态 chips → 日期分组双列胶片网格」。同功能两个长相，且 iOS 首屏被 12 张未识别完的图片卡各占一屏，把候选列表推到十几屏之后。

**改法**：新建 `InboxPendingLayout.swift`，结构 1:1 对齐 `PagePending.vue`；`InboxView` 只保留状态与路由。

| 缺陷 | 现象 | 处置 |
|---|---|---|
| D-06 | 12 张未完成图片各占一屏 | 合成一条可折叠横幅，展开后 52pt 缩略图紧凑行（约 1.4 屏） |
| D-07 | 「今天」下面永远 0 条 | 不是 bug：范围只认发生日期，73 条都在 2023-09～2026-10。改为分段直显 `今天 0`，空态解释真实原因 + 「查看全部 73 条」出口 |
| D-08 | 右上角空方块 | 实为单列/双列切换按钮。PWA 固定双列，删除 |
| D-09 | 标题「待确认」与筛选「待确认」同名 | 标题改「待处理」，筛选顺序按 PWA：全部→待分类→待确认→需重试→待修补→账单补全 |
| D-10 | 首页入口胶囊写「待确认 73」 | 统一为「待处理 73」（`MainShellView.swift`） |
| D-11 | 分组标题打印 `2026-10-31` | 新增 `NativeLocalDate.sectionTitle`，输出「10月31日 · 周六」 |
| D-12 | chips 把 0 计数全藏了 | 六个常驻、横向滚动，标签对齐 PWA（`待补全账单`→`账单补全`） |
| D-13 | 「今天」副标题折行顶歪分段 | 缩成单行「今天发生的记录为 0 条」 |

**卡片排版踩的两个坑**（改这块必看）

1. **金额被邻卡盖住**。根因不是 `lineLimit`，而是 `scaledToFill` 的图片固有尺寸把卡片撑宽、溢出栅格列。试过 `fixedSize()`、`layoutPriority`、`minimumScaleFactor` 全部无效。真正解法是给视觉区一个固定框：

```swift
Color(hex: "E7E4D9")
    .aspectRatio(3.0 / 4.0, contentMode: .fit)
    .overlay { if hasImage { imageVisual } else { InboxFactNoteVisual(item: item) } }
    .clipped()
```

2. **账单卡文字重影**。账单截图自带商户名和金额，叠加 scrim 说明会重影。已改为仅 `kind != .pendingExpense` 才显示 scrim 文字。

**有意偏差**：账单的「商户名 + 金额」在 iOS 分两行（PWA 同行）。窄列里同行必然裁金额，这是权衡结果，不是漏改。

**相关文件**：`InboxPendingLayout.swift`(新) `InboxView.swift` `Models/NativeInboxItem.swift` `Services/NativeDataService.swift` `Services/DashboardSnapshotStore.swift` `App/AppState.swift` `Features/Root/MainShellView.swift` `Models/NativeLocalDate.swift`

### 3.2 域详情页删除「当前待处理候选」

**问题**：明细页底部挂一整段未确认候选，73 条能把页面拖到十几屏，而「未确认候选」本来就属于收件箱。

**改法**：删掉 `currentCandidates` 私有视图与 `isDrillDown` 分支调用。

```swift
domainSections
// 明细页只呈现所选日期的事实；未确认候选属于收件箱，不再在这里重复一遍。
if !isDrillDown { observationEntry }
```

**验收**：记账明细底部「与前一天比较」之后直接是空态「这一天还没有记账记录」。全仓 `当前待处理候选` / `currentCandidates` / `最新候选` **零命中**。

### 3.3 「与前一天比较」改成卡片组件族

**问题**：九个句子同一字号同一颜色堆在一起，读者得逐行读才知道哪行是当天；差额多少要靠心算。放在有图表的详情页里像一段没排完的日志。

**改法**：抽出 `DesignSystem/JieziCompare.swift`，按「分组卡壳 → 小字标题 → 大数字 → 可视化 + 一句说明」四层重排。记账明细 = 一宽 + 两窄三张卡；记账首页双列卡也换成同族，底边齐平。

**语气色**：多花赭红、少花墨绿、持平中性灰（与中文涨红跌绿一致），色值全部取自各域 scene，未新增颜色。

**有意偏差**：对比卡用**实心 `surface` + 0.8pt 弱描边**，而不是其它卡的 `0.66~0.78` 半透明。详情页背景本身是米白纸，半透明只差 5~8 个色阶，框立不起来，而需求正是「用组件框起来」。

**已知不一致**：睡眠/饮食/运动/阅读四组指标卡仍是老 `metricCard`，与新卡并排会显旧（§6.1）。

### 3.4 收支明细时间列：兜底与排序

**现象**：左列出现「—」，唯一有值那条显示 `11:30:0 / 0`（折行）。

**三个原因，逐个解**

1. **「—」是数据真空**：`local_expenses` 里 11-02 四条只有一条有 `transaction_time`，其余 NULL，读模型把 `transactionTime` 原样当标签。
2. **折行是格式没处理**：存的是 `11:30:00`，带秒；列宽 42pt，`caption2` 等宽装不下 8 字符。
3. **兜底后排序错位**（改完才暴露）：多处在用 `timeLabel` 裸字符串降序比较，`上传 18:58` 的中文码位比数字高，被顶到 `11:30` 前面。

**改法**

- `NativeLocalDate` 新增 `clockKey`（截秒）、`listTimeLabel(recordTime:uploadedAt:)`（发生时刻优先，没有退到「上传 HH:mm」）、`listTimeSortKey`（把「是否兜底」编进排序键：真实时间在前，兜底在后）。
- 四个本机读模型统一走这个入口：`LocalExpenseReadModel` `LocalIncomeReadModel` `LocalRecordReadModel` `LocalFactReadModel`。**不只记账，睡眠/运动/饮食/阅读的当日记录也不再出现「—」**。
- 界面：时间列宽度不变，`上传 ` 前缀折成下一行 9pt 小字；时刻加 `lineLimit(1) + minimumScaleFactor`，以后再混进秒数也不折行。
- 排序统一到 `listTimeSortKey` 的五个位置：`chronologicalOrder`（`model.records` 真正入口）、`mergeRecordGroups`（AppState）、首页投影（`NativeHomeDashboard`）、`NativeDayRecord` 分组、`NativeDataService` 远端 `dayRecordGroups`。

**口径说明**：兜底时间标的是「记录进库时间」，不是「钱几点花的」，所以加「上传」二字而不是伪装成发生时间。历史迁移的数据会挤在同一刻，看起来集中——这是把「时间不可信」显性化，比留「—」让人以为 0 点更诚实。

**未动**：记录详情弹层里的「日期」行仍只显示日期（事实字段不适合放推断值）。若需要，可另加一行独立「上传时间」。

## 4. 踩坑清单

分四类。前两类来自 Obsidian 已有沉淀，后两类是本轮新增。

### 4.1 机器与环境（Obsidian `10-环境/`）

| 坑 | 症状 | 解法 |
|---|---|---|
| Homebrew 抢走 `xcode-select` | `requires Xcode, but active developer directory is a command line tools instance` | `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`；顺序上先装 Xcode 再装 brew |
| Xcode 许可未接受 | `git` / `xcrun` **无输出且不返回**，不是报错 | `sudo xcodebuild -license accept` |
| 受限 shell 里 `brew install` | 只报 `killed`，不报权限错误 | 下载预编译包铺到 `~/.local/opt`，在 `~/.local/bin` 放 wrapper；PATH 放 `.zprofile` |
| 下载慢/失败 | HTTP/2 framing error，或代理只有 17 KB/s | 先降协议 `curl --http1.1`；再用镜像前缀 `https://ghfast.top/<原地址>`（实测 3.7 MB/s，快 200 倍）。**不要在同一通路反复重试** |
| 下载被截断 | `ls -lh` 看着正常，装完出现各种诡异行为 | 必须 `shasum -a 256` + `tar -tzf` 校验 |
| 中文文件名 | `git status` 显示 `\344\272\244...` | `git config --global core.quotepath false` |
| dotfiles | 改了没生效 | 软链而非复制；`zsh -i -c`（zshrc）和 `zsh -l`（zprofile）都要验 |

### 4.2 Xcode 27 / 工程（Obsidian `10-环境/`、`30-工程/`、`20-调试/`）

| 坑 | 症状 | 解法 |
|---|---|---|
| `Simulator.app` 不存在了 | `open -a Simulator` 全失败 | 用 `open "/Applications/Xcode.app/Contents/Applications/DeviceHub.app"` 或 `open -b com.apple.dt.Devices`。注意是 `Contents/Applications/`（复数），不是旧的 `Contents/Developer/Applications/` |
| `Index.noindex` 空壳 | `find ... -path "*Debug-iphonesimulator*"` 命中没有 Info.plist 的壳，`simctl install` 不报错但装不上 | 用 `-showBuildSettings` 取 `BUILT_PRODUCTS_DIR`；或 find 加 `-not -path "*Index.noindex*"`；**最稳是固定 `-derivedDataPath /tmp/sc-dd`** |
| XcodeGen 静默覆盖 | 界面上改的签名 / entitlements / 密钥，下次 `xcodegen generate` 全丢且无警告 | 真源是 `project.yml`，手改 Xcode 后必须回填；本轮 `ios/SnapCount.xcodeproj` 已**整体不入库**，所以 clone 后必须生成，不要以为工程丢了 |
| 分支拓扑假象 | `merge-base --is-ancestor` 说未合并，其实代码早在里面 | squash merge 会让提交对象消失。用**两点 diff**（`git diff main branch`）看内容，不要用三点 diff 看提交 |
| 文件数统计偏大 | 212 个 Swift 算成 1459 | 排除 `*/.spm-packages/*` |
| Debug 包 82MB | 以为代码太大 | 57MB 是 `SnapCount.debug.dylib` + 24MB 是 `NotoSerifSC-Variable.ttf`。**Debug 体积不代表上架体积**（Release 约 28–32MB） |
| idb 装不上 | `idb-companion` 已不在 homebrew-core | 用 `meta/idb` 预编译包 + 独立 venv 装 `fb-idb`；先 `idb connect <UDID>` 才能操作 |
| Keychain -34018 | 本地 Debug 登录失败 | Debug 用 Apple Development + Automatic + Debug Keychain Sharing entitlement。**修完还要补 Supabase 配置**，两个错误会连着出现 |

### 4.3 本轮新增：模拟器操作

| 坑 | 症状 | 解法 |
|---|---|---|
| 点击落空 | `idb ui tap` 返回 ok，界面没变 | 坐标单位是**点**不是像素；点之前用 `idb ui describe-point x y` 反查，比点完看截图猜可靠 |
| 纵向滑动被当成翻页 | App 是横向 pager，`idb ui swipe` 纵向手势偶尔被判定为切页 | 用短距离滑动（如 `195 700 → 195 330`）+ `--duration 0.2`；每次点击后重新截图确认当前选中日期 |
| 截图看不出动没动 | 两轮操作后截图 md5 相同 | 每步都 `md5 -q` 对比，别凭感觉判断「应该切过去了」 |

### 4.4 本轮新增：SwiftUI / 数据层

| 坑 | 症状 | 解法 |
|---|---|---|
| `scaledToFill` 撑宽容器 | 栅格双列里金额被邻卡盖住，加 `fixedSize`/`layoutPriority`/`minimumScaleFactor` 都无效 | 给视觉区固定 `aspectRatio` 框 + `clipped()`，不要指望文字层自己收敛 |
| 中文字符串直接比较时间 | `上传 18:58` 排到 `11:30` 前面 | 排序键必须剥掉中文前缀或另建键（`listTimeSortKey`），**不要用展示字符串排序** |
| Optional 上 switch | `switch stagingRecord?.recordType` 易漏分支 | 先 `?? ""` 再匹配字符串 |
| 元组做 `Identifiable` | `[(String,String)]` 传给 ForEach 编译不过 | 建 `InboxBillFact: Identifiable, Hashable` |
| 新文件不生效 | 编译报 no such file / 改动看不见 | `ios/project.yml` 是按目录收源文件的，新增文件后要 `xcodegen generate` |
| 空态文案撒谎 | 「今天」0 条时提示「没有符合筛选的记录」，让人以为是筛选问题 | 区分「范围问题」与「筛选问题」，文案要说真实原因 + 给出路 |
