## 4. 对 `imported_row_count=0` 的解释

本地 `local_records`、`local_income_records` 和 unresolved 记录都早于当前 generation-2 检查点的开始时间；当前检查点的 `imported_row_count` 只表示这一代检查点提交时新增并入账的行数，不是本机当前历史库存总数。

因此，`imported_row_count=0` 不能单独解释为“没有历史数据”，也不能单独证明“历史迁移已经完整”。当前 ID 对账已经确认交易、正式记录、收入、暂存记录和账户都能在本地正式表、钱包快照表、待处理表或 unresolved 表中找到对应关系；剩余发布阻塞是页面统计和状态文案，不是这批历史数据的 ID 缺失。

这 20 条钱包记录的云端元数据显示：15 条具备 `snapshot_balance` 与 `account_snapshot_kind`，5 条两项都缺失；全部 `domain_version=1.0`，发生时间均存在，创建时间范围为 2026-05-17 至 2026-10-28。它们已经对应到本地 20 条钱包快照；另有 11 条被云端 `account_entries` 引用，3 条被 `account_repayment_cycles.evidence_record_id` 引用，说明钱包表不能从页面正式记录总数中省略。后续若重新跑映射，需要确认这 5 条缺字段记录是沿用已有本地快照，还是保留为历史待核对。

## 5. 对页面走查矛盾的影响

页面走查中看到的“正式记录 7”“unresolved 0”等摘要，与同一工作区数据库的 `local_records=253`、`local_history_unresolved_records=227` 不一致。后续页面修复必须统一统计口径，并在标签中明确：

- 正式记录：统计已写入 `local_records` 与 `local_wallet_snapshots` 的记录，并分别显示通用记录和钱包快照；
- 待处理账单：统计 `local_pending_transactions`，并区分 `pending` 与 `done`；
- 历史待核对：统计 `local_history_unresolved_records`，不能用迁移检查点的 `imported_row_count` 代替；
- 迁移完成：只表示检查点 scopes 已提交，不表示云端每一行都已经进入正式本地表。
