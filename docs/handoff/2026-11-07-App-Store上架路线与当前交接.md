## 3. 已完成的关键修复与证据

### 快捷指令识别

根因有两个：模拟器重装清空 `upload_token`，以及旧快捷指令从编辑器运行时截到了快捷指令页面，后端返回 `uncertain`。Intent 还曾把所有异常统一显示为“识别未完成”。

已完成：

- 统一输出凭据、网络、图片和不支持域的具体错误。
- HTTP 401 明确提示重新打开芥子同步登录。
- 快捷指令模拟器副本改为“选择照片 → 调整大小 → 转换 JPEG → 上传 JPEG 到芥子”。
- 上传地址兼容项目根地址和 `/functions/v1` 地址，避免重复拼接。

真实验证：

- 相册账单：拼多多，¥26.45，2026-04-27 15:47:06。
- 后端返回 200。
- `local_image_intakes.status=completed`。
- 正式本地消费已写入，记录页显示在 2026-04-27。
- 详情页和快捷指令结果均显示动态反馈“清楚入账 / 拼多多这笔已经归位，今天账面更清楚”。

### AI 与 Planner 口径

页面层沿用 PWA 优先级：存在 companion 或 Planner 时展示对应内容；没有时才使用结构化规则反馈或域兜底。正式账目详情是否显示反馈卡片必须继续以 PWA 当前行为为准，待确认页面需要重点验收。

## 4. 上架分阶段计划

### 阶段 A：冻结发布基线

目标：让后续每次修复都可追溯。

验收：

- 从当前 WIP 整理出发布分支和固定 tag。
- 明确保留哪些改动，禁止把旧 worktree 的 WIP 混入。
- `project.yml` 成为 XcodeGen 配置真源，清理 pbxproj 与生成文件漂移。
- CI 能从干净 checkout 构建同一 SHA。

### 阶段 B：本地数据与云同步收口

目标：确保用户登录、导入、离线使用和同步不会丢数据。

验收：

- 全新安装 → 登录 → 重启 → 会话恢复。
- 读取云端数量、刷新本机盘点、执行迁移、对账、重启恢复。
- 解释 `imported_row_count` 与本地记录数量差异，处理 unresolved 记录。
- 生成本地备份并验证导入导出。
- 退出登录后本地事实、云端绑定和 Keychain 清理符合预期。

### 阶段 C：五域与快捷指令回归

目标：确认识别结果进入正确日期、域和记录状态。

每个域固定一张脱敏图片，记录：识别候选、日期、字段、状态、详情页、AI 内容、重启恢复。

重点样本：账单、睡眠、饮食、运动、阅读、收入、钱包/待还。

快捷指令必须在真机完成：相册选择、当前屏幕截图、辅助键触发、失败重试、重复图片去重。

### 阶段 D：页面与交互收口

目标：解决详情页粗糙、信息层级不清和反馈重复。

顺序：

1. 记录详情页：原图、金额、域、时间、来源、状态、抽取字段、账户绑定。
2. 待确认页：失败图片缩略图、重试、手动处理、丢弃、反馈卡片。
3. 反馈卡片：companion、Planner、规则反馈的优先级和空状态。
4. 收件箱、设置、历史迁移、同步状态。
5. Dynamic Type、VoiceOver、窄屏和深色模式。

### 阶段 E：发布候选与 TestFlight

目标：从干净环境验证发布包。

验收：

- CI iOS Build 通过。
- 全量 XCTest 通过。
- 签名、entitlements、Supabase、快捷指令模板来自 `project.yml`/CI secrets。
- TestFlight 包安装、登录、迁移、识别、同步、导出、删号全部走通。
- App Privacy、隐私政策、服务协议、支持页和审核账号准备完成。
- 记录已知限制和审核备注。

提交前冻结版本号和 build，保存最终 SHA、CI run、IPA、测试报告、隐私资料和回滚说明。提交后只处理审核反馈，不再混入功能开发。
