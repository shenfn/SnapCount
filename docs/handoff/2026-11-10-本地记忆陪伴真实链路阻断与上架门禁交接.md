# 本地记忆陪伴真实链路阻断与上架门禁交接

## 0. 2026-11-11 复审结果

本轮已把之前断开的 Shortcut 本机记忆 Companion 代码链路接上：Hosted 与 BYOK 图片识别都只返回事实；事实正式保存在设备后，iOS 才读取同域本机摘要、用户表达偏好、当地时间和少量旧文案，调用 Hosted 或本机 BYOK 文案生成并把结果保存到本地记录。Hosted 使用登录会话 JWT；Shortcut 上传凭据仍只用于图片入口。待确认账单等用户确认后才触发生成。

这只说明本地代码和线上函数已更新，**不代表整条链路已跑通或文案达到用户要求**。本轮已部署 Supabase `ingest-receipt` v206（ACTIVE，保留 `verify_jwt=false`），并应用默认值迁移；数据库列默认值现为 `false`，查询到的 31 个现有账户仍为 `true`，没有被本次迁移覆盖。iOS Debug 编译通过，iPhone 17 / iOS 27.2 Simulator 的 626 条 XCTest 全部通过；Deno CLI 当前不可用，尚未重放真机快捷指令。GitHub Actions 工作流 #162 已完成 Release Archive、导出和 TestFlight 上传，Delivery UUID 为 `c73ac89d-cbd1-459f-a892-e2b3decff388`，等待 App Store Connect 处理。App Store 仍阻断。

另外补入近 30 天重复商户/类别的本机定性摘要（至少两条正式记录才产生），但真实数据是否能形成有用摘要、模型是否会自然使用，仍需登录真机对照验收。

## 1. 交接结论

**用户要的是 PWA 那种会结合个人习惯、当前记录、时段和表达偏好的自然陪伴。现在本机记忆接入的代码已完成，但效果与真实链路尚未验证，因此目标仍未完成，是用户明确的 App Store 上架阻断项。记忆卡片本身没有产品价值。**

如果后续只能产出“小额支出 / 已入账 / 分类记到某类”这类换商户名的模板，或只能证明接口返回 HTTP 200，不能算完成。用户已明确表示：达不到期望效果宁可不上架。

本阶段没有增加跨设备记忆同步、记忆 outbox 或新的业务数据云写入；PWA 现有行为不应被本次修复改变。

## 2. 用户确认的目标与验收标准

1. **本地记忆服务于陪伴生成。** 记忆开启时，iOS 从本机取当前记录同域、紧凑且有证据的个人摘要，随当前事实和 Planner 候选交给 Hosted AI。模型应能自然地理解“这笔新记录和用户近期习惯有什么关系”，而不是只拼接统计数字。
2. **生成效果要接近 PWA 的个人感。** 文案应结合当前事实、可靠的本地模式、用户 Companion 人格/语气/偏好、真实时段和近期表达去重；不能套固定句式。Planner 候选继续作为内部生成依据，**不另加本地 Planner/记忆反馈卡片**。
3. **记忆开关是硬隐私闸门。** 关闭时不能读取本地记忆表，也不能把 `local_memory_context` 发给 Hosted AI；Companion 总开关关闭时不发起生成。仅新用户的默认值关闭，不擅自覆盖已有用户明确选择。
4. **事实必须由当前记录支撑。** 本地摘要不能改变金额、商户、分类或日期，不能把弱相关性说成确定结论，不能伪造频率、统计口径或偏好。没有足够证据时宁可少说或返回空文案。
5. **保持本地优先边界。** 识别所需的图片沿用现有 Hosted Vision 路径；纯文本 Companion 请求只带当前结构化事实、受限候选和同域摘要，不附带原图或完整本地历史。记忆不写云端业务表、记忆表或同步 outbox。
6. **按真实快捷指令路径验收。** 使用已登录账户和当前 App Intent 快捷指令；覆盖记忆开/关、有/无历史证据、无日期小票和生成失败。HTTP 200、语法检查或模拟器启动本身不算用户体验验收。

### 3.1 最近一次真实 Shortcut 场景及证据边界

- 测试账户当时已登录；使用 iPhone 17 Simulator（iOS 27.2）和当前 App Intent 快捷指令。当前链接会调用 `com.jiezi.app.UploadScreenshotIntent`，无需旧版手填 `upload_token`。
- 输入是“青禾便利店”小票，两个商品 ¥3 + ¥6，合计 ¥9，纸面上没有日期。快捷指令实际动作是截取当前屏幕、缩放、转 JPEG，再调用 App Intent。屏幕来自相册查看界面，画面带有相册的“今天 21:13”界面信息。
- App 成功保存 ¥9 本地消费，详情页显示 AI Companion 和 AI 摘要；观察到的文案包括“晚上好，青禾便利店的9元小支出已归档”“青禾便利店 ¥9.00，这笔小额已落账”“分类记到生活，后面看一周频率”。Planner/本地记忆独立卡片未显示。
- 这证明 Shortcut → Hosted 识别 → 本地入账 → 陪伴字段可见的路径能运行；**不证明**识别器从无日期小票得到了正确日期（截图 UI 自带时间信息），也**不证明**陪伴消费了本地记忆。文案仍然像通用归档模板，不符合目标。
- Supabase 日志中看到函数请求 HTTP 200，但日志没有暴露请求 action 或 `local_memory_context`；HTTP 200 只能证明函数响应，不能证明记忆被用、结果被采纳或最终 UI 正确。

下一次无日期用例必须确保识别图片本身不带相册日期、状态栏或快捷指令 UI。当前 Shortcut 的“截屏”动作会把屏幕 UI 一并交给 OCR；需要让原图直接作为 Shortcut 输入，或在干净的全屏原图视图中运行，再核对最终本地 `transactionDate` 和详情文案。

## 4. 当前代码链路与断点

### 4.1 快捷指令图片入口（已运行）

```text
当前 Shortcut 截屏 → JPEG → UploadScreenshotIntent
→ LocalImageRecognitionUseCase.ingest
→ HostedAIImageRecognitionProvider
→ ingest-receipt operation=recognize_only
→ Hosted Vision 只返回事实（不读云记忆、不调用 Voice）
→ 自动正式入账 → 本机投影刷新 → 有效 JWT 调用 generate_local_expression → 写回本机详情
→ 待确认 → 用户确认入账后由 AppState 触发同一 Companion 生成
```

关键位置：

- [UploadScreenshotIntent.swift](../../ios/SnapCount/Intents/UploadScreenshotIntent.swift)：读取当前登录/上传凭据并触发本地识别 Use Case。
- [LocalImageRecognition.swift](../../ios/SnapCount/LocalData/LocalImageRecognition.swift)：调用 Hosted 图片识别并把响应保存为本地记录/待确认事实。
- [SnapCountUploadService.swift](../../ios/SnapCount/Services/SnapCountUploadService.swift)：`recognizeNativeImage` 发送 `operation=recognize_only`。
- [ingest-receipt/index.ts](../../supabase/functions/ingest-receipt/index.ts)：本轮改为 `recognize_only` 不调用 Voice、不加载云端 Companion 记忆和域画像；正常 PWA `ingest` 分支保留原逻辑。

### 4.2 本地 Companion 组合链路（已接入 Shortcut 图片入口）

```text
手工事实创建/编辑
→ AppState.scheduleLocalCompanion
→ 读取 Companion 偏好、设备当地时间
→ 仅在记忆开启时读取同域 compactContextJSON 和少量旧文案
→ HostedAICompanionProvider / BYOK Provider
→ generate_local_expression
→ 本地持久化 Companion / feedback
```

关键位置：

- [LocalCompanionComposition.swift](../../ios/SnapCount/LocalData/LocalCompanionComposition.swift)：把事实、Planner 候选和本机摘要发给 Hosted/BYOK provider。
- [AppState.swift](../../ios/SnapCount/App/AppState.swift)：手工新建/编辑和本机待确认财务记录确认后触发；Shortcut 自动正式入账由 `LocalImageRecognitionUseCase` 使用同一上下文构造器。
- [LocalCompanionMemoryRepository.swift](../../ios/SnapCount/LocalData/LocalCompanionMemoryRepository.swift)：返回当前域最多 8 条、每条至多 240 字的摘要。
- [ingest-receipt/index.ts](../../supabase/functions/ingest-receipt/index.ts)：只读 `generate_local_expression` handler 已存在。

### 4.3 本轮接线后的重要边界

- Hosted Companion 仅用 Keychain 登录会话 JWT 鉴权；JWT 失效且刷新失败时跳过文案生成，已保存记录不受影响。图片上传 `upload_token` 不用于文案 action；BYOK 文字生成使用设备保存的 Qwen Key。
- OCR 直接归档后的记忆投影刷新已补；待确认财务事实要在用户确认后才进入正式投影并生成 Companion。
- 本机摘要新增重复商户/类别的定性模式；低于两条正式记录时不产生模式，不把待确认记录算入记忆。
- iOS 编译和 626 条 XCTest 已通过；这些仍未证实真实商户字段、历史摘要和最终生成语气在登录设备上正确。

## 6. 隐私与数据边界

- 新用户的记忆开关默认关闭；已有用户明确设置保留。
- 开启时只将必要的当前事实、同域紧凑摘要、Planner 候选和有界表达偏好发给 Hosted 文案生成；不要发送全部记账历史或原图到 Companion 纯文本调用。
- 关闭时不读记忆表、不构造摘要、不发该请求字段。不能只在服务端丢弃摘要而客户端仍读取。
- 不创建记忆云端表写入、不增加 memory sync outbox、不修改跨设备冲突协议；本轮应用的迁移只调整新行默认值，没有改写已有用户设置。
- Hosted 失败时本地事实成功保留；BYOK 只在用户明确选择时使用其 Key。不得把模型超时变成事实写入失败。
- 记录 AI 生成失败或诊断时不记录摘要原文、API key、JWT、upload token 或小票内容。

## 7. App Store 上架门禁

**以下全部达成前，不把当前分支当作 1.0 发布候选，不上传新的 App Store 构建：**

- Shortcut 图片路径上的本地记忆 Hosted Companion 已接通，而非只接手工编辑路径。
- 登录状态下真实测试记忆开启/关闭；开时个人化自然且可追溯到本地证据，关时确认无记忆读取和发送。
- 记忆投影能表达有用的本地模式，不只是笔数和总额，并覆盖 OCR 自动归档刷新。
- 模型失败、请求失败或无记忆时记录仍完整入账，重复图片仍幂等，事实字段不被 Companion 改写。
- Companion 文案接近 PWA 自然度；不出现固定套话、无依据的“你总是/又一次”或武断作息建议。
- Planner 作为内部生成上下文工作，不显示额外本地反馈卡；PWA 原流程不回归。
- 备份恢复和本地记忆开关的既有规格没有被本轮路径破坏；无新增跨设备同步或远端业务写入。
- 冻结发布 SHA `3fa7cd5`，在 TestFlight #162 上做真机验证。旧 TestFlight #160 不是当前分支代码的验证包；即使 #162 处理完成，也不能替代真实快捷指令和记忆开关对照验收。
