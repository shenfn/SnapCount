## 必须拆分或补证据的问题

### 1. 不是纯视觉提交

PR 新增本地 nickname 偏好、`AppState.lastDashboardSyncedAt` 暴露和刷新时间语义调整。这些内容涉及用户偏好、状态语义和数据同步反馈，不应隐藏在视觉改动里。

处理建议：

- 首页布局和组件先保留在视觉切片。
- nickname 偏好单独记录隐私范围、清理行为和多用户切换测试。
- 同步时间语义单独补状态测试，证明只在成功发布或恢复快照后更新。

### 2. “芥子低语”是确定性业务规则

`NativeHomeWhisper.make` 根据日期、记录数、待处理数和小时生成文本。它不是纯装饰；其数字和时间窗口必须有特征测试，且不能替代服务端事实或 AI 表达契约。

最小测试场景：

- 今日无记录、无待处理。
- 今日无记录但已有待处理。
- 有记录且跨越 23:00/05:00 边界。
- 非今天日期不使用“今天”语义。
- 待处理数量变化不会造成事实与文案不一致。

### 3. 当前 PR 没有新增测试

现有 diff 没有新增 XCTest 或快照证据。Windows 不能得出 Swift 编译结论，必须在 macOS CI 验证：

- 原有 `SnapCountTests` 不回归。
- `NativeDayGreeting` 和 `NativeHomeWhisper` 的纯函数测试通过。
- 首页小屏、大屏、动态字体、浅色/深色状态可截图复核。

### 4. 设计 Token 使用不完整

`HomeMastheadView` 中存在白色背景、固定 10/30 间距、字体和透明度等局部常量。它们应优先映射到生成 Token；若确需视觉特例，应在设计规范中记录原因，不能形成第三套首页样式。

### 5. HTML 提案不应进入 iOS 代码 PR

`docs/ios-home-redesign-proposal-v0.1.html` 是设计审阅素材，应保留在设计文档/素材范围，不与 Swift 页面代码一起作为生产实现提交。

- 现有 AppState、Repository、导航、保存、删除和确认门禁未被整体替换，具备拆分修正的基础。
