## 8. 2026-11-06 快捷指令相册识别复测（证据待重验）

### 根因

1. 模拟器重装后清空了 `upload_token`，快捷指令请求会返回 401；此前 Intent 把所有异常都压成“识别未完成”，无法区分凭据失效、网络错误和图片内容不支持。
2. 原快捷指令第一步是“截屏”。从快捷指令编辑器或 URL 启动时，曾观察到它截到快捷指令页面并返回 `domain_key=uncertain`；这只能解释旧模板的那次输入，不能作为 2026-11-06 新 App Intent 复测的根因。新 App Intent 在重编译/重装后出现过行为变化，必须固定 build 和真实账单输入重新验证。

### 已完成修复

- `LocalImageRecognitionFailureMessage` 统一给快捷指令、相册入口和收件箱保留具体错误原因，并说明原图是否已保存。
- HTTP 401 明确提示重新打开芥子同步登录凭据。
- 快捷指令同名副本在模拟器中把第一步替换为“选择照片”，调整大小动作绑定到“照片”输出，再保留 JPEG 转换和“上传 JPEG 到芥子”。

### 一次成功样本（不能作为当前构建稳定证明）

- 从模拟器相册选择真实账单图（拼多多，2026-04-27 15:47:06）并运行 `芥子- 截图`。
- 后端返回 200；本地 `local_image_intakes.status=completed`。
- 正式记录：支出 ¥26.45，商家“拼多多”，日期 2026-04-27，时间 15:47:06，分类 shopping，支付方式“拼多多先用后付”。
- 记录详情页按 2026-04-27 展示，AI 卡片显示“清楚入账 / 拼多多 这笔已经归位，今天账面更清楚。”；快捷指令结果弹窗也返回同一条动态文案。

后续复核发现，重编译/重装后 App Intent 行为发生变化，因此本节成功样本不能单独证明当前发布候选的稳定 E2E。需要在固定构建上重复真实账单测试，并保存 build、输入图片、HTTP 响应和本地状态证据。

### 真机复用

真实设备上的辅助键绑定仍按快捷指令名称生效，但快捷指令内容需要同步为“选择照片 → 调整大小 → 转换 JPEG → 上传 JPEG 到芥子”。当前 IDB 只发现模拟器目标，未连接物理 iPhone，因此辅助键本身未在真机上代按。
