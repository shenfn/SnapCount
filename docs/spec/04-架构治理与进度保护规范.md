# 架构治理与进度保护规范

> 文档编号：GOV-002
>
> 状态：试行
>
> 目标：即使 Agent 更换、上下文压缩或任务中断，也不会静默改变总体方向或覆盖已有 WIP。

## 1. 适用范围

本规范适用于 PWA、iOS、Edge、Supabase、跨端契约和架构治理任务。一次性脚本或不改变行为的纯文档修改可以使用轻量记录，但不得把重要决策只留在聊天中。

## 2. 唯一入口与指针链

恢复顺序固定为：

```text
AGENTS.md
→ docs/spec/规格文档索引.md
→ docs/spec/03-阶段与任务索引.md
→ docs/spec/05-仓库清洗与架构收拢实施计划.md
→ 当前模块 Spec
→ 相关 ADR
→ 当前任务交接快照
```

每一级只负责指向下一级，不在多个文件复制同一份当前状态。入口文件缺失、链接失效或状态冲突时，必须暂停并报告。

## 3. 工作区与分支

1. 新任务从最新父分支建立干净 worktree。
2. 一个 worktree 只承载一个任务。
3. 有未提交 WIP 的 worktree 不接收新任务。
4. 根工作区和其他任务 worktree 默认只读，不得顺手清理。
5. 新分支使用 `feature/中文短名`、`fix/中文短名`、`refactor/中文短名`、`docs/中文短名` 或 `test/中文短名`。
6. 旧的 `codex/*` 分支先登记，不在本规范任务中批量改名。

## 4. 任务记录

每个非平凡任务至少记录：

- 稳定任务编号；
- 用户价值和范围；
- 明确的非目标；
- 影响的模块和文件类别；
- 测试层映射；
- 当前状态、未验证项、剩余风险和下一步。

## 5. 决策记录

反直觉、跨模块或会影响后续实现的决策写入 ADR，至少包含：

- 决策内容；
- 背景和替代方案；
- 选择原因；
- 影响范围；
- 禁止被“顺手清理”推翻的边界。

## 6. 收尾与接续

任务结束前必须更新阶段索引或交接快照。新会话不得凭上下文摘要继续，必须重新读取指针链，并确认：当前阶段、冻结范围、任务范围、验证基线、已完成内容和下一步。

## 7. 验收标准

治理机制通过以下演练才算可用：开一个全新会话，只提供仓库路径和任务编号，不提供历史聊天；Agent 能在几分钟内指出当前阶段、冻结范围、任务 Spec、验证基线和下一步。演练结果写入带日期的交接记录。
