# PWA 与 iOS 视觉设计实施规范

> 规格编号：DESIGN-001
>
> 状态：草案
>
> 基线：`origin/main@6d36bf1`
>
> 适用范围：PWA、iOS、共享设计 Token

## 1. 目标

在不改变业务事实、状态机、账户影响、AI 口径和数据访问边界的前提下，逐步统一 PWA 与 iOS 的信息层级、视觉语言、组件状态和发版展示质量。

本规格允许视觉工作与 Phase 3 的 `expression-core` 试点并行，但不允许借视觉重构提前实施 Phase 4 的状态管理、Repository、AppState 或服务层重构。

## 2. 当前决策

- iOS 首页只继续评估 PR #25（`codex/ios-home-redesign`）；`ios-home-v3-native` 不再推进。
- 设计 Token 唯一来源是 `trae-design-system/tokens/design-tokens.json`。
- PWA 与 iOS 可以使用不同布局和平台控件，但金额、日期、状态、记录引用和导航目标必须一致。
- 首页作为第一个试点；首页验收完成前，不并行重做待处理、记录、数据域和设置页面。

## 3. 允许立即开展

- 页面信息层级、留白、排版、图标、色彩、动效和响应式布局。
- 共享 Token、生成器和已有设计组件的接入。
- 首页的加载、空态、错误态、部分数据可用和长文本展示。
- PWA 桌面/移动布局与 iOS 系统控件的差异化设计。
- 不改变业务行为的可访问性、动态字体、点击区域和对比度改进。
- 脱敏演示账号下的截图、视觉验收和发版素材准备。

## 4. 暂不允许

- 拆分或重写 PWA `useStore`。
- 从 iOS `AppState` 抽业务编排，或改写 `NativeDataService`、Repository Protocol。
- 新增页面到 Supabase 的直接调用。
- 修改数据库迁移、RPC、账户流水、删除级联或生产配置。
- 修改 Planner、Prompt、AI 事实来源、统计口径或陪伴表达算法。
- 为了视觉效果隐藏失败出口、确认门禁、来源字段或账户影响。

遇到上述内容时必须停止当前视觉切片，转入对应模块 Spec 和 Phase 3/4 流程。

## 5. 分阶段范围

| 阶段 | 页面 | 目标 | 进入条件 |
|---|---|---|---|
| D1 | PWA 首页、iOS Today 首页 | 建立跨端首页信息层级和组件状态 | 本规格评审通过 |
| D2 | 待处理、记录列表和详情 | 统一状态、操作反馈和长内容密度 | D1 验收完成 |
| D3 | 数据域、账户、分析和设置 | 统一指标、趋势、表单与配置展示 | D2 验收完成 |

每个阶段分别使用 PWA 和 iOS 实现分支，不把两端代码放进同一个实现提交。

## 6. D1 首页行为不变量

### DESIGN-001：首页事实来源

- 首页金额、日期、记录数、账户状态和今日记录只展示现有 ViewModel/Adapter 提供的事实。
- 视觉组件不得自行重新计算余额、统计或时间归属。
- 部分模块加载失败时保留成功模块，不用全空态覆盖有效内容。

### DESIGN-002：导航和操作

- 点击记录、日期、待处理入口和账户入口仍进入原有语义目标。
- 保存、删除、归档、确认和重试门禁不因视觉重构改变。
- iOS 保留 `AppState`、Repository 和 NavigationRoute；PWA 保留现有 Store/API 调用边界。

### DESIGN-003：稳定状态

- 加载、空数据、错误、部分失败、离线恢复和长文本均有稳定布局。
- 最长金额、最长商户/标题和系统动态字体不能遮挡相邻内容。
- 固定格式组件使用稳定尺寸或响应式约束，状态切换不得造成明显布局跳动。

### DESIGN-004：跨端一致性

- 两端共享信息优先级和业务语义，不要求像素一致。
- PWA 可以提高桌面信息密度；iOS 使用渐进式披露和系统导航。
- 同一记录在两端展示的金额、日期、状态和目标详情必须一致。

### DESIGN-005：可访问性

- 主要点击区域不小于平台建议尺寸。
- 文本和背景满足可读对比度；颜色不是状态的唯一表达方式。
- iOS 动态字体与 PWA 200% 文本缩放下，关键内容仍可访问。

## 7. 设计系统约束

- 先修改 Token，再运行 `generate-ios.mjs`、`generate-css.mjs` 等生成器。
- 不手改 `trae-design-system/dist/` 或生成的主题文件。
- iOS 优先使用 `JieziType`、`JieziSpacing`、`JieziRadius`、`JieziCard`、`JieziSectionHeader`、`JieziListRow`、`JieziMetric`、`JieziEmptyState`。
- PWA 优先使用现有语义变量和页面组件，不在单页新增第二套全局色板。

## 8. 验证策略

### PWA

- `npm run build`。
- 页面现有行为测试和关键契约测试。
- Playwright 在移动端和桌面视口检查加载、空态、错误、完整数据和长文本。
- 检查控制台错误、横向溢出、遮挡和布局跳动。

### iOS

- Node 设计生成器和静态差异检查。
- GitHub Actions macOS iOS Build 与 XCTest。
- 模拟器截图验证小屏、大屏、动态字体、浅色和深色模式。
- Windows 不作为 Swift 编译或最终视觉通过证据。

## 9. 每个页面切片的完成定义

1. 页面范围和非目标已写入对应执行记录。
2. 行为不变量有现有测试或新增特征测试保护。
3. 视觉变更没有修改数据层、业务状态或生产配置。
4. PWA 构建/浏览器截图或 iOS macOS CI 通过。
5. 加载、空态、错误、部分失败和长文本均已验收。
6. 交接快照记录修改文件、验证结果、未验证项和下一页面。
