# iOS 本地优先与 PWA 维护模式实施计划

> 计划编号：LOCAL-PLAN-001
>
> 状态：已批准，L0 已完成，处于 LOCAL-SPIKE-001
>
> 基线：`origin/main@dc482ac`（2026-08-22）
>
> 目标：在不破坏当前云端版本、PWA 和既有用户数据的前提下，将 iOS 渐进升级为免登录、本地优先、可选同步、AI 可插拔的个人数据产品。

## 1. 产品决策

用户首次打开 iOS 时直接开始，不要求注册或选择技术模式。产品只在需要时呈现两个独立设置：

```text
数据：默认本机保存 -> 用户主动开启云端同步时登录
AI：关闭 / 使用应用 AI / 使用我的 API Key
```

PWA 继续作为登录后的云端客户端和管理入口。它只能看到已同步到云端的数据，不承诺展示 iOS 尚未同步的本地记录。

## 2. 架构目标

```text
View -> AppState -> Use Case -> Local-first Repository
                                  |-> Local Database
                                  |-> Outbox
                                        -> Sync Engine -> Supabase

Use Case -> VisionProvider / ExpressionProvider
             |-> Disabled
             |-> Hosted AI
             |-> BYOK
```

核心原则：

1. 本地写入不等待网络或 AI。
2. 同步失败不撤销已成功的本地业务事实。
3. AI 失败不阻止手动记录和本地保存。
4. 登录只解锁云同步和需要身份的托管能力，不是核心使用门槛。
5. 套餐是能力组合，不进入领域模型和 Repository 分支。

## 4. PWA 维护边界

PWA 继续使用当前 Supabase 云端架构。本计划不要求 PWA 接入本地数据库、免登录或 BYOK。任何 PWA 新需求默认延期，除非属于：

- P0/P1 缺陷、安全或隐私修复；
- 云同步后的数据查看、管理、导出和兼容；
- 共享契约或 Supabase 变更导致的必要适配。

## 5. 首片范围

LOCAL-002 只处理消费记录和支持它所必需的最小本地账户，不处理：

- 收入、睡眠、运动、阅读、饮食等其他域；
- 图片识别、Hosted AI、BYOK 实现；
- 多设备自动冲突合并；
- 生产迁移、TestFlight 或套餐付费。

## 6. 关键待裁决项

| 决策 | 当前状态 | 解决阶段 |
|---|---|---|
| GRDB/SQLite 或 SwiftData | 已选择 GRDB/SQLite，见 ADR-037 | LOCAL-SPIKE-001 已裁决 |
| 本地数据库是否额外加密 | L1 先落实 iOS Data Protection；SQLCipher 由独立威胁模型和 ADR 决定 | L1/安全评估 |
| 本地匿名 profile 的生成与登录绑定 | 原则已定，字段和迁移未定 | L1 |
| 同步冲突策略 | 未决定；账户禁止最后写入覆盖 | L3 |
| BYOK 首批供应商和直连能力 | 未决定；需验证 SDK、CORS、审核和隐私条款 | L4 |
| Hosted AI 免费体验额度 | 商业决策，不进入领域架构 | 发布前 |

## 7. 最高规格验证

每个实现阶段必须遵循 Spec-first、特征测试或有效红灯、最小实现、回归、macOS CI 和交接快照。至少覆盖：

- 免登录、断网、重启、低存储空间和数据库迁移失败；
- 用户切换、登录绑定、退出后本地数据归属；
- 重复导入、重复同步、删除 tombstone 和恢复；
- AI 关闭、Hosted 失败、BYOK 失效和 Key 撤销；
- 本地模式无业务数据访问 Supabase 的网络闸门；
- 现有云端用户升级不丢失、不重复、不静默改余额。

## 8. 发布与回滚边界

- 当前云端版本继续作为稳定基线，不在 L0/L1 删除 Supabase 表或 Edge 路径。
- 本地优先功能必须使用可关闭的内部能力开关渐进验证，但开关不能演变为多套业务实现。
- 没有导出恢复、迁移回滚和审核 Demo 前，不把免登录本地模式作为不可逆默认发布。
- 任何生产迁移、部署或 TestFlight 仍需用户在当前任务明确授权。
