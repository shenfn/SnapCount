## 目标与范围

- Repository 调用 `discard_staging_record` 并映射结构化清理结果。
- Discard Feature 负责同 ID 去重、session generation、失败保留和 accepted 后本地收敛分层。
- `useStore` 保留确认、提示、本地列表和公开 API；不再直调丢弃 RPC。
- 页面和批量动作只把 `accepted` 当作业务完成。
- 不修改中转读取、图片签名、数据库、Edge、iOS 或生产配置。

## 红灯证据

- PWA-042 Repository：`repository.discard is not a function`。
- PWA-043/PWA-044/PWA-046 Feature：`createStagingDiscardFeature.js` 不存在。
- PWA-042 Facade：`useStore` 不含 `createStagingDiscardFeature`，且仍直调 RPC。
- PWA-045 页面与批量：批量只检查 truthy 返回；详情页在 await 后无条件推进。

## 最小实现

- `stagingRepository.discard` 只传 `p_staging_id`、`p_reason`，映射 cleanup status，不传用户 ID。
- 新增 `createStagingDiscardFeature`，共享重复请求并在 reset 后拒绝旧会话响应回写。
- accepted 后本地收敛失败仍返回业务成功与明确 `convergenceStatus`，不重发写操作。
- `useStore.discardStagingRecord` 收窄为 Feature 门面；批量和 `PagePending` 只认 accepted。
- 安全契约从“RPC 位于 Store”收紧为“RPC 位于 Repository 且 Store 禁止直调”。
- Release Validation 新增 `test:staging-discard`。
