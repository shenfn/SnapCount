# LOCAL-AI-003 全域共享 Planner 接入

设备读取当前 profile 的正式记录，运行 PWA 共用的候选、资格和选择规则。同域正式记录沿用原有的本机统计规则。记忆摘要、最近文案和跨记录关联由陪伴记忆开关控制。Hosted 仅接收当前事实、一个已计算观察和受限证据引用。原始历史留在设备。该请求只用于生成文案。

| 场景 | 输入与预期 | 验证 |

| LOCAL-AI-003-PARITY-LIFE | 历史睡眠、同餐次饮食、运动及阅读。得到对应的时刻、餐次和个人基线候选 | 同上，另验 Hosted 睡眠字段 |
| LOCAL-AI-003-PARITY-WALLET | 同账户同类快照可比较，异账户和异类不可比 | 同上 |
| LOCAL-AI-003-PARITY-RELATION | 可信历史中时间接近且对象重合，关联仍为假设 | 同上 |
| LOCAL-AI-003-PARITY-TRANSPORT | Hosted 只接收选中观察及证据引用，丢弃越界包；记忆关闭时无跨域关联和记忆摘要，同域正式统计仍可用 | iOS 请求与 Edge 契约 |

改动范围为正式事实投影、伴随生成上下文、共享 Planner 的 iOS 运行入口和 Hosted 请求验证。Prompt、页面和业务同步沿用现有流程。

## 实现和复验

- iOS 从同一 profile 的正式记录构造输入，通过 JavaScriptCore 运行打包后的共享 Planner。支出复用完整候选规则，收入及五个生活数据域复用通用 Planner。历史明细、图片路径和图片散列均留在设备。
- Hosted 只接受当前记录绑定的单个观察和最多八个证据引用。诊断区分观察被接受、没有可用观察、被接收规则拒绝、服务端版本尚不支持。客户端观察只用于生成文案，服务器校验版本、格式和引用，历史运算由设备负责。
- 仿真核对同样本的支出及阅读选句指纹。其余域覆盖了特有候选和 Hosted 接收，跨域覆盖候选及关闭开关后的缺席。验证了睡眠 UTC 转北京时间、收入的业务日月界，以及选中的观察进入实际文案请求构造器。
- `npx --yes deno check supabase/functions/ingest-receipt/index.ts` 已通过。全域、旧支出兼容和文案上下文合计 32 项测试通过。生成资源可用 `node scripts/generate-ios-companion-planner.mjs --check` 校验。
- PWA 云端既有的展示次数、历史点评权重仍由云端 Planner 使用。iOS 的基础候选与打分规则已共用，未迁入这些个人历史权重。
- 变更留在本地诊断分支。使用新请求格式的 iOS 构建和 Hosted 版本需要配套验证。实际模型输出、线上部署和真机验证尚未执行。
- iPhone 17e iOS 27.2 模拟器全量回归 666/666 通过。其中快捷指令睡眠样例覆盖识别、保存、发送共享观察、读取接收状态及结果持久化。模型响应使用固定测试回包。
