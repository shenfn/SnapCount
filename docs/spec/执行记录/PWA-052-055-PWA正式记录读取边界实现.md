## 目标行为

- 正式记录查询 transport 和 DTO 映射由 Record Repository 唯一持有。
- Store 保留并发、用户/run guard、失败分层和页面状态编排。
- 未绑定财务记录复用相同月份口径和 DTO。

## 当前行为

- `loadData` 直接查询交易、收入和通用记录并映射 DTO。
- `loadUnboundRecords` 再次直接查询交易/收入并重复映射。
- PWA-056 缺少可靠的持久化目标类型，不能安全按显式类型读取。

## 权威来源

- 查询字段和历史失败出口：`src/composables/useStore.js` 当前特征行为。
- 上海时间范围：`src/utils/financeOccurrence.js`。
- 读取边界：`正式记录读取规格说明.md` 与 ADR-021。

## 红灯测试及失败原因

- `recordRepository.js` 不存在，Repository 行为测试报 `ERR_MODULE_NOT_FOUND`。
- Store 源边界未找到 `createRecordRepository` 和六个读取方法调用。
- `loadData` 与 `loadUnboundRecords` 仍直接查询正式记录表。
- 红灯失败均来自目标行为缺失，不是凭据、网络、依赖或测试环境问题。

## 最小实现

- 新增只读 `recordRepository`，持有月度/待补全支出、月度/最近收入、通用记录和未绑定记录查询。
- 将 `mapIncomeRow` 与 `mapDataRecordRow` 移到 Repository，交易继续复用现有 `mapTransaction`。
- `loadData` 消费结构化 Repository 结果，保留 current user/run guard、失败分层和派生读模型。
- `loadUnboundRecords` 消费统一 DTO，保留 loading、页面提示和状态写入。
- Release Validation 新增 `test:record-read`。
- 发生时间静态契约改从新的 DTO 权威文件验证收入 `occurredAt`，保存 RPC 断言仍留在 Store。
