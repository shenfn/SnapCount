## 目标与范围

- Repository 持有开放/已处理 `staging_records` 查询 transport 和 DTO 映射。
- `useStore.loadData` 只消费结构化 Repository 结果，保留并发编排和 current user/run guard。
- 图片签名、还款候选、正式记录、数据库、Edge、iOS 和生产配置不在本片。

## 红灯证据

- `repository.listOpen is not a function`。
- `repository.listProcessed is not a function`。
- Store 源契约仍发现 `sb.from('staging_records')`，尚未接入 Repository。
- 首次红灯测试有一个正则转义错误，已修正后重新运行；最终红灯只包含上述目标行为缺失。

## 最小实现

- `stagingRepository.listOpen/listProcessed` 固定过滤、排序、限制和失败结构，映射数据库列为 PWA 中转 DTO。
- Store 主查询改用 `listOpen`；补充已处理查询改用 `listProcessed`。
- `hydrateStagingImages` 继续消费 DTO 的 `imagePath`；还款周期继续在 Store 生成 `repaymentCandidate`。
- Release Validation 新增 `test:staging-read`，非目标源契约固定图片签名和还款候选不进入 Repository。
