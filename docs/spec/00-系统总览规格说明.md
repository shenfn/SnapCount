## 1. 文档目的

本文档描述芥子的系统边界、长期目标、平台职责、核心实体、跨端不变量和交付门禁。

本文档不替代具体功能的详细规格，不定义某个页面的像素、颜色或最终交互，也不把当前代码中尚未确认的行为自动视为产品规则。

后续功能应先遵守本文档的系统级约束，再在对应领域规格中补充可执行的业务场景和测试映射。

## 2. 产品定位

芥子从截图记账和自然捕获开始，持续沉淀用户的消费、运动、睡眠、饮食、阅读、钱包等生活记录，并在长期积累后建立记录之间的联系。

芥子不是单一记账软件、传统数据仪表盘或 AI 聊天外壳。记录是入口，长期记忆、跨数据域理解和用户可控的个人上下文是长期价值。

产品判断遵循以下原则：

1. 用户始终拥有数据的控制权、解释权和删除权。
2. 能由系统可靠完成的步骤，不要求用户重复操作。
3. 数据捕获应自然、低负担，必要确认应清晰且可恢复。
4. AI 只能基于真实记录和明确来源表达事实、推断或建议，并允许用户纠正。
5. 美学服务于长期靠近感，但不能损害清晰度、可信度和基本可用性。
6. iOS 默认免登录、本地保存；云同步和 AI 数据发送必须由用户主动选择。

长期产品基调详见 [芥子长期产品与设计基调](../前端设计理念/芥子长期产品与设计基调.md)。

## 3. 系统范围

### 3.1 本系统覆盖

- iOS 本地 profile、可选邮箱认证、会话恢复和用户隔离。
- iOS 本地数据库、导出恢复和可选云同步。
- 图片、截图和手动记录采集。
- 支出、收入和通用数据域记录。
- AI 识别、结构化入库、重复识别和待处理队列。
- 记录查看、编辑、确认、归档、删除和图片生命周期管理。
- 账户、账户流水、钱包快照、负债和还款链路。
- 数据域列表、数据域详情、指标、趋势和最近记录。
- 首页、待处理、记录、分析、设置等日常使用入口。
- AI 洞察、陪伴表达和表达反馈的可控展示。
- PWA 构建验证和 iOS macOS CI 编译、单元测试验证。

### 3.2 本文档不覆盖

- 生产数据库迁移、生产部署或 TestFlight 上传授权。
- 尚未确定的商业化、计费和团队协作能力。
- 需要领域专家确认的医疗、营养或财务专业建议口径。
- 视觉稿的最终像素参数和具体品牌主题实现。
- 将所有现有历史代码一次性重构为统一架构。

## 4. 平台职责

| 平台 | 主要职责 | 不应承担的职责 |
|---|---|---|
| PWA（Vue 3 + Vite） | 维护型云端客户端；登录后查看、管理、导出已同步数据，并承接安全与兼容修复 | 不参加本轮本地优先重构，不声称能看到 iOS 未同步的本地数据 |
| iOS（SwiftUI） | 主产品；免登录本地记录、本地数据生命周期、可选云同步、Hosted AI/BYOK 和移动端核心体验 | 不把套餐或供应商判断扩散进业务层，不重新定义共享金额、时间和状态规则 |
| iOS 本地数据库与 Sync Engine | 当前设备业务事实、离线事务、Outbox、导入导出和跨设备同步协调 | 不用最后写入覆盖账户余额，不在用户未授权时上传业务数据 |
| `ingest-receipt` Edge Function | PWA 和 Hosted AI 路径的鉴权、上传、去重、AI 识别、域路由、云端写入和伴随表达 | 不接收 BYOK Key，不把未经确认的推断直接当作已确认事实 |
| `generate-insights` Edge Function | 根据已沉淀的记录和配置生成分析或洞察 | 不绕过用户权限读取数据，不替代事实层 |
| Supabase Auth | 云同步、PWA 和需要身份的托管能力的用户身份、会话和令牌生命周期 | 不作为 iOS 本地核心功能的使用前提 |
| Supabase Postgres/RLS/RPC | PWA 云端权威、已授权同步副本、事务性云端写入、权限隔离和级联清理 | 不覆盖 iOS 尚未协调的本地事实，不允许绕过必要原子契约修改账户影响 |
| Supabase Storage | 原图和相关文件的受控存储、签名访问与清理 | 不把长期留存默认隐藏成不可解释的行为 |
| Cloudflare Pages/Worker | PWA 静态托管和必要的反向代理 | 不承载新的业务事实来源 |

## 5. 核心用户闭环

### 5.1 本地身份、登录和同步

1. iOS 首次启动创建仅存在设备上的本地 profile，用户无需登录即可进入核心功能。
2. 用户主动开启云同步或需要身份的托管能力时，再注册或登录 Supabase 账号。
3. 登录本身不自动上传全部本地数据；开启同步前必须说明范围和影响。
4. 用户切换、退出或会话失效时，停止旧账号同步任务并隔离导航、缓存、记录和设置；本地数据的保留或删除必须有明确出口。
5. PWA 继续以登录会话作为云端数据入口。

### 5.2 自然捕获和识别

1. 用户通过快捷指令、PWA、iOS 相机、相册或手动表单提交记录。
2. 手动记录优先写入 iOS 本地数据库；PWA、Hosted AI 或已授权云同步路径才访问 Edge/Supabase。
3. AI 关闭时仍可完成本地记录；AI 结果进入本地或云端待处理队列取决于用户选择的数据路径。
4. 失败、低置信度、缺少必要字段或无法路由的结果必须保持可见且可恢复。

### 5.3 确认、归档和修正

1. 用户查看待处理记录的事实、来源和缺失字段。
2. 用户补充或修正必要信息。
3. 支出、收入和钱包影响必须通过当前数据路径的事务性 Repository 契约保存；PWA/云端继续使用原子 RPC，iOS 本地模式使用可审计流水和本地事务。
4. 归档成功后，首页、记录页、账户和分析应在刷新或本地状态更新后保持一致。
5. 删除、撤销或丢弃必须有确认门禁，并完成规定的关联清理。

### 5.4 查看和理解

1. 首页提供当前状态、今日记录和待处理入口。
2. 记录页提供按月份、日期、类型或数据域查看的事实列表。
3. 数据域详情展示该域的指标、趋势、分布和最近记录；未知动态域应有可理解的通用降级。
4. 分析和 AI 洞察只使用符合统计口径的事实，不把待处理或失败记录混入确认统计。

## 6. 核心实体和权威来源

权威来源按数据路径区分：PWA 和现有云端用户继续使用 Supabase；iOS 本地优先切片完成后，以本地数据库作为当前设备即时事实，Supabase 只保存用户授权同步的数据。跨设备冲突由同步协议协调，不能由任一端直接覆盖。

| 实体 | 云端来源 / 本地目标 | 说明 |
|---|---|---|
| 支出交易 | `transactions` / iOS 本地 expense 实体 | 支出金额、日期、分类、平台、支付方式、账户和确认状态 |
| 收入记录 | `income_records` / 后续本地 income 实体 | 收入金额、日期、来源、账户和确认状态 |
| 通用数据记录 | `data_records` / 后续本地 domain record | 覆盖运动、睡眠、阅读、饮食等；共享域 key 和 JSON 契约 |
| 数据域定义 | `data_domains` | 域 key、名称、图标、schema、展示配置和记录数 |
| 中转记录 | `staging_records` | 识别后尚未完成归档或需要用户处理的通用记录 |
| 待补全支出 | `transactions.status = pending` 等现有契约 | 支出识别后缺少确认字段的记录 |
| 账户 | `accounts` / iOS 本地 account 实体 | 资产、负债和账户生命周期；多设备同步不得最后写入覆盖余额 |
| 账户流水 | `account_entries` / iOS 本地不可变流水或等价操作日志 | 云端由 RPC、本地由事务性领域契约产生，余额为可解释的派生结果 |
| 钱包快照 | 现有钱包快照契约 | 记录某一时点的账户或钱包状态 |
| AI 识别日志 | `ai_recognition_logs` | 识别过程和可审计信息，不等同于已确认事实 |
| AI 洞察 | `ai_insights` 及表达反馈表 | 基于事实和配置生成的分析、候选表达和用户反馈 |
| 用户配置 | `user_configs`、设备本地偏好和 Keychain | 主题、AI、同步、图片留存等设置；BYOK Key 只允许进入 Keychain |

### 6.1 数据事实层和表达层

- **事实层**：用户记录、账户余额、状态、时间、来源和 payload。事实必须可追溯、可修正、可删除。
- **候选层**：AI 提取的字段、比较候选、洞察候选和待确认信息。候选不能自动获得已确认事实的权限。
- **表达层**：首页文案、AI 陪伴、报告文字和通知。表达必须绑定明确的事实或候选来源，并支持失效、撤回和反馈。

## 7. 系统级不变量

以下规则适用于 PWA、iOS 和服务端；具体字段和状态出口在领域规格中补全。

### 7.1 用户隔离

- 云端用户数据按 `auth.uid() = user_id` 或等价服务端身份约束隔离；免登录数据按本地 profile 和设备级存储边界隔离。
- 用户切换、退出或会话失效后，不得继续展示上一用户的页面、缓存、图片签名 URL 或待处理操作。
- 客户端不得把用户 ID、账户 ID 或记录 ID 当作授权依据；权限由 Auth、RLS 和服务端契约决定。

### 7.2 事实和统计

- 待处理、失败、丢弃和仅预览的内容不进入已确认统计。
- 金额、日期、时区和状态使用共享契约；本地实现不得复制或改写另一套业务规则。
- 账户余额、负债和还款影响由可审计账户流水产生；云端使用 RPC，本地使用等价事务契约，页面只展示派生结果。
- 部分数据域加载失败时，保留成功的数据并明确提示不可用部分，不以空数据覆盖旧的有效快照。

### 7.3 幂等和可恢复

- 同一截图或同一业务操作重复提交不得产生重复入账。
- 目标记录已成功写入但源记录状态更新失败时，后续重试必须识别已有目标并避免重复创建。
- 失败状态必须存在后续出口：重试、修正、丢弃、人工处理或明确终止。
- 删除、清理和账号注销必须遵循同一数据生命周期规则，不能只删除 UI 入口。

### 7.4 AI 边界

- AI 识别结果必须区分原始来源、提取事实、推断和表达。
- AI 不得为了生成文案而补造没有来源的金额、日期、人物或健康结论。
- 用户可以纠正、拒绝或删除 AI 产物；反馈不会直接篡改历史事实。

## 8. PWA 与 iOS 的一致和差异

### 8.1 必须一致

- 数据域 key、记录引用格式、状态含义和核心字段。
- 金额、日期、时区和统计口径。
- 账户关联、归档、删除和 RPC 的业务影响。
- 待处理项目的分类、失败原因和后续出口。
- 用户隔离、图片访问和数据生命周期。
- 关键导航的目标语义，例如某个日期、某个领域或某条记录的详情。

### 8.2 允许平台差异

- PWA 使用页面、弹窗、底部导航；iOS 使用 NavigationStack、Sheet、TabView 等系统范式。
- PWA 优先支持批量和宽屏管理；iOS 优先支持快捷捕获、触觉、相机和系统分享。
- PWA 可以提供完整的桌面信息密度；iOS 可以采用渐进式披露和移动端紧凑布局。
- 视觉主题、动画和系统权限说明可以平台化，但不能改变用户对事实和状态的理解。

## 10. 质量目标和完成定义

### 10.1 核心业务变更

一个核心业务变更只有同时满足以下条件，才可以标记完成：

1. 有中文详细规格，包含成功、空态、失败、重试和删除出口。
2. 关键业务规则先有失败测试，再有最小实现。
3. 受影响平台的构建和相关 Node/Deno/数据库验证通过；未修改的平台不得被虚报为已重新验证。
4. iOS 变更通过 GitHub macOS Build 和 XCTest；Windows 不作为 Swift 编译结论。
5. PWA 与 iOS 的差异已经在平台附录中说明，而不是默认为实现缺陷。
6. 关键用户路径有可复现的验收记录。

### 10.2 视觉和交互变更

- 先明确页面信息层级和不变的行为契约。
- 保留保存、删除、确认门禁、导航和数据加载状态。
- 完成静态或快照检查，并在可用的 macOS/iOS 环境进行真机或模拟器验收。
- 视觉验收不能替代业务测试，业务测试也不能替代视觉验收。

以下事项在总体层只登记，不在本文档擅自定案：

- `transactions`、`staging_records`、通用 `data_records` 的完整状态机和所有终态出口。

- 本地匿名 profile 与云端账户绑定、同步冲突和老用户迁移的字段级契约。
- Vue 组件测试框架的引入时机，以及 Playwright 的最小关键路径集合。
- iOS XCUITest 或截图测试是否进入合并门禁，还是先作为夜间/手动验证。

这些问题由后续领域规格和评审记录解决，不能通过页面实现自行决定。
