## 1. 目标与非目标

本阶段把架构收拢计划中的依赖不变量转换为可追溯基线，回答三件事：当前哪里已经违反、哪些违反属于历史存量、从本次开始如何阻止新增违规。

本阶段不做以下事情：

- 不把 `tools/ai-validation` 迁移到生产 `_shared`；该动作属于 A2，必须先有模块 Spec 和特征测试。
- 不拆 PWA `useStore`，不改变页面、认证、RPC 或数据加载行为。
- 不拆 iOS `AppState` 或 `NativeDataService`，不修改 iOS 视觉实现。
- 不建立生产 RPC、时间、金额或状态规则的新权威实现。

## 3. 端侧边界盘点

### 3.1 Edge 与 Planner Lab

生产入口 `supabase/functions/ingest-receipt/expression-shadow-planner.ts` 直接引用 `tools/ai-validation/expression-planner` 的实体归一化、候选生成、资格门、确定性评分和渲染契约模块。当前生产可运行，但依赖方向是：

```text
Edge 生产入口 → tools/ai-validation（实验目录）
```

目标方向应为：

```text
supabase/functions/_shared/expression-core/ ← Edge 入口
                                          ← Planner Lab 离线适配
```

本阶段仅将 12 条导入登记在 `scripts/architecture-boundary-baseline.json`，不复制或删除任何规则实现。

### 3.2 PWA

- `src/lib/supabase.js` 是客户端入口，负责 Supabase 客户端和网络错误适配。
- `src/composables/useStore.js` 约 4,739 行，承担认证、数据加载、RPC、记录写入、账户和表达反馈等多种编排职责，是 A3 的主要收拢对象。
- `src/components` 下目前存在 4 个组件直接引用 Supabase，其中 `PageSettings.vue` 还直接请求 `ingest-receipt`；这些全部作为历史基线，不在 A1 改动。
- `src/domains` 当前未发现 Vue、Supabase 客户端或 `fetch` 依赖；但部分 Domain adapter 仍通过 `src/utils/helpers.js` 获取时间和展示适配，是否属于共享规则重复要在 A3 前逐项分类。

### 3.3 iOS

- `ios/SnapCount/App/AppState.swift` 约 2,532 行，承担会话、Dashboard、记录、账户、待处理、中转站、表达反馈和设置等业务编排。
- 14 个 Feature/View 文件直接持有 `AppState` 环境对象，页面与编排层耦合明显。
- Repository Protocol 已存在，`NativeDataService.swift` 约 1,938 行；A4 应优先利用现有 Protocol，收窄 Service 的 HTTP/RPC/DTO 责任，而不是先做机械拆文件。
- Windows 环境不验证 Swift 编译；iOS 行为验收仍以 macOS GitHub Actions Build/XCTest 为准。

### 3.4 规则重复候选

当前只能确认“多处实现/适配存在”，不能在没有模块 Spec 的情况下把它们都判为错误重复：

- 金额：PWA 财务 adapter、iOS 记录模型、Planner Lab 的数值解析和格式化。
- 状态与证据：Edge 生命周期/候选资格、PWA `pendingQueue`、iOS 展示模型。

A2 先确定生产权威规则和纯函数边界，再逐项把“跨端适配”与“第二份业务规则”区分开。

## 4. 检查实现与运行方式

机器基线位于 `scripts/architecture-boundary-baseline.json`，检查脚本为 `scripts/check-architecture-boundaries.mjs`。

```text
npm run governance:arch
```

当前启用三条 ratchet：

1. `supabase/functions` 新增 `tools/` 导入失败；
2. `src/components` 新增 Supabase 客户端或网络直连失败；
3. `src/domains` 新增 UI、HTTP 或 Supabase 依赖失败。

RPC 契约和规则重复目前输出 warning，不伪装成自动检查。等 A3/A5 建立共享契约注册表后，再把对应规则升级为硬门禁。
