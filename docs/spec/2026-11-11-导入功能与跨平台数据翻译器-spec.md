# 芥子导入功能与跨平台数据翻译器 Spec

## 1. 文档目的

为芥子增加一个统一的“导入数据”功能。记账软件或平台的数据先经过导入翻译器转换为芥子的标准财务记录，再进入本地数据库。

本功能只处理记账相关数据，不处理睡眠、运动、饮食等其他生活记录域。第一版先支持芥子自己导出的 JSON 和 CSV，验证完整导入链路。后续可以增加支付宝、微信、其他记账软件和通用记账 CSV 的适配器。

## 2. 当前基础

已有能力：

- 普通数据导出已经支持 JSON 和 CSV。
- 完整本地备份已经支持预览、合并恢复、图片恢复、重复导入跳过和失败回滚。
- 导入入口当前主要面向完整本地备份，普通导出文件尚未形成独立的导入流程。

相关代码：

- `ios/SnapCount/LocalData/LocalFactPortability.swift`
- `ios/SnapCount/LocalData/LocalCompleteBackupPortability.swift`
- `ios/SnapCount/Features/Settings/SettingsView.swift`
- `ios/SnapCount/App/AppState.swift`

## 3. 产品范围

### 3.1 第一版必须支持

- 从文件选择 JSON 或 CSV。
- 识别文件来源和格式版本。
- 将输入转换为芥子标准财务记录。
- 导入前预览新增、跳过和错误数量。
- 导入到当前本地用户。
- 根据稳定标识去重。
- 支持重复导入而不产生重复记录。
- 失败时整批回滚。
- 保留商户、金额、日期、分类、渠道、备注和原始 payload。
- 在字段存在时保留 AI 陪伴内容和图片引用。

### 3.2 第一版不包含

- 自动读取第三方平台账号或接口。
- 在线同步其他平台数据。
- 导入非财务生活记录域。
- 自动猜测所有未知字段并直接入账。
- 修改已有记录的人工合并界面。
- 把导入数据直接上传云端。

## 3.3 财务域边界

跨平台翻译器只输出消费和收入两类财务记录。外部平台的其他字段如果无法映射到财务记录，进入原始 payload 或警告信息，不创建其他生活记录。

芥子自己的完整本地备份继续使用现有完整备份恢复链路。跨平台翻译器不替代完整备份恢复。

## 4. 核心数据流

```text
文件选择
  -> 文件格式检测
  -> 平台适配器解析
  -> 芥子标准记录
  -> 预检查与预览
  -> 用户确认
  -> 本地事务导入
  -> 导入结果
```

导入翻译器只负责解析和转换，不直接写数据库。数据库写入由现有本地记录、财务和图片存储层负责。

## 5. 统一翻译器模型

定义一个中间模型 `ImportRecordDraft`，作为所有平台适配器的输出。

建议字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| sourcePlatform | 是 | 来源平台，例如 `jiezi_json`、`jiezi_csv`、`wechat` |
| sourceRecordID | 否 | 来源平台原始 ID |
| sourceFingerprint | 是 | 根据来源、日期、金额、商户等生成的稳定指纹 |
| kind | 是 | expense 或 income |
| businessDate | 是 | 业务日期 |
| occurredAt | 否 | 精确发生时间 |
| amountMinor | 视类型 | 金额，使用最小货币单位保存 |
| currency | 否 | 默认 CNY |
| merchant | 否 | 商户名称 |
| category | 否 | 芥子分类键或原始分类 |
| channel | 否 | 支付渠道 |
| account | 否 | 账户名称或来源账户 |
| note | 否 | 备注 |
| sourcePayloadJSON | 否 | 原始字段，便于追溯和二次翻译 |
| companionMessage | 否 | 已存在的陪伴内容 |
| image | 否 | 图片数据、路径和 hash |
| warnings | 否 | 翻译过程产生的非阻断提示 |

标准模型不直接携带目标数据库的内部主键。目标主键和 profile ID 在导入确认阶段生成或映射。

## 6. 适配器接口

```swift
protocol ImportSourceAdapter {
    var sourcePlatform: String { get }
    func canRead(data: Data, fileExtension: String?) -> Bool
    func preview(data: Data) throws -> ImportPreview
    func translate(data: Data) throws -> [ImportRecordDraft]
}
```

第一版实现：

- `JieziJSONImportAdapter`
- `JieziCSVImportAdapter`

后续新增记账平台时，只增加适配器，不修改数据库导入主流程。

## 7. 文件格式与版本

### 7.1 JSON

识别字段：

- `format`
- `schemaVersion`
- `profileID`
- `facts`

只接受已知格式和兼容版本。未知版本进入错误状态，不直接猜测导入。

### 7.2 CSV

第一版只保证读取芥子当前导出的财务列：

- `id`
- `profile_id`
- `reference`
- `kind`
- `domain_key`
- `source_kind`
- `domain_version`
- `title`
- `summary`
- `business_date`
- `record_time`
- `occurred_at`
- `note`
- `image_path`
- `image_hash`
- `image_data_base64`
- `payload_json`

CSV 解析必须支持引号、逗号、换行和空值。

## 8. 预检查规则

阻断导入的情况：

- 文件格式无法识别。
- schema 版本不支持。
- 必填日期缺失或格式错误。
- 金额无法解析或超出范围。
- 同一文件内出现重复稳定标识。
- 图片 hash 不匹配。
- 图片路径越权或文件超过本地上限。
- 总行数或文件大小超过本地限制。

允许导入但需要提示的情况：

- 分类无法映射，保留原始分类文本。
- 支付渠道无法映射，保留原始渠道文本。
- 商户为空，使用记录标题或“未命名商户”。
- 来源记录没有稳定 ID，使用内容指纹去重。
- AI 陪伴字段缺失，导入后由本地规则决定是否生成新的陪伴内容。

## 9. 去重规则

按以下顺序判断：

1. 来源平台加来源记录 ID。
2. 芥子原始记录 ID。
3. 内容指纹，包括类型、日期、金额、商户、分类和来源平台。

导入结果分为：

- 新增
- 已存在并跳过
- 有警告但允许导入
- 错误并拒绝

重复导入同一文件必须保持幂等。

## 10. 数据库写入

确认导入后使用一个本地数据库事务：

1. 映射当前 profile ID。
2. 写入账户、记录、消费或收入数据。
3. 写入原始 payload 和来源信息。
4. 恢复图片并校验 hash。
5. 写入本地陪伴字段。
6. 事务提交后刷新首页、明细和观察数据。

导入过程中不创建云端 outbox 操作。用户后续执行正常同步时，再按现有同步策略处理。

任何数据库错误、图片写入错误或关系校验错误都必须回滚本批次新增内容。

## 11. 页面交互

在现有“数据导出”页面增加“导入数据”按钮，进入文件选择器。

预览页显示：

- 来源平台
- 文件格式和版本
- 时间范围
- 总记录数
- 新增数量
- 已存在数量
- 警告数量
- 错误数量
- 图片数量

确认按钮使用明确文案：

> 导入到本机当前数据

完成后显示：

> 已新增 X 条，跳过 Y 条，警告 Z 条。

错误详情支持查看行号、字段名和原因。

## 12. 测试要求

### 单元测试

- JSON 导出后重新导入，字段保持一致。
- CSV 导出后重新导入，字段保持一致。
- CSV 中包含逗号、引号和换行时解析正确。
- 同一文件导入两次不产生重复记录。
- profile ID 正确映射到目标本地用户。
- 图片 hash 正确时恢复成功。
- 图片 hash 错误时整批回滚。
- 单条错误能显示具体行号和字段。
- 旧版已支持格式仍可导入。
- AI 陪伴字段和原始 payload 能够保留。

### 真机验收

1. 在已有数据的设备导出 JSON。
2. 在另一份测试数据环境中导入 JSON。
3. 检查首页、明细、图片和 AI 陪伴内容。
4. 再次导入同一文件，确认不重复。
5. 导出 CSV 后重复上述流程。
6. 导入故意损坏的文件，确认原有数据不受影响。

## 13. 开发拆分

### M1 统一模型和适配器接口

建立 `ImportRecordDraft`、错误模型、预览模型和适配器协议。

### M2 芥子 JSON 导入

复用现有 `LocalFactArchive`，完成解析、预览、去重和本地事务导入。

### M3 芥子 CSV 导入

实现安全 CSV 解析和字段转换，保持与 JSON 导入共用下游流程。

### M4 页面接入

在设置页增加导入入口、预览确认、结果展示和错误详情。

### M5 测试与 TestFlight

完成单元测试、模拟器闭环后，发布新的 TestFlight 构建给真机验证。

## 14. 完成标准

当用户可以把芥子导出的 JSON 或 CSV 文件交给另一台已经安装芥子的设备，并通过“导入数据”完成记录恢复、图片恢复、陪伴字段保留、重复导入幂等和失败回滚时，第一版导入功能完成。

第三方记账平台适配只需要新增对应的 `ImportSourceAdapter`，不应重新设计导入页面和数据库写入流程。
