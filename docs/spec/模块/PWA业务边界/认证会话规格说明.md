## 1. 目标

建立 Auth Repository 与 Session Feature，使 App 成为唯一 session event 入口，AuthPage 只发起登录/注册并展示结果；用户切换、退出和异步加载由 generation 保护，旧用户响应不得写入新会话。

建议落点：

```text
src/repositories/authRepository.js
src/features/auth/createSessionState.js
src/features/auth/__tests__/
src/App.vue
src/components/pages/AuthPage.vue
src/composables/useStore.js
scripts/test-pwa-auth-boundary.mjs
```

## 2. 场景与不变量

| 场景 | 行为不变量 | 测试层 |
|---|---|---|
| PWA-018 | App 的 auth event 是用户状态唯一写入入口；AuthPage 不直接赋值用户状态或调用 `loadData` | 源契约 + PWA build |
| PWA-019 | 同一 session 的 `getSession`、`INITIAL_SESSION`、`SIGNED_IN` 只能触发一次首次数据加载 | Session Feature 行为测试 |
| PWA-020 | A 用户加载未完成时切到 B，A 的主查询、补充查询和失败状态不得写回 B | Store/Session 行为测试 |
| PWA-021 | `SIGNED_OUT` 立即清空用户数据和所有 feature state；退出前发出的响应只能结束 Promise，不得写状态 | 行为测试 |
| PWA-022 | Auth 订阅在 App 卸载时 unsubscribe，重复挂载不得累积监听器 | 源契约或组件行为测试 |
| PWA-023 | 注册只提交当前 terms/privacy 版本与敏感数据同意；服务端决定同意时间并创建默认配置行 | Repository + 注册同意服务端契约 |
| PWA-024 | 登录/注册网络失败返回结构化错误；自动重试不能重复提交已成功的认证写操作 | Repository/Feature 行为测试 |
| PWA-025 | Settings Feature 继续负责 `user_configs` 配置快照；Auth Feature 不读取或更新设置字段 | 依赖检查 + 回归测试 |

## 3. 边界职责

| 层 | 负责 | 不负责 |
|---|---|---|
| AuthPage | 邮箱/密码输入、同意复选框、loading/error 展示 | Store 用户字段、session 订阅、全量数据加载 |
| App | 订阅和注销 auth state change，向 Session Feature 转发事件 | 登录表单、配置字段、业务查询 |
| Session Feature | generation、去重、切换/退出 reset、一次性 load 编排 | Supabase DTO、记录金额与状态规则 |
| Auth Repository | auth transport、session/user DTO、错误归一化 | Store、导航、flash、数据加载 |
| 服务端 | consent 版本/时间、RLS、auth user 与默认配置行 | 页面交互与客户端导航 |

## 4. 失败与并发契约

- 登录/注册 transport 成功与首次数据加载失败必须区分；不得因刷新失败重复提交认证请求。
- Session Feature 用 session user id + generation 判定响应是否仍可写入。
- `TOKEN_REFRESHED` 不应重置页面或重复全量加载；用户 id 不变时只更新 session 身份。
- `SIGNED_OUT` 和用户切换必须使旧 generation 立即失效，再 reset 数据。
- App 订阅回调中的异步错误必须被捕获并暴露，不产生未处理 Promise rejection。

## 5. 非目标

- 不修改数据库 trigger、RLS、terms/privacy version 或敏感数据同意文案。
- 不重写 `loadData` 内全部查询为 Repository；本片只加用户/run 写回门禁。
- 不迁移 PageSettings 导出、隐私清理或 signOut UI。
- 不改变邮箱确认、密码规则、第三方登录或视觉设计。
- 不修改 iOS、Edge、部署和生产配置。

## 6. TDD 顺序

1. 固定 App/AuthPage 当前入口与注册 metadata 特征。
2. 写同 session 去重、用户切换旧响应、退出旧响应和 unsubscribe 红灯。
3. 实现 Auth Repository 与纯 Session Feature。
4. 由 App/useStore 兼容组合，移除 AuthPage 的重复用户状态和加载编排。
5. 为 `loadData` 主查询增加 current run/user guard，不迁移其业务查询内容。
6. 运行注册同意、Settings、Expression、架构治理和 PWA build 回归。

## 7. 完成定义

- PWA-018 至 PWA-025 都有行为、契约或明确非目标证据。
- 登录/注册成功只由一个 auth event 路径设置当前用户并触发一次加载。
- 用户切换和退出后不存在旧主查询写回。
- 注册同意服务端契约继续通过，客户端没有第二份时间/版本校验。
- 未修改数据库、Edge、iOS、部署或其他 worktree。
