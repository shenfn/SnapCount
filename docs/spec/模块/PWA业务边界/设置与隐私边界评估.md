> 任务：CLEAN-001/A3、PWA-008

> 基线：`52aa92a`（PR #66 合并提交）

## 1. 评估结论

“设置与隐私”不是一个可以整块搬迁的单一职责。当前 `PageSettings.vue` 约 1,166 行，同时包含用户配置、模型与陪伴偏好、原图留存和立即清理、数据导出、上传 Token 与退出登录；直接抽成一个大 Feature 会把配置、隐私副作用、数据读取和认证重新耦合在一起。

正确顺序是先统一 `user_configs` 的读取、字段白名单、共享状态和失败回滚，再分别处理原图清理、数据导出和认证。首实现切片只迁移配置读写，不改变数据导出、清理 Edge action、注册同意或登出行为。

## 4. 发现的行为风险

### 4.1 留存保存与立即清理缺少成功契约

`store.setRetention` 保存失败时会在内部回滚并吞掉异常，调用方拿不到失败结果。`confirmRetentionModal` 随后仍可能执行 `cleanup_all_images`，造成“策略未保存但已有原图被清理”。首片必须让保存返回明确成功/失败，立即清理只能发生在保存成功之后。

### 4.2 用户切换和并发响应可能覆盖新状态

PageSettings 与 PageAiVisionSettings 的 onMounted 查询没有 revision/version 保护；旧用户慢响应可能在 reset 或切换后写入页面本地 ref。多个直接 update 也没有统一的同键请求去重或旧失败隔离。

### 4.3 页面默认值和数据库默认值分散

vision provider、Qwen model、companion persona/memory/style 和隐私开关的默认值分散在迁移、Store 和两个页面。客户端只应做 DTO 兼容和显示归一化，服务端默认和约束仍是权威。

### 4.4 数据导出会静默忽略查询错误

当前导出查询只读取 `data`，没有检查 Supabase `error`，失败时可能导出空文件并显示成功。该问题需要单独的 Export Spec 和行为测试，不能混入配置首片顺手修复。

## 5. 首片目标边界

```text
PageSettings / PageAiVisionSettings / ModalWelcome
                    ↓
             useStore 兼容门面
                    ↓
          Settings Feature State
                    ↓
          Settings Repository
                    ↓
               user_configs
```

- Feature 维护共享配置快照、加载状态、revision 和按字段更新状态。
- Repository 只处理 `user_configs` 查询、更新、缺列兼容和传输错误，不决定产品默认和副作用。
- `AuthPage` 的注册配置创建暂留认证边界，不计入本切片。
- `PageSettings` 因导出、清理和登出仍可暂时保留 Supabase/fetch import，但不得再直接访问 `user_configs`。
- `ModalWelcome` 与 `PageAiVisionSettings` 移除页面直连后，架构基线预计由 5 项降到 3 项；实际以实现 diff 和检查结果为准。
