## 1. 目标

首片把 `user_configs` 的读取、兼容映射、共享状态和更新编排集中到 Settings Feature/Repository，同时保留 `useStore` 的设置公开 API 和现有页面交互。页面不再自行实现 `user_configs` 查询、缺列回退或更新回滚。

建议落点：

```text
src/repositories/settingsRepository.js
src/features/settings/createSettingsState.js
src/features/settings/settingsConfig.js
src/features/settings/__tests__/
src/composables/useStore.js
src/components/pages/PageSettings.vue
src/components/pages/PageAiVisionSettings.vue
src/components/ModalWelcome.vue
```

## 3. 配置分组

| 分组 | 字段 |
|---|---|
| 隐私与陪伴开关 | ai logs、prompt optimization、expression improvement、keep images、retention days、companion enabled、companion memory enabled |
| 视觉模型 | legacy vision primary、screenshot/photo provider、Qwen model、thinking flags |
| 陪伴偏好 | AI insight provider、persona、memory strength、expression style、custom note |
| 只读账户配置 | upload token、plan |

客户端字段名与数据库列名的映射只能有一份。任意 patch API 必须经过白名单，不能允许组件提交任意列。

## 4. 失败与并发契约

- load 失败不覆盖最后一次成功快照；首次加载失败使用明确默认并暴露错误状态。
- 更新可以乐观展示，但失败只在当前值仍属于该请求时回滚，不能让旧失败覆盖新选择。
- 同一字段请求使用 revision 或串行化；不同字段不得共享一个会吞掉结果的隐式全局锁。
- retention 保存返回结构化结果，例如 `{ ok, error }`；页面只有在 `ok === true` 时才能进入立即清理步骤。
- reset 后所有 in-flight 响应只允许结束自己的 Promise，不得写入状态。

## 5. 非目标

- 不迁移数据导出查询、CSV/JSON 序列化和下载。
- 不迁移 `cleanup_all_images` HTTP transport，只增加保存成功门禁。
- 不迁移 AuthPage 注册、App session 或 PageSettings signOut。
- 不修改数据库列、默认值、触发器、RLS 或 Edge action。
- 不修改页面视觉和产品文案。

## 6. TDD 顺序

1. 为共享加载、legacy fallback、用户切换、同字段竞态、retention 失败门禁写红灯。
2. 实现 settings Repository 与纯配置映射。
3. 实现 Settings Feature State，再由 `useStore` 兼容组合。
4. 逐个替换 PageSettings、PageAiVisionSettings、ModalWelcome 的 `user_configs` 直连。
5. 运行新增行为测试、注册同意、安全契约、架构 ratchet 和 PWA build。
6. 只移除实际消失的两项页面直连基线，PageSettings 与 AuthPage 保持显式例外。
