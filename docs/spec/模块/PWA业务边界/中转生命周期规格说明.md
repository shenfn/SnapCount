## 1. 场景矩阵

| 场景 | 行为不变量 | 测试层 |
|---|---|---|
| PWA-026 | 中转动作由 Feature/Repository 编排，页面不拼 transport 或自行判断服务端重试上限 | 源契约 + Repository 测试 |
| PWA-027 | 中转与待补全账单保留 source/type，统一队列展示但不混淆权威状态机 | 队列行为测试 |
| PWA-028 | `retry_count >= 3` 后不能发起第四次 AI 重试，记录继续可见 | PWA 行为 + Edge 契约 |
| PWA-029 | 达到重试上限仍有人工归档、字段修复和丢弃出口 | PWA 组件/Feature 行为测试 |
| PWA-030 | 重试失败、原图缺失和网络错误不移除中转记录，返回结构化失败结果 | Repository/Feature 测试 |
| PWA-031 | 用户切换/退出使旧重试和图片响应失效，不得写入新用户队列 | generation 行为测试 |
| PWA-032 | 写入成功但列表刷新失败时只重试读取，不重复执行重试/归档/丢弃写操作 | Feature 行为测试 |
| PWA-033 | 归档原子性差异被单独登记，REC-009 不以客户端补偿伪造事务完成 | 评估证据 + 数据库任务门禁 |

## 2. 首片 TDD 顺序

1. 固定现有队列 source/type 和 retry action 特征。
2. 为第四次重试、上限人工出口、失败保留和用户切换写红灯。
3. 抽出最小 Staging Repository/Feature，仅承载 REC-009 所需动作。
4. 保留 `useStore` 公开方法，通过兼容门面转发。
5. 运行 PWA、Edge/Deno、`test:pending-queue`、安全契约、架构 ratchet 和 build 回归。
6. 完成后再决定是否单独启动归档原子性数据库任务。

## 3. 完成定义

- PWA-026 至 PWA-032 有行为、契约或明确不重复验证证据；PWA-033 的阻断项有单独任务记录。
- 第四次重试不会产生第二次业务写入，原中转记录仍可人工处理。
- PWA 与 iOS 使用相同 REC-009 业务含义，但保留平台交互差异。
- 未执行数据库迁移、生产部署、Edge 热更新、iOS 上传或历史数据修复。
