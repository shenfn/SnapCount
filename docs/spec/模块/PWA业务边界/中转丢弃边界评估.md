# PWA 中转丢弃边界评估

> 任务：CLEAN-001/A3、PWA-041
>
> 基线：`829a586`（PWA-040 PR #77 合并提交）
>
> 状态：只读评估完成，待文档 PR 门禁

## 1. 结论

下一最小切片只收拢中转丢弃：把 `discard_staging_record` transport 和并发/会话/结果编排移入现有 Staging Repository/Feature，保留 `useStore` 兼容门面和页面确认交互。

不同时拆中转读取。当前读取与全量 `loadData`、DTO 映射、图片签名、还款候选和已处理列表耦合，回归面明显大于丢弃动作；先完成丢弃可补齐中转三类主要写动作的统一边界，而不扩大到读模型重构。

## 2. 已核对证据

| 位置 | 当前行为 | 风险 |
|---|---|---|
| `useStore.discardStagingRecord` | 直接调用 `discard_staging_record`，再移除待处理项并写入已处理列表 | transport、业务结果和 UI 提示仍混在门面 |
| `PagePending.discardFromVerdict` | `await` 结束后无条件推进队列 | RPC 失败返回 `null` 时仍可能离开当前项 |
| `useStore.batchDiscard` | `Promise.allSettled` 后以 fulfilled 且 truthy 计数 | 没有同 ID 请求去重；会话切换与旧响应没有独立契约 |
| session reset | 只 reset retry/archive Feature | 丢弃旧请求没有 generation 隔离 |
| `loadData` | 同时查询正式记录、账户和中转，随后签名图片并生成还款候选 | 不适合与单一写动作同片迁移 |

服务端 RPC 已负责中转终态与图片清理排队；本片不复制状态规则，也不新增数据库函数。

## 3. 目标边界

```text
PagePending / batch action
        ↓
useStore 兼容门面（确认、提示、本地列表收敛）
        ↓
Staging Discard Feature（去重、session generation、结构化结果）
        ↓
Staging Repository（RPC 参数与 DTO 映射）
        ↓
discard_staging_record（状态与清理事实权威）
```

页面只在 `accepted` 时推进；`failed`、`rejected` 和 `stale` 均保留当前记录。Repository 不生成状态、时间或清理结论。

## 4. 非目标

- 不修改 `discard_staging_record`、迁移、Edge、iOS 或生产配置。
- 不抽离 `loadData`、图片签名、还款候选或已处理列表查询。
- 不重写 `PagePending` 视觉和批量选择交互。
- 不处理生产迁移编号差异、历史孤儿或真实数据修复。
