## 1. 场景矩阵

| 场景 | 行为不变量 | 测试层 |
|---|---|---|
| PWA-063A | 补绑复用 Record Repository 的两个保存方法和 canonical DTO；Store 不再直接调用保存 RPC，也不再组装 `p_*` 参数 | Feature 输入映射/Store 源边界 |
| PWA-063B | 同用户、kind、record 和 account 的并发补绑共享 Promise；同记录不同 account 的并发请求返回 `binding_conflict` | Feature 行为 |
| PWA-063C | reset 或用户切换使旧单笔结果 stale；批量在下一项开始前停止，不刷新或提示当前会话 | Feature 行为 |
| PWA-063D | Repository accepted 后先以 canonical record 收敛；刷新失败仍保持 accepted，并返回独立 `refreshStatus/refreshError` | Feature/Store 行为 |
| PWA-063E | 批量顺序执行并返回逐项结果、成功数和失败数；部分成功显式返回 `partial`，全部写入后最多刷新一次 | Feature 行为 |
| PWA-063F | 页面保留推荐、预览和确认；成功项从未绑定集合移除，失败项可重试，stale 不显示旧任务提示 | Store/Page 源边界与回归 |

## 2. 目标接口

新增 `createAccountBindingFeature({ repository, getCurrentUserId })`：

- `bind(kind, record, accountId, options)` 处理单笔补绑。
- `bindBatch(items, options)` 处理已确认候选的顺序补绑。
- `reset()` 提升 generation 并清空 inflight 引用。
- `buildAccountBindingInput(kind, record, accountId)` 将正式记录 DTO 映射为 Record Repository 的语义保存输入，不暴露 RPC 名或 `p_*` 参数。

单笔结果使用 `rejected`、`failed`、`stale` 或 `accepted`；accepted 结果保留 `record`，并附带 `refreshStatus`。同一记录正在绑定到不同账户时返回 `rejected/binding_conflict`。

批量结果使用 `accepted`、`partial`、`failed` 或 `stale`，并返回 `items`、`successCount`、`failedCount` 和写后刷新结果。批量没有数据库原子性。

## 3. Store 与页面职责

- 推荐账户、默认账户和支付线索匹配继续由 Store 计算。
- 用户确认后把明确的 `kind + record + accountId` 交给 Account Binding Feature。
- `onAccepted` 使用 canonical record 更新 `bills` / `incomeRecords` / `recentIncomeRecords`，从对应未绑定集合移除成功项，并失效表达计划缓存。
- 单笔 accepted 后刷新账户、未绑定列表和当前详情；批量 accepted 项收敛后只刷新一次账户和未绑定列表。
- `failed` 保留记录供重试；`partial` 明确显示成功与失败数；`stale` 不显示旧任务提示。
- 页面按钮锁和预览开关只负责交互，不作为业务并发或用户隔离权威。

## 4. 错误与状态契约

| 结果 | Store 行为 |
|---|---|
| `rejected/invalid_input` | 不调用 Repository，保留页面状态并提示输入缺失 |
| `rejected/binding_conflict` | 不发第二次写入，提示当前记录正在绑定其他账户 |
| `failed` | 保留未绑定项；单笔显示服务错误，批量计入失败数 |
| `stale` | 不收敛、不刷新、不关闭当前用户预览、不显示旧任务提示 |
| `accepted + refreshStatus ok/not_requested` | 使用 canonical record 收敛并显示成功 |
| `accepted + refreshStatus failed` | 保留 accepted 事实与本地收敛，提示列表刷新失败且不得建议再次补绑 |
| `partial` | 成功项已 accepted，失败项保留；显示两个计数，不伪装成全成功 |

## 5. 非目标

- 不修改数据库保存 RPC、迁移、账户流水、余额方向或发生时间规则。
- 不修改推荐算法、默认账户、候选阈值、预览默认全选或账户匹配文案。
- 不修改 manual/edit、staging、待补全、wallet、删除、图片签名、iOS、Edge 或 Planner。
- 不承诺批量原子性、网络重试幂等或跨 Finance Save Feature 的全局写入串行化。

## 7. 完成定义

- PWA-063A 至 PWA-063F 均有有效红灯、最小实现和绿灯证据。
- `bindRecordToAccount` 不再直接调用保存 RPC或包含重复 `p_occurred_at` 键。
- 单笔与批量都不会让旧会话结果污染当前用户状态。
- canonical RPC 返回 DTO 是补绑成功项本地收敛的唯一事实输入。
- 部分成功与刷新失败不会被错误描述成全失败或诱导重复写入。
- 推荐策略和全部非目标未进入实际 diff。
