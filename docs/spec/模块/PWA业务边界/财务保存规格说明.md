## 1. 场景矩阵

| 场景 | 行为不变量 | 测试层 |
|---|---|---|
| PWA-058 | Record Repository 的支出/收入保存方法只调用对应 canonical RPC，不发送 `user_id`；成功行分别经 `mapTransaction` / `mapIncomeRow` 映射，服务错误保持结构化失败 | Repository 行为 |
| PWA-059 | 同一用户、同一 kind、同一 create/edit 标识的并发保存共享同一个 Promise；不同 kind 或不同记录互不阻塞 | Feature 行为 |
| PWA-060 | 保存期间用户切换、注销或 `reset` 后，旧请求返回 `stale/session_changed`，且不执行本地收敛和写后刷新回调 | Feature 行为 |
| PWA-061 | RPC 已 accepted 后，写后刷新失败仍返回 `accepted`，并单独返回 `refreshStatus: failed` 和 `refreshError`；不得把它降级成保存失败 | Feature 行为 |

## 2. 目标接口

### Record Repository

- `saveExpense(input)` 负责把语义字段映射为 `save_transaction_with_account` 的 `p_*` 参数。
- `saveIncome(input)` 负责把语义字段映射为 `save_income_with_account` 的 `p_*` 参数。
- 成功返回 `{ status: 'accepted', reason: 'saved', kind, record }`。
- 服务失败返回 `{ status: 'failed', reason: 'service_error', kind, record: null, error }`。
- Repository 不读取 Vue ref，不选择账户，不刷新页面数组，也不发送 `user_id`。

### Finance Save Feature

- `saveExpense(input, options)` 与 `saveIncome(input, options)` 复用一套请求隔离机制。
- 请求键为 `userId + kind + create/edit id`；create 在同一 kind 下共享请求，edit 按记录 ID 隔离。
- `reset()` 提升 generation 并清空 inflight 引用；无法取消已发出的数据库请求，但能禁止旧结果进入当前会话。
- `options.onAccepted` 只负责使用权威 DTO 完成本地同步操作。
- `options.refresh` 负责账户、未绑定列表或详情等写后刷新；异常被归入 `refreshStatus`，不改变 accepted 事实。
- Repository 返回后、执行回调前，以及刷新返回后都检查 generation 和用户身份。

## 3. Store 保留职责

- 金额、必填字段、modal mode、日期时间与账户选择校验。
- staging 模式继续分流到已有原子归档 Feature。
- 组装 Repository 的语义输入，但不组装 RPC 名或 `p_*` 参数。
- accepted 后以 `result.record` 对 `bills` / `incomeRecords` / `recentIncomeRecords` 按 ID upsert。
- 表达计划失效、财务词表学习、modal 关闭、详情同步和用户提示。
- 提供账户与未绑定列表刷新回调，并区分保存失败和刷新失败文案。

## 4. 错误与状态契约

| 结果 | Store 行为 |
|---|---|
| `rejected` | 保留 modal，显示输入或会话错误，不进行刷新 |
| `failed` | 保留 modal，显示保存失败，不进行本地 upsert |
| `stale` | 不触碰当前页面状态，不显示旧会话提示 |
| `accepted + refreshStatus ok/not_requested` | 关闭 modal，以权威 DTO 收敛并显示保存成功 |
| `accepted + refreshStatus failed` | 关闭 modal并保留权威 DTO，提示“已保存，列表刷新失败”，不得建议再次保存 |

Feature 的并发合并只覆盖同一客户端会话中的同时调用，不是网络超时后的数据库幂等。

## 5. 非目标

- 不修改两个数据库保存 RPC、数据库迁移、账户流水、余额方向或时间规则。
- 不迁移 staging 归档、`confirm_pending_transaction_with_account`、账户补绑或批量补绑。
- 不修改 wallet、删除、图片签名、iOS、Edge、Planner、生产数据或部署配置。
- 不以本片处理网络超时后的重复创建；该问题需要独立 operation ID 数据库契约。
- PWA-063 账户补绑继续冻结为下一独立切片。

## 7. 完成定义

- PWA-058 至 PWA-062 均有有效红灯、最小实现和绿灯记录。
- manual/edit 保存不再从 Store 直接调用两个 canonical RPC。
- RPC 返回 DTO 是页面数组收敛的唯一输入；编辑和创建使用同一 upsert 规则。
- reset 或用户切换后的旧保存结果不能关闭 modal、写数组、刷新账户或显示提示。
- 刷新失败保持 accepted 事实，并有不会诱导重复写入的用户提示。
- PWA-063 及全部非目标未进入实际 diff。
