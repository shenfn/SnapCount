## 2. Repository 契约

扩展 `createAccountRepository({ client })`，新增纯读取方法：

- `listAccounts()`：读取并映射账户，返回 `accepted + rows` 或 `failed + error`。
- `listAccountEntries({ accountId, limit })`：按账户读取流水，返回结构化结果。
- `listAccountPayments({ accountId, limit })`：按账户读取还款记录；缺表兼容返回 `unavailable`，普通传输错误返回 `failed`。
- `listRepaymentCycles({ accountId, limit })`：按账户读取周期，不生成周期。
- `ensureRepaymentCycles({ cycleMonth })`：显式调用现有 ensure RPC，返回 `accepted/failed`，不与 list 合并。

Repository 复用 domain adapter 中的账户 mapper，并把流水、payment 与 cycle mapper 收敛到 Repository/adapter 侧。所有查询依赖当前认证会话和 RLS，不接收、发送或过滤 `user_id`。Repository 不读 `data_records`，不签图片，不修改余额，不持有 Vue 状态。

## 3. Account Detail State 契约

新增 `createAccountDetailFeature({ accountRepository, loadSourceSnapshot, getCurrentUserId })`：

- `load(account, options)`：加载当前账户详情；`options.ensureCycles` 只对负债账户显式启用。
- `refresh(account, options)`：与 load 使用同一状态机，供页面刷新和还款 accepted 后刷新。
- `reset()`：提升 generation，清空 inflight 与当前详情身份。
- `getState()` 或等价只读状态：向 Store 提供当前 identity、loading、sections、errors 和最后结果。

请求 identity 至少由 generation、当前 user id 和 account id 组成。相同 identity 的并发 load/refresh 复用同一 Promise；不同账户可以启动新请求，但旧 identity 只能返回 `stale`，不得收敛到当前状态。

来源快照通过注入的 `loadSourceSnapshot(account)` 读取。该协作者可以复用现有 `data_records` 与签名能力，但其 transport/DTO 不进入 Account Repository。

## 4. 分区与结果语义

详情分区为：

```text
entries / payments / repaymentCycles / sourceSnapshot
```

每个分区至少保留：

```text
status: idle | loading | accepted | failed | unavailable
data: 分区数据
error: 结构化错误或 null
```

整体结果：

| 结果 | 含义 | Store/Page 行为 |
|---|---|---|
| `accepted` | 所有适用分区成功；不适用来源快照不算失败 | 收敛全部分区，显示正常内容/真实空态 |
| `partial` | 至少一个分区成功，至少一个适用分区 failed/unavailable | 保留成功分区，显示局部错误与重试 |
| `failed` | 所有适用读取分区失败 | 不伪装为空详情，保留当前账户和重试出口 |
| `stale` | user/account/generation 已失效 | 不更新当前详情、错误或用户提示 |

ensure cycle 是读取前的显式准备结果。ensure 失败不得阻止已有周期的纯查询，但必须作为 repaymentCycles 分区的辅助错误保留；不得把写命令失败伪装成“没有周期”。

## 5. 列表收敛与隐藏副作用

- `loadData` 与 `refreshAccountsFromDB` 必须委托同一个 `accountRepository.listAccounts()`。
- 首次加载失败可保持空 rows，但必须保留失败状态；已有 rows 的刷新失败不得清空最后成功值。
- list accepted 后不得调用 `repairEmptyAccountSnapshotBalances`。
- 本片不删除 repair 函数，也不改变快照采纳条件；只移除其账户读取隐式调用。后续 wallet repair 切片决定显式入口、幂等和会话隔离。

## 6. Store 与页面兼容

- 保留 `accounts`、`selectedAccount`、`selectedAccountEntries`、`selectedAccountPayments`、`selectedAccountSourceSnapshot` 等现有公开引用。
- 新增最小详情状态引用，用于 sections loading/error 和最后 refresh result；页面不直接依赖 Repository。
- `openAccountDetail` 先建立当前 account identity，再委托 Feature；导航行为保持现状。
- `refreshAccountDetail` 返回结构化结果，使 Repayment Feature 能正确区分 accepted 后的 accepted/partial/failed/stale 刷新。
- 页面必须能对失败分区显示简短错误和重试按钮；成功分区继续展示，不用全页错误覆盖。
- 现有金额、还款状态、溢缴、来源截图打开、账户编辑和归档交互不改变。

## 8. 非目标

- 不修改账户创建、编辑、默认项、归档、还款确认/撤销、截图还款或流水补偿 helper。
- 不重写或删除 `repairEmptyAccountSnapshotBalances`，不执行余额校准，不新增生产 migration/RPC。
- 不把 `data_records`、图片签名或 wallet 快照写入放进 Account Repository。
- 不修改 iOS、Edge、Planner、生产配置、部署或 TestFlight。
- 不改变账户金额、周期状态、还款预览或 RLS 权威。

## 10. 完成定义

- PWA-065A 至 PWA-065E 均有场景测试与执行证据。
- `useStore.js` 不再直接查询 `accounts`、`account_entries`、`liability_payments` 或账户详情周期。
- 账户纯读取路径不再调用余额 repair 或隐藏 ensure 写命令。
- 相同详情请求不重复 transport；旧 account/user/generation 结果不污染当前详情。
- 分区失败不清空成功数据，页面可见局部失败与重试。
- 写入 accepted 后的详情刷新保留 accepted 事实，不诱导重复还款。
- 实际 diff 未进入账户 CRUD、wallet repair、数据库、iOS、Edge 或生产发布范围。
