## 2. PostgreSQL 契约

新增 `supabase/migrations/20260816160000_account_management_atomic_contract.sql`。

### 2.1 存量规范化与约束

- 所有 `is_archived = true` 的账户清除两个默认标记。
- 同一用户存在多个活跃默认时，分别按 `sort_order asc, created_at asc, id asc` 保留第一项，清除其余项，以保持当前客户端实际选择。
- 新增两个 active partial unique index：每个用户最多一个活跃默认支出、一个活跃默认收入。
- 新增归档默认 check：归档账户两个默认标记必须均为 false。
- 迁移可重复执行；第二次执行不得改变已规范数据或重复创建对象。

### 2.2 旧客户端兼容 trigger

`before insert or update` trigger 必须：

- 按 user id 获取事务级串行锁，避免 PWA/iOS 并发写出多默认。
- `NEW.is_archived = true` 时强制清除 `NEW.is_default_expense/income`。
- 目标账户设为默认时，在同一事务中先清除该用户其他账户的同类默认标记。
- 不修改余额、历史字段、来源快照或其他用户数据。

trigger 是存量 PWA/iOS 直写的兼容层；新 PWA 不直接依赖 trigger transport。

### 2.3 canonical RPC

`save_account`：

- 不接收 `user_id`；使用 `auth.uid()`。
- 创建时接受初始余额并同步初始/当前余额；编辑时忽略或拒绝初始余额变更，不修改余额。
- 校验名称、尾号、账单日、还款日、账户类型和自动扣款账户归属/类型/归档状态。
- save 不接收归档状态；归档使用独立 command。
- 有历史或未来引用的账户跨资产/负债家族变化返回 `account_type_transition_blocked`；空且无引用账户允许切换。
- 转为资产时清空负债专属配置。
- 返回 canonical `accounts` 行。

`set_account_archived`：

- 只操作当前用户账户并返回 canonical 行。
- 归档清除两个默认标记，不自动选择替代默认。
- 归档一个自动扣款资产账户时，清除其他账户的未来自动扣款配置及未关闭周期的 `auto_debit_account_id`；paid/ignored 历史周期、payments、entries 和余额保持不变。
- 恢复只取消归档，不恢复默认或自动扣款关系。

权限：authenticated 可执行，anon/public 不可执行；service role 保持管理能力。RPC 采用 `security definer` 与固定 `search_path`。

## 3. Repository 契约

扩展 `createAccountRepository({ client })`：

- `saveAccount(command)` 调 `save_account`，返回 `accepted + account` 或 `failed + reason/error`。
- `setAccountArchived(command)` 调 `set_account_archived`，返回相同结构。
- command 不包含 `userId`，Repository 不读 Vue 状态、不刷新列表、不显示提示。
- RPC 空响应不得报告 accepted。
- 已知数据库错误映射稳定 reason：`account_type_transition_blocked`、`invalid_auto_debit_account`、`account_not_found`、`service_error`。

## 4. Account Management Feature 契约

新增 `createAccountManagementFeature({ repository, getCurrentUserId })`：

- `save(command, hooks)` 与 `setArchived(command, hooks)` 产生稳定 command identity。
- 同 identity 并发调用复用 Promise；同一账户的不同写命令在已有写入期间返回 `account_command_conflict`，不得发第二次 transport。
- 创建命令以调用期生成的本地 command key 防重复点击；不同创建表单不是同一命令。
- `reset()` 提升 generation 并清空 inflight；Repository 已接受但 identity 过期时返回 `stale`，不得执行 convergence/refresh hooks。
- accepted 时先调用 `onAccepted(account)`，再调用 `refresh()`；refresh 异常或 failed 不改变 accepted 事实。
- 结果至少区分 `accepted`、`failed`、`conflict`、`stale`，accepted 带 `refreshStatus/refreshError`。

Feature 不依赖 Vue、Supabase、页面、确认框或提示文案。

## 5. Store 与页面兼容

- `saveAccount` 保留表单校验和公开函数名，但组装 command 后委托 Feature。
- `archiveAccount` 保留确认交互和公开函数名，委托专用 archive command；modal 不再用资料保存同时改变归档状态。
- accepted canonical account 按 id 更新/插入 `accounts`；若 `selectedAccount.id` 相同，同时更新 `selectedAccount`。
- accepted 后 modal 关闭并显示成功；stale 不显示旧用户提示；refresh failure 显示“已保存/归档，但刷新失败”，不诱导重复写入。
- `resetUserData` 调 `accountManagementFeature.reset()`。
- `useStore.js` 的账户管理片段不得出现 `sb.from('accounts').insert/update` 或 `unsetOtherDefaults`。
- wallet 账户区增加非空“已归档”分区；归档卡片仍可进入详情。
- 详情页提供明确的归档/恢复动作；归档说明历史流水和余额不变，恢复说明默认/自动扣款不会自动还原。

## 6. 类型与归档产品语义

- 同一账户可同时作为默认支出和默认收入；两个角色分别互斥。
- 归档当前默认后可以暂时没有默认账户，不自动猜测替代账户。
- 归档保留历史记录、流水、余额、账单和还款记录。
- 有历史/引用的账户不能通过资料编辑跨资产/负债家族；错误必须可见，原表单保持可修改重试。
- 不提供单账户物理删除。

## 10. 完成定义

- PWA-066A 至 PWA-066F 均有测试和执行证据。
- 旧客户端直写与新 RPC 都不能制造多活跃默认或归档默认。
- migration 重复执行、跨用户拒绝、余额/历史不变与类型阻断由 PostgreSQL 证明。
- Store 不再直接写账户管理表，旧命令不会污染新会话。
- canonical account 同步列表与当前详情，refresh failure 不掩盖 accepted。
- PWA 可查看并恢复归档账户；无单向死状态。
- diff 未进入 wallet repair、截图还款、iOS、Edge、Planner 或生产发布。
