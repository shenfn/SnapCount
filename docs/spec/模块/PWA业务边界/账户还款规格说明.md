## 2. 数据库特征契约

新增独立 PostgreSQL fixture 和断言脚本，在 CI 的隔离数据库中加载还款所需最小 schema、余额触发器与现有 RPC 定义，证明：

- 全额或部分还款产生一条 confirmed payment，并按现有规则更新 cycle。
- 负债账户只按有效还款减少欠款；可选扣款账户按本次 payment 金额扣减。
- 同一 cycle 重新确认先作废旧 payment/entry，再写新事实，余额不重复累计。
- 撤销 payment 会作废其流水并重算 cycle；重复撤销不重复回滚余额。
- 其他用户不能确认或撤销当前用户的记录。

该测试是已有数据库行为的特征测试，首次通过不伪装成红灯。本片不新增或修改生产 migration。

## 3. 目标接口

新增 `createAccountRepository({ client })`：

- `confirmRepayment(command)` 调用确认 RPC，返回 `accepted + cycle` 或结构化 `failed`。
- `revokePayment(command)` 调用撤销 RPC，返回 `accepted + cycle|null` 或结构化 `failed`。
- `mapRepaymentCycleRow(row)` 是本片唯一的 PWA cycle DTO mapper。

新增 `createRepaymentFeature({ repository, getCurrentUserId, now })`：

- `confirm(command, options)` 处理单一 cycle 的确认事务。
- `revoke(command, options)` 处理单一 payment 的撤销事务；command 显式携带 `paymentId`、`cycleId` 和 `accountId`。
- `reset()` 提升 generation 并清空 inflight 引用。

command 的并发签名只使用用户已确认的业务字段，不把 Feature 内生成的 `paidAt` 纳入签名。Repository 不接收 `userId`，数据库通过认证上下文和 RLS/函数检查隔离用户。

## 4. 结果与 Store 契约

| 结果 | Store 行为 |
|---|---|
| `rejected/unauthenticated` | 不调用 Repository，提示登录状态失效 |
| `rejected/invalid_input` | 不调用 Repository，保留页面输入 |
| `rejected/repayment_conflict` | 不发第二次写入，提示当前账单操作进行中 |
| `failed` | 不收敛 cycle；保留页面供重试 |
| `stale` | 不收敛、不刷新、不显示旧任务提示 |
| `accepted + refreshStatus ok/not_requested` | 使用 canonical cycle 收敛并显示成功 |
| `accepted + refreshStatus failed` | 保留 accepted 与 canonical cycle，提示列表刷新失败，不建议再次还款或撤销 |

Store 的 `onAccepted` 只更新 `repaymentCycles` 中对应 canonical cycle。刷新账户与当前详情仍走现有入口，但必须把失败显式抛回 Feature；页面继续负责确认弹窗、金额/状态预览、按钮和提示。
