# PWA 中转归档原子性评估

> 任务：CLEAN-001/A3、PWA-033
>
> 基线：`4ee12f7`（REC-009 收口 PR #73 合并提交）
>
> 状态：只读评估完成，待数据库契约测试与 PWA 接线分片

## 1. 结论

数据库已经存在中转归档的权威原子入口 `archive_staging_record`，不需要重新设计一套事务。当前风险来自 PWA 的采用不完整：iOS 和 PWA 通用域补全路径已经调用该 RPC，但 PWA 的快速归档、支出补全和收入补全仍在客户端分步执行“写正式记录 → 更新中转状态 → 写路由反馈”。第二步失败时会留下正式目标已经创建、中转记录仍开放的半状态。

下一步应分成两片，而不是把数据库、PWA 和历史数据一次性改完：

1. 先补 `archive_staging_record` 的 PostgreSQL 行为测试，固定行锁、幂等、账户流水、用户隔离、失败回滚和目标引用。
2. 数据库契约通过后，再让 PWA 的 `archiveStagingRecord` 通过现有 Staging Repository 调用该 RPC，并删除 `finishStagingArchive` 客户端事务模拟。

## 3. 生产迁移对账

只读 `migration list` 显示：

- 生产登记 `20260808054219`；
- 仓库登记 `20260808120000`；
- 两者没有相同版本号，迁移历史映射仍未修复。

管理 API 的只读函数查询同时证明，生产 `archive_staging_record` 已包含仓库最新版的关键语义：加固 search_path、nullable `p_record_date`/`p_occurred_at`、`p_occurred_at` 向账户保存 RPC 透传、`FOR UPDATE` 行锁和 `idempotent_retry` 返回，且不存在 `coalesce(p_occurred_at, now())`。

结论：当前函数能力不是阻断项，但版本表差异必须继续记录。未经单独授权不得执行 `migration repair`、重放迁移或生产部署。

## 4. 新发现的正确性风险

### B-02：PWA 跨表归档非原子

PWA 的多步流程可能在正式记录成功后、中转更新失败前中断。用户再次点击时可能看到重复、唯一约束错误或错误的开放任务状态。

### B-03：缺失金额被伪造成 `0.01`

PWA 快速归档支出/收入时使用 `amount > 0 ? amount : 0.01`，会把“没有金额证据”变成正式财务事实，违反记录生命周期规格的金额不变量。迁移到 RPC 后必须让金额缺失进入人工补全，不得换一个兜底值绕过 RPC 校验。

### M-10：幂等重试可返回错误类型的目标引用

当前 RPC 在已归档分支中根据本次请求的 `p_domain_key` 拼接 `target_reference`。如果同一中转 ID 用不同域重试，数据库不会重写目标，但可能返回与真实目标表不一致的引用。数据库契约测试应先固定期望：拒绝域不一致，或根据已存在目标推导真实引用。

### M-11：数据库测试覆盖不足

现有 PostgreSQL fixture 只验证通用域未知发生时间；安全 fixture 未验证 archive RPC 的 authenticated/anon 权限、跨用户拒绝、支出/收入账户流水、同 ID 幂等和失败回滚。静态源码断言不能替代事务行为测试。

### M-12：写成功后刷新失败仍缺结构化结果

RPC 成功后 PWA 当前会直接改本地数组。后续刷新失败时必须保留“业务已成功”的结果，只允许重试读取，不能重新执行归档写入。

## 5. 实施顺序

### 第一片：数据库契约证明

- 新建脱敏 PostgreSQL fixture，执行最新版迁移两次并验证幂等。
- 覆盖 expense、income、universal、账户流水、跨用户、同 ID 重试和故意失败回滚。
- 裁决域不一致的幂等重试；需要修复时新增迁移，不改旧迁移历史。
- 把测试挂入 PR `Release Validation`。

### 第二片：PWA 原子归档接线

- 在 `stagingRepository` 增加 archive action 和统一 DTO。
- Staging Feature 处理 `accepted/failed/stale`、动作去重和用户 generation。
- `useStore` 保留公开 API，只负责本地读模型收敛和提示。
- 删除 PWA `finishStagingArchive`，不再直接写正式表、中转状态或路由反馈。
- 财务字段不完整时打开/保留补全入口，不创建 `0.01`、默认渠道或默认支付事实。
