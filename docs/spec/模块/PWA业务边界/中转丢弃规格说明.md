## 1. 场景矩阵

| 场景 | 行为不变量 | 测试层 |
|---|---|---|
| PWA-042 | Repository 只调用 `discard_staging_record` 并映射结构化结果，不传 `user_id`、不计算终态或清理结论 | Repository 行为 |
| PWA-043 | 同一中转 ID 的重复丢弃共享一个请求，不能重复提交 RPC | Feature 行为 |
| PWA-044 | 用户切换或退出后，旧丢弃响应标记为 stale，不能移除新会话队列项 | Feature 行为 |
| PWA-045 | RPC/网络失败保留记录；页面只在 accepted 时推进，批量成功数只统计 accepted | Feature + 页面边界契约 |
| PWA-046 | RPC accepted 后即保留业务成功事实；本地列表收敛或读取刷新失败不得重发丢弃写操作 | Feature 行为 |

## 2. TDD 顺序

1. 固定现有 RPC 参数、成功 DTO 和图片清理提示所需字段。
2. 为重复点击、session stale、失败保留、页面推进和成功后本地失败写红灯。
3. 在现有 `stagingRepository` 增加 discard transport，在 `src/features/staging/` 增加最小 Discard Feature。
4. `useStore.discardStagingRecord` 只保留确认、提示和本地读模型收敛；页面根据结构化状态推进。
5. 保持批量交互不变，只修正成功计数和失败保留。
6. 运行 staging、pending queue、session、build、治理、安全和架构回归，再交 GitHub 门禁。

## 3. 完成定义

- PWA-042 至 PWA-046 均有自动化证据。
- `useStore` 丢弃路径不再直接调用 Supabase RPC。
- 失败、拒绝或 stale 不推进队列、不移除记录；accepted 不因后续本地失败而重复写。
- 用户切换 reset 包含 retry、archive 和 discard 三类 Staging Feature。
- 不修改数据库、Edge、iOS、生产部署或中转读取链。
