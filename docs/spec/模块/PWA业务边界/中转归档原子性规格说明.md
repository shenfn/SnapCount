## 1. 场景矩阵

| 场景 | 行为不变量 | 测试层 |
|---|---|---|
| PWA-033 | 中转归档只由 `archive_staging_record` 完成正式目标、中转状态和路由反馈写入 | SQL 行为 + Repository 契约 |
| PWA-034 | expense/income 归档与账户流水在同一事务成功或回滚 | PostgreSQL fixture |
| PWA-035 | 财务金额缺失或无效时拒绝归档并保留人工补全，不写 `0.01` | SQL + Feature 行为 |
| PWA-036 | 相同中转 ID 重试返回同一目标，不重复正式记录、账户流水或路由反馈 | PostgreSQL fixture |
| PWA-037 | 用户不能读取或归档其他用户的中转记录，anon 不能执行 RPC | PostgreSQL fixture |
| PWA-038 | 目标、中转状态或反馈任一步失败时整个事务回滚 | PostgreSQL fixture |
| PWA-039 | 已归档记录以不同域重试时拒绝或返回真实目标类型，不返回伪引用 | PostgreSQL fixture |
| PWA-040 | 归档成功但刷新失败时不重复写，只允许重试读取并保留成功事实 | Feature 行为 |

## 2. 分片门禁

### 数据库契约片

1. 先写 PostgreSQL 红灯/特征 fixture，不修改 PWA。
2. 现有行为正确的断言作为特征测试；PWA-039 如红灯，再新增最小迁移修复。
3. 新迁移必须可重复执行，并明确 revoke/grant、search_path 和函数签名。
4. 不修复生产迁移版本表，不执行生产部署。

### PWA 接线片

1. 数据库契约片合并后再开始。
2. Repository 只传输参数和映射 DTO，不计算金额、账户或状态。
3. Feature 只编排请求状态、session generation 和本地读模型收敛。
4. `useStore` 保留兼容 API；页面不新增 Supabase 直连。
5. 删除客户端事务模拟和财务伪造兜底。

## 3. 完成定义

- PWA-033 至 PWA-040 均有自动化证据或明确的非重复验证说明。
- PWA 不再直接创建中转来源的正式目标、更新中转终态或写路由反馈。
- 相同中转 ID 在超时、重复点击和刷新失败下最多产生一个业务结果。
- 财务记录没有金额证据时保持可修复，不进入正式统计和账户流水。
- 本地与 GitHub PostgreSQL、PWA、治理和安全门禁通过。
- 生产迁移编号差异和历史孤儿继续作为独立未验证项，不冒充已解决。
