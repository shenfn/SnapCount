## 1. 场景矩阵

| 场景 | 行为不变量 | 测试层 |
|---|---|---|
| PWA-047 | 开放中转查询固定状态过滤、排序和队列上限；Repository 不传 `user_id`；返回规范化中转 DTO | Repository 行为 |
| PWA-048 | 已处理查询只读取 `archived/discarded`，按 `resolved_at` 稳定排序并限制 30 条；不暴露页面数组 | Repository 行为 |
| PWA-049 | `loadData` 继续负责并发编排和 current user/run guard；旧加载不能写入新用户状态 | Store/Session 特征测试 |
| PWA-050 | 图片签名和还款候选继续留在现有 helper/账户边界；Staging Repository 不调用签名或账户周期规则 | 源契约/架构边界 |

## 2. 范围

- 在 `stagingRepository` 增加开放列表和已处理列表读取 transport。
- Repository 负责数据库列到 PWA 中转 DTO 的规范化映射。
- `useStore.loadData` 继续保留 Promise 并发、current user/run guard 和状态写入，只消费 Repository 结果。
- 继续由 Store/现有 helper 处理图片签名和 `repaymentCandidate`。

## 3. 非目标

- 不抽离交易、收入、通用记录、账户查询或正式记录写入。
- 不修改中转状态过滤语义、数据库函数、RLS、Edge、iOS 或生产配置。
- 不改变图片签名 URL 缓存、还款周期查询或候选算法。
- 不以删除 `loadData` 为目标；本片只移除中转表的直接查询和 DTO 映射重复。

## 4. TDD 顺序

1. 先为 Repository 查询参数、排序、限制、DTO 映射和错误结果写红灯。
2. 为 Store 中转查询改走 Repository、保留页面边界和签名/还款职责写红灯。
3. 写最小 Repository transport 与映射。
4. 接线 `loadData`，保持当前用户/run guard 和补充加载时序。
5. 运行中转专项、PWA build、治理、安全和架构回归。

## 5. 完成定义

- PWA-047 至 PWA-050 有自动化证据或明确的非重复验证说明。
- `useStore` 不再直接调用 `sb.from('staging_records')`。
- 开放/已处理列表的查询参数和 DTO 映射只有 Repository 一份。
- 图片签名、还款候选和正式记录边界未被本片吸收。
- 失败读取不伪造成功数组；旧用户/run 响应不能覆盖当前状态。
