## 1. 目标

把 iOS 手动确认还款和撤销还款从 AppState 内联编排收拢到纯 Swift Use Case，固定重复点击、操作冲突、用户切换、事务 accepted 和读模型刷新失败的出口，同时保持页面公开入口、还款预览、导航和现有成功提示兼容。

## 2. 输入和依赖

Use Case 接收：

- `AccountRepositoryProtocol`，只调用 `confirmRepayment` / `revokePayment`；
- session provider；
- 当前 user/generation context provider；
- canonical cycle 收敛回调；
- accepted 后按 `accountId` 刷新账户、详情和 dashboard 的回调。

确认命令包含 `cycleId/accountId/paidAmount/debitAccountId/status/note`；撤销命令包含 `paymentId/cycleId/accountId`。命令不接收 access token 或客户端 user ID。

`paid_at` 本片继续由 Repository 在 RPC transport 内生成，避免无规格地改变既有时间语义。

## 3. 结果契约

```text
transaction: accepted(operation, canonical cycle, recorded debit)
           | rejected(unauthenticated | invalid_input)
           | conflict(repayment_conflict)
           | failed(error)
           | stale
refresh: not_started | succeeded | failed(error)
```

- accepted 表示数据库事务已提交；canonical cycle 必须先收敛。
- refresh failed 不得把 accepted 改成 failed，也不得重发写 RPC。
- stale 不收敛、不刷新、不更新当前用户提示。
- Repository 返回撤销成功但没有 canonical cycle 时视为稳定协议失败，不伪造 cycle。

## 4. 并发与会话隔离

1. 身份为 `userId + cycleId`，签名为完整 command。
2. 同身份同签名复用 Task，只发一次 RPC。
3. 同账期不同确认命令、确认/撤销交叉操作返回 `repayment_conflict`。
4. reset 提升内部 generation 并清空索引；旧 Task 即使 RPC 返回也只能 stale。
5. session 前后、Repository 后和 refresh 后检查当前 user/generation。

## 5. 场景矩阵

| 场景 | 行为不变量 | 测试层 |
|---|---|---|
| A4-IOS-003A | 无效金额/标识和未认证在 transport 前拒绝 | XCTest |
| A4-IOS-003B | 同命令复用；同账期确认/撤销冲突；只发一次 RPC | XCTest |
| A4-IOS-003C | canonical cycle accepted 后刷新失败仍保持 accepted | XCTest |
| A4-IOS-003D | reset/user switch 使旧确认 stale，且不刷新 | XCTest |
| A4-IOS-003E | 撤销显式携带 payment/cycle/account，返回 canonical cycle | XCTest |
| A4-IOS-003F | AppState 保留公开入口、busy 和既有成功提示，仅投影 Use Case 结果 | XCTest/源边界 |

## 6. AppState 兼容边界

保留：

- `confirmRepayment(cycle:paidAmount:debitAccountId:status:note:) async -> Bool`；
- `revokeLiabilityPayment(payment:accountId:) async -> Bool`；
- `isSubmittingRepayment`、`repaymentMessage`；
- accepted 后账户列表、当前详情和 dashboard 刷新。

移出 AppState：session 获取、Repository 写调用、命令级 in-flight、conflict、stale 和 accepted/refresh 分类。AppState 不直接调用两个还款 Repository 写方法。

## 7. 非目标

- 不修改数据库 RPC/migration、余额触发器或状态集合。
- 不修改 `NativeRepaymentCalculator`、页面还款金额/最低还款/溢缴计算。
- 不处理截图还款、候选匹配、账户 CRUD、读取整体重构或钱包快照。
- 不修改 PWA、Edge、Planner、视觉 Token 或生产配置。
