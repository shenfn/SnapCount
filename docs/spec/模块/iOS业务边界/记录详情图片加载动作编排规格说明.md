## 1. 目标与范围

将记录详情图片签名与 hydration 的认证隔离、请求 identity、并发复用、reset/generation stale 和结果分类收拢到纯 Swift `RecordDetailImageUseCase`。AppState 继续决定触发时机，并负责把成功结果投影到既有详情缓存和选中详情。

本片只处理“已有详情副本之后补齐图片 URL”的动作编排，不改变详情读取 transport、图片签名服务或业务记录事实。

## 2. 明确边界

### Use Case 负责

- 接收 `NativeRecordDetail`、记录 canonical reference 和当前 session/context；
- 无 `imagePath` 或空路径时不调用 Repository，返回 `notNeeded`；已有 `imageURL` 时不重复 hydration；
- 认证后调用窄 Repository `hydrateDetailImage`，不自行拼接 storage URL；
- 以 `userId + generation + recordReference + imagePath` 作为请求 identity，同 identity 的 in-flight 请求复用同一个 Task；
- 在 transport 前和返回后校验 session/context；reset、用户切换或详情切换后的旧返回统一为 `stale`；
- 结构化返回 `hydrated(detail)`、`notNeeded`、`failed(message)`、`stale`；
- `reset()` 清理本地 in-flight 引用并递增内部 generation，已发出的请求不得投影到新会话。

### AppState 保留

- 在详情读取完成、缓存命中或用户重试时决定是否触发 hydration；
- 将 `hydrated(detail)` 与现有表达反馈字段合并，再写入 `recordDetailCache` 和 `selectedRecordDetail`；
- 失败时仅设置图片加载错误/重试入口，不清空详情、不覆盖 `recordDetailMessage`，不刷新财务或账户状态；
- 继续负责完整详情读取、表达计划、反馈卡片、导航和缓存生命周期；用户注销/切换时调用 Use Case `reset()`。

### Repository 保留

`RecordRepository.hydrateDetailImage(_:, accessToken:)` 只负责既有 transport 委托。它不接收客户端 user id，不拥有并发、generation、页面投影或业务重试策略。

## 3. 输出契约

```text
hydrated(detail)
notNeeded
failed(message)
stale
```

`hydrated` 只表示返回了详情图片字段的副本；不代表详情重新读取成功，不生成表达计划，不确认曝光，不改变记录、账户、余额或钱包事实。`failed` 不能被 AppState 当作完整详情失败。`stale` 不得写入任何当前会话或当前详情状态。

## 4. 行为不变量与场景矩阵

| 场景 | Given / When / Then 不变量 | 测试层 |
|---|---|---|
| A4-IOS-011A | 无图片路径或空路径时返回 `notNeeded`，Repository 调用次数为 0 | Use Case XCTest |
| A4-IOS-011B | 已有有效 `imageURL` 时不重复请求；同 identity 并发 hydration 只调用一次 | Use Case XCTest |
| A4-IOS-011C | signed URL 只能由 Repository/图片服务返回；Use Case 不拼 bucket、路径或过期参数 | Repository XCTest/源边界 |
| A4-IOS-011D | transport 失败返回 `failed`，不清空详情、不刷新财务/账户、不触发表达计划 | Use Case/AppState 特征测试 |
| A4-IOS-011E | reset、用户切换、generation 变化或 active reference 变化后，旧返回为 `stale` 且不投影 | Use Case XCTest |
| A4-IOS-011F | 成功投影只改变图片字段，既有表达反馈、planner 字段和详情事实保持不变 | AppState 特征测试 |
| A4-IOS-011G | 完整详情读取、表达计划和反馈入口仍由原职责拥有；页面不直接调用图片 transport | 源边界脚本 |

## 5. TDD 顺序与完成定义

1. **红灯**：新增 A4-IOS-011A-G XCTest、源边界脚本和执行记录；在当前基线证明缺少 Use Case、并发复用和专项 stale 契约。
2. **最小实现**：先建立纯 Swift Use Case 与窄协议，再由 AppState 做最小兼容投影和 reset 接线；不顺带改详情读取或图片服务。
3. **绿灯**：专项 XCTest、源边界、治理、架构、PWA/Edge 回归和 GitHub macOS iOS Build 全部通过。Windows 不运行 Swift/XCTest，macOS CI 为 iOS 编译与测试权威。
4. **收口**：更新 Spec、执行记录、阶段索引和交接快照；核对 diff 未包含数据库、Edge、Planner、PWA、账户、余额、保存/删除或视觉改动。

## 6. 非目标与禁止扩张

- 不改 `fetchDetail`、`fetchMonth`、详情 DTO、数据库、Edge、Planner 或签名 URL 参数；
- 不迁移 `SupabaseImageURLProvider` 的缓存寿命、重试次数或 bucket；
- 不把图片失败转成记录失败，不重发详情读取；
- 不处理记录编辑、删除、完整详情 Use Case 或表达计划生成；
- 不在本片刷新 dashboard、账户、余额、钱包或中转列表。
