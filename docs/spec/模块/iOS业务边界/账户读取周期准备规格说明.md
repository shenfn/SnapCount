## 1. 目标

把 `ensure_liability_repayment_cycles` 从账户详情和截图候选读取前的隐藏步骤改为显式周期准备命令。纯账户读取保持零写入；周期准备的 accepted、failed 和 stale 可观察，并由 AppState 兼容入口投影，不再通过 `try?` 静默吞掉失败。

## 2. 输入与依赖

`AccountReadPreparationUseCase` 只接收：

- 窄协议 `AccountReadPreparationRepositoryProtocol.ensureRepaymentCycles`；
- session provider；
- 当前 user/generation context provider。

命令只携带 `monthKey`。Use Case 不读取页面、账户列表、staging、候选或图片；Repository 不从读取方法内部调用 ensure。

## 3. 结果契约

```text
transaction: accepted
           | rejected(unauthenticated | invalid_input)
           | failed(error)
           | stale
```

- `accepted` 只表示周期准备 RPC 已完成，不代表详情读取成功。
- `failed` 允许后续纯详情读取继续展示已有 section，但必须保留准备失败提示和显式重试出口。
- `stale` 不更新账户、账期、候选或当前用户提示。
- 相同 user+month 命令共享 Task；失败后允许显式重试。

## 4. 场景矩阵

| 场景 | 行为不变量 | 测试层 |
|---|---|---|
| A4-IOS-005A | 未认证和无效月份在 session/transport 前拒绝；详情读取不隐藏 ensure | XCTest/源边界 |
| A4-IOS-005B | 同一用户同一月份准备复用 Task，只发一次 RPC | XCTest |
| A4-IOS-005C | prepare 失败单独可见，失败完成后可显式重试 | XCTest/AppState 源边界 |
| A4-IOS-005D | entries/cycles/payments 分区失败仍由 `NativeAccountDetail.loadErrors` 独立保留 | Repository 源边界/既有回归 |
| A4-IOS-005E | reset 或 user/generation 切换使旧 prepare stale | XCTest |
| A4-IOS-005F | 来源快照继续由 Wallet/Record Repository 读取，Account Repository 不吸收 `data_records` 或图片 | 源边界 |
| A4-IOS-005G | 截图候选和 `confirm_staging_repayment` 不进入本 Use Case | 源边界/回归 |

## 5. AppState 兼容边界

保留 `loadAccounts`、`loadAccountDetail` 和 `loadInboxRepaymentCandidates` 公开入口。负债详情和截图候选需要账期时，AppState 显式调用准备 Use Case，再进行现有纯读取；准备失败不得伪装为“没有还款计划”，stale 必须立即停止当前投影。

`resetUserScopedState` 必须 reset 准备 Use Case。现有详情 section、来源快照和候选引擎不迁入 Use Case。

## 6. 非目标

- 不修改数据库 migration/RPC、账期金额或状态规则。
- 不收拢截图还款候选/确认、收件箱导航或 processed staging；这些属于 A4-IOS-006。
- 不改账户管理、手动还款、钱包快照、PWA、Edge、Planner 或页面视觉。
- 不以文件大小或类型数量作为完成标准。
