# iOS 账户还款动作编排边界评估

> 任务：A4-IOS-003
>
> 阶段：A4 iOS 业务编排收拢
>
> 基线：`2f6b389`（A4-IOS-002 收口合并提交）
>
> 状态：评估中；本文件不修改业务实现

## 1. 结论

下一片最小切片建议选择“手动账户还款确认/撤销动作编排”。它只收拢已有的两个 AppState 命令：`confirmRepayment` 与 `revokeLiabilityPayment`，不改变数据库 RPC、还款金额计算或页面视觉。

这两个动作的事务权威已经在 `AccountRepository` 中明确：

- `set_repayment_cycle_paid_amount`
- `revoke_liability_payment`

当前问题不在 transport，而在 `AppState` 同时承担了 session 获取、busy 锁、请求调用、账户/详情/dashboard 刷新和消息投影。该组合使 accepted 与 refresh failure 难以区分，也没有与 A4-IOS-002 一致的 generation stale 和同命令并发语义。

## 2. 当前职责盘点

| 位置 | 当前职责 | 评估 | 目标归属 |
|---|---|---|---|
| `AppState.confirmRepayment` | session、全局 busy、输入传递、Repository RPC、刷新、成功/失败消息 | 业务编排过重 | `RepaymentActionUseCase`；AppState 保留兼容入口 |
| `AppState.revokeLiabilityPayment` | session、全局 busy、Repository RPC、刷新、成功/失败消息 | 与确认动作共享状态但没有命令级并发语义 | `RepaymentActionUseCase`；AppState 保留兼容入口 |
| `AppState.refreshAfterRepayment` | 账户列表、选中详情、dashboard 三处刷新 | 读取副作用应单独表达，且不能覆盖 accepted 事实 | Use Case 的 refresh 协作回调或 AppState 适配层 |
| `AccountRepository.confirmRepayment` | 校验金额、组装确认 RPC 参数、解码 canonical cycle | transport 与少量输入校验混合 | Repository 保留 RPC 参数/DTO/错误映射；命令校验移至 Use Case |
| `AccountRepository.revokePayment` | 组装撤销 RPC 参数、解码 canonical cycle | transport 边界清晰 | Repository 保留 |
| `confirmStagingRepayment` | staging 候选、跨表确认、收件箱刷新 | 另一种跨边界事务 | 本片排除，后续独立切片 |

## 4. 本片范围

### 纳入

1. `AppState.confirmRepayment` 的 Use Case 编排边界。
2. `AppState.revokeLiabilityPayment` 的 Use Case 编排边界。
3. 同一命令的 Task 复用。
4. 同一账期不同确认命令、确认与撤销交叉操作的冲突出口。
5. reset 或用户切换后的 generation/user stale 保护。
6. RPC accepted 后 canonical cycle 先收敛；账户列表、当前详情和 dashboard 刷新独立记录结果。
7. AppState 公开入口、`isSubmittingRepayment` 和 `repaymentMessage` 的兼容投影。
8. 对应 XCTest、源边界检查、阶段索引和交接记录。

### 不纳入

- `confirmStagingRepayment`、截图候选计算和 inbox 状态。
- 账户创建、编辑、默认项、归档。
- 账户列表/详情读取整体重构和 `ensureRepaymentCycles` 的副作用拆分。
- 钱包快照动作、流水 helper、数据库 migration/RPC 修改。
- `NativeRepaymentCalculator` 的金额、最低还款、状态和溢缴规则修改。
- 页面视觉、导航、文案设计、PWA、Edge、Planner 和生产配置。

## 5. 目标行为契约

### 5.1 命令输入

确认命令固定携带：`cycleId`、`accountId`、`paidAmount`、`debitAccountId?`、`status`、`note`。撤销命令固定携带：`paymentId`、`cycleId`、`accountId`。Use Case 负责检查必填标识、金额大于零和命令目标一致性；Repository 不推导业务状态。

### 5.2 结果分层

| 结果 | 不变量 | AppState 行为 |
|---|---|---|
| `rejected/unauthenticated` | 未取得当前用户时不发 RPC | 保留输入，提示登录失效 |
| `rejected/invalid_input` | 不调用 Repository | 保留输入，可修正后重试 |
| `rejected/repayment_conflict` | 同目标不同命令不重复写入 | 不刷新，不显示成功 |
| `failed` | RPC 未 accepted 时不收敛本地 cycle | 保留页面状态，可重试 |
| `stale` | generation 或用户不匹配时不更新当前用户状态 | 不收敛、不刷新、不显示旧消息 |
| `accepted + refresh ok` | canonical cycle 是唯一已接受事实 | 收敛 cycle，刷新读模型并显示成功 |
| `accepted + refresh failed` | 刷新失败不撤销 accepted | 保留 canonical cycle，单独提示刷新失败，不诱导再次还款 |

### 5.3 并发

- 同一用户、同一目标、同一业务命令共享一个 Task，不产生第二次 RPC。
- 同一账期的不同确认命令返回结构化 conflict。
- 确认与撤销交叉操作返回结构化 conflict，不能依赖全局按钮锁掩盖语义。
- reset/user switch 会使旧 Task 的 accepted、refresh 和 message 投影全部 stale。

## 6. 跨端对应关系

本片沿用 PWA-064A 至 PWA-064F 已验证的业务不变量，但不复制 PWA 的 Store 实现：

| PWA 契约 | iOS 对应 |
|---|---|
| PWA-064B Repository 独占 RPC | `AccountRepository` 继续独占两个 RPC 的参数和 DTO 解码 |
| PWA-064C 命令复用与冲突 | `RepaymentActionUseCase` 命令级 Task/冲突键 |
| PWA-064D reset/user stale | AppState `userStateGeneration` 与 Use Case generation |
| PWA-064E accepted/refresh 分层 | Use Case 返回 canonical cycle 与 refresh status |
| PWA-064F 页面只提交确认命令 | iOS 页面保留预览和确认交互，AppState 仅作兼容门面 |

跨端共享的是行为语义，不共享 Swift/TypeScript 编排代码；后续实现应补充同一组 JSON 场景 fixture，避免两端状态阈值或 stale 规则漂移。

## 9. 完成定义

- 本片所有纳入行为都有 XCTest 证据，且测试断言行为不变量而非固定成功文案。
- AppState 不再直接编排两个还款 RPC、Task 并发和 accepted 后刷新。
- 同命令不重复写入；冲突、失败、stale 均有明确出口。
- accepted 与 refresh failure 可独立观察，失败不会诱导重复还款。
- `confirmStagingRepayment`、账户 CRUD、读取整体重构和数据库改动未进入 diff。
- 阶段索引、ADR、执行记录/交接快照已更新，fresh-agent 可沿指针链恢复本片范围。
