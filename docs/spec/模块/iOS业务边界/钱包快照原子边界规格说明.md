## 1. 用户价值与本轮目标

iOS 用户在“从钱包快照创建账户”或“将快照关联到已有账户”时，必须得到与 PWA 相同的账户、记录、账期、还款证据和余额语义。当前 iOS Repository 通过多次 REST 写入实现同一动作，部分成功会留下无法可靠重试的中间状态。

本轮只定义并固定 iOS 接入边界：`WalletSnapshotRepository` 的两个写入口统一调用已存在的 `apply_wallet_snapshot(p_record_id, p_account_id)`，由数据库原子命令返回 canonical 结果；AppState 保持现有公开动作和页面入口兼容。

## 2. 当前证据与问题

| 位置 | 当前行为 | 风险 |
|---|---|---|
| `ios/SnapCount/Repositories/WalletSnapshotRepository.swift` | `createAccount` 先查账户、再 POST `accounts`、PATCH `data_records`、upsert 还款周期；`link` 先 PATCH 账户和记录，再补周期与流水 | 任一步失败都会留下部分成功；客户端无法判断应重试还是补偿 |
| `WalletSnapshotRepository.reconcileLiability` | 客户端计算 delta，调用 `create_account_entry_for_record` 后再 PATCH `last_reconciled_at` | 账户流水和校准水位不是同一事务 |
| `ios/SnapCount/App/AppState.swift` | 页面动作直接调用 `createAccount`/`link`，成功后刷新多个读模型 | Repository 结果只有 `accountId/warnings`，无法区分 created、replayed、needs-confirmation |
| PWA `AccountRepository.applyWalletSnapshot` | 只传 `recordId/accountId`，映射 canonical RPC 结果 | 已有可复用的跨端业务契约 |

## 3. 范围

### 3.1 本轮范围

- 为 iOS 固定 `apply_wallet_snapshot` 的 transport 参数：只发送 `p_record_id` 和可空 `p_account_id`。
- `createAccount(from:)` 映射为 `accountId = nil`；`link(_:to:)` 映射为目标账户 ID。
- 解码并校验 canonical 响应：`outcome`、`record_id`、`linked_account_id`、`account`、可选 `cycle/payment`、`balance_changed`、`review_required`。
- 让 iOS 结果模型保留 `created`、`linked`、`replayed`、`needs_confirmation` 和 `invalid_response` 等稳定语义；不把 `needs_confirmation` 降级成普通 warning。
- 保留 AppState 的 `createAccountFromWalletSnapshot`、`linkWalletSnapshot`、刷新入口和页面导航兼容性；本轮不要求完成 AppState 全量 Use Case 拆分。
- 用 XCTest 固定 Repository 的 RPC 参数、结果映射、畸形响应拒绝和稳定错误映射；用源边界测试保证写路径不再调用旧的多步 REST/helper。

### 3.2 非目标

- 不修改 `supabase/migrations`、`apply_wallet_snapshot` SQL、PWA 实现、Edge、Planner、生产配置或真实数据。
- 不在本轮抽离完整 AppState、重写页面 UI、改变导航或刷新策略。
- 不新增第二套 iOS 金额、账期、还款或余额校准规则。
- 不把 `create_account_entry_for_record` 作为钱包快照写入口继续保留在该 Repository；该 primitive 的其他消费者不在本轮处理。
- 不执行生产 migration、部署、TestFlight 或远端分支/worktree 清理。

## 4. 依赖方向与权威归属

```text
DomainsView / AppState（兼容公开动作）
  -> WalletSnapshotRepository（iOS transport + DTO 映射）
    -> apply_wallet_snapshot(p_record_id, p_account_id)
      -> data_record + account + cycle/payment + entry/balance 原子事务
```

- 数据库 RPC 是跨表写入、权限、金额、幂等和失败回滚的唯一权威。
- iOS Repository 只负责认证 token、参数传输、响应解码和稳定错误映射，不计算 delta、不创建账期、不写账户流水。
- AppState 只负责 session 获取、动作 busy、结果收敛和刷新；不复制数据库状态机。
- `NativeDataService` 不新增钱包快照写入逻辑；本轮优先复用现有 Repository Protocol。

## 5. 场景矩阵

| 场景 | Given / When / Then 不变量 | 测试层 |
|---|---|---|
| A4-IOS-001 | create 动作只调用一次 `apply_wallet_snapshot`，参数为 `p_record_id=snapshot.id`、`p_account_id=null`；不发送账户资料或 `userId` | XCTest Repository 参数/源边界 |
| A4-IOS-002 | link 动作只调用一次同一 RPC，`p_account_id` 为目标账户 ID；不执行旧 REST 多步写入 | XCTest Repository 参数/源边界 |
| A4-IOS-003 | RPC 返回 `created/linked/replayed` 时，结果保留对应 outcome、账户 ID、账户 DTO 和可选 cycle/payment；不把不同 outcome 合并成 warning | XCTest DTO 映射 |
| A4-IOS-004 | RPC 返回 `needs_confirmation` 时，动作视为“事务已接受但需人工确认”，保留 `reviewRequired`，不自动重发或伪造成功文案 | XCTest 结果语义/AppState 特征测试 |
| A4-IOS-005 | RPC 返回空数组、缺少 outcome、record ID 不匹配、linked account 不匹配或 malformed nested DTO 时，Repository 返回 `invalid_response`，不得报告 accepted | XCTest 畸形响应 |
| A4-IOS-006 | `wallet_snapshot_not_found`、`account_kind_mismatch`、`snapshot_link_conflict` 等稳定数据库错误保持可区分；不把所有错误降成网络 warning | XCTest 错误映射 |
| A4-IOS-007 | AppState 仍保留现有公开入口和刷新触发；Repository accepted 后才允许收敛/刷新，失败或 needs-confirmation 不假装完成 | XCTest AppState 特征/回归 |
| A4-IOS-008 | 用户切换或 session 失效不会把旧请求结果写入当前账户读模型；至少保留现有 action guard，并为后续 Use Case generation 接线留出边界 | XCTest 会话回归；完整 stale 机制为后续切片 |

跨端映射：A4-IOS-001 至 A4-IOS-006 对应 PWA-068G 的 Repository 契约；A4-IOS-007 至 A4-IOS-008 对应 PWA-068H/PWA-068I 的客户端收敛语义。数据库行为不在 iOS 侧重复测试，以 PR #108 的 PostgreSQL 证据为权威基线。

## 6. iOS 结果契约

Repository 内部应使用显式结果模型，至少包含：

```text
outcome: created | linked | replayed | needs_confirmation
recordId: String
linkedAccountId: String
account: NativeAccount
cycle: NativeRepaymentCycle?
payment: NativeLiabilityPayment?
balanceChanged: Bool
reviewRequired: Bool
```

错误分为两类：

1. **稳定业务错误**：从 RPC 错误消息映射为可判断的 `SupabaseRemoteError` reason，例如未认证、记录不存在、账户类型不匹配、关联冲突和还款证据冲突。
2. **协议/环境错误**：HTTP、解码、空响应和字段不一致统一为 `invalid_response` 或 transport error；不得返回一个看似成功的 `NativeWalletSnapshotLinkResult`。

`userId` 仅由 session 用于认证上下文，不进入 RPC body，也不由 iOS 决定跨表所有权。
