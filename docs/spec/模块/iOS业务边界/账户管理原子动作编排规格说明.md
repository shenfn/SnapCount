## 1. 目标

把 iOS 账户创建/编辑、归档/恢复接入数据库 canonical account command，并将 AppState 当前的 session、并发、写入、列表/详情刷新和提示投影收拢到纯 Swift `AccountManagementActionUseCase`。页面公开入口保持兼容，数据库继续作为默认项、归档引用和类型迁移的唯一事实源。

## 2. 依赖和输入

Use Case 接收：

- `AccountManagementRepositoryProtocol`：只执行保存或归档 command，返回 canonical account；方法名为 `saveAccount` / `setAccountArchived`；`AccountRepository` 在 transport 层实现该窄协议，但不扩张现有还款/读取 `AccountRepositoryProtocol`；
- `NativeSessionProvider`：获取当前 user/access token；
- 当前 user/generation context provider；
- accepted account projection callback；
- accepted 后的列表/详情 refresh callback；
- `reset()` 能力，使 in-flight command 失效。

Use Case 不依赖 SwiftUI、HTTP、Supabase client、AppState、页面或数据库 row 类型。

保存 command：

```text
accountId?: String
name: String
type: NativeAccountType
institution?: String
last4?: String
initialBalance: Decimal/String  // 仅创建有效；编辑不得改变余额
billDay?: Int
paymentDueDay?: Int
autoDebitAccountId?: String
autoConfirmRepayment: Bool
isDefaultExpense: Bool
isDefaultIncome: Bool
```

归档 command：

```text
accountId: String
archived: Bool
```

Repository 将保存字段映射到 `save_account` 的 `p_*` 参数，将归档字段映射到 `set_account_archived(p_account_id, p_archived)`。RPC 不接收客户端 `userId`；所有权由 `auth.uid()` 决定。

## 3. 结果契约

```text
transaction: accepted(operation, canonical account)
           | rejected(unauthenticated | invalid_input)
           | conflict(account_command_conflict)
           | failed(stable RPC/protocol error)
           | stale
refresh: not_started | succeeded | failed(error)
```

- `accepted` 只表示 RPC 已返回可校验的 canonical account；空响应或缺少账户 id 必须是 `failed(invalid_response)`。
- `accepted` 后先执行 canonical account projection，再执行 refresh；refresh 失败不撤销 accepted，也不得重发写 RPC。
- `stale` 不执行 accepted projection、列表/详情 refresh 或当前用户提示。
- 数据库错误 reason 至少保留 `account_type_transition_blocked`、`invalid_auto_debit_account`、`account_not_found` 和 `service_error` 的可判断性。

## 4. 并发与会话隔离

1. 命令身份为 `userId + accountId/createKey`；签名包含完整保存字段或目标 archived 状态。
2. 同身份同签名的 in-flight 调用复用同一个 Task，只发送一次 RPC。
3. 同一账户的保存与归档/恢复交叉执行返回 `account_command_conflict`，不发送第二次 RPC。
4. 创建命令使用调用期生成的稳定 create key；不同表单不能误复用。
5. `reset()` 提升内部 generation 并清理本地 in-flight；旧请求即使 RPC 已 accepted，也只能返回 stale，不得写当前用户状态。
6. RPC 前、RPC 后、projection 前和 refresh 后检查 user/generation。

## 5. 场景矩阵

| 场景 | Given / When / Then 不变量 | 测试层 |
|---|---|---|
| A4-IOS-004A | 空名称、非法尾号、非法账单日、空账户 id 归档在 transport 前 rejected；Repository 不被调用 | Use Case XCTest |
| A4-IOS-004B | 保存调用只发送 `save_account`；归档调用只发送 `set_account_archived`；不再 REST 写 `accounts` 或调用 `unsetOtherDefaults` | Repository XCTest/源边界 |
| A4-IOS-004C | RPC 返回 canonical account；列表和当前详情按 id 收敛同一账户；不重新推导默认/归档语义 | Use Case/AppState XCTest |
| A4-IOS-004D | 同身份同签名并发保存/归档复用 Task，Repository 各只收到一次调用 | Use Case XCTest |
| A4-IOS-004E | 同一账户保存与归档交叉命令返回 `account_command_conflict`，不发第二次 RPC | Use Case XCTest |
| A4-IOS-004F | RPC accepted 后 refresh 失败仍返回 `accepted + refresh=failed`，不重复写入 | Use Case/AppState XCTest |
| A4-IOS-004G | reset/user switch 使旧请求 stale；旧结果不 projection、不 refresh、不提示当前用户 | Use Case XCTest |
| A4-IOS-004H | RPC 空响应、跨用户、类型迁移阻断、无效自动扣款账户和网络错误保持可区分失败 | Repository/Use Case XCTest |

## 6. AppState 兼容边界

保留：

- `saveAccount(_ draft: NativeAccountDraft) async -> Bool`；
- `setAccountArchived(_ account: NativeAccount, archived: Bool) async -> Bool`；
- `isSavingAccount`、`accountMessage`、表单校验、确认门禁、列表和已归档分区。

移出 AppState：

- 账户写 RPC 选择和参数拼装；
- command identity、Task 复用、冲突和 stale 判断；
- accepted/refresh 结果分类。

AppState 仅把结构化结果投影为既有 UI 状态，并按 canonical account id 更新列表和当前详情。refresh failure 不得把成功写入显示为未保存。
