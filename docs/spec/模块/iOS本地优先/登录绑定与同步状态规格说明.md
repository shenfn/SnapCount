# LOCAL-003C 登录绑定与同步状态规格说明

> 规格编号：LOCAL-003C
>
> 状态：提议，进入红灯准备
>
> 上游：`LOCAL-003`、`LOCAL-003B`、`LOCAL-DATA-001`、`ADR-038`、`ADR-039`

## 1. 目标

本片把“已有云端账号接入本地优先 App”收敛为一个可验证的身份与同步状态边界：

- 用户可以在统一业务页面中登录已有账号；
- 登录只建立云端身份，不自动上传本地业务数据；
- 登录后先展示本地 workspace 与云端账号的绑定预览，再由用户决定是否开启同步；
- 同步状态、云端数据可见性和本地数据权威彼此独立；
- 账号切换、退出登录和异步任务完成不会把旧账号结果写回当前 workspace；
- 用户在任何确认点都能选择暂不开启同步，并继续使用本地数据。

本片只固定状态和用户出口，不实现首次双向同步。这样后续 `LOCAL-003D` 可以在明确边界上实现导入与 Outbox 上传，而不是把登录、绑定和传输揉成一个不可回滚动作。

## 2. 当前实现基线

只读核对基于 `origin/main@bc250a5`：

| 区域 | 已有事实 | 本片处理 |
|---|---|---|
| 本地 profile/workspace | `local_profiles.id` 已经是本机数据空间的稳定 ID，表中已有 `cloud_user_id`、`sync_enabled`；`LocalProfileStore` 可创建/读取 profile | 将 profile 明确定义为 `LocalWorkspace`；`cloud_user_id` 只表示确认后的绑定，不表示登录候选；checkpoint 等由后续同步切片实现 |
| 本地业务数据 | `local_expenses`、`local_accounts`、`local_account_entries` 已有稳定 UUID、版本、tombstone 基础 | 本片只读取数量和摘要用于预览，不迁移其他数据域 |
| Outbox | `local_outbox_operations` 已有 `pending/processing/failed/sent`、顺序号和幂等键 | 本片不发送、不重试、不改变既有操作语义 |
| 登录 | `SupabaseAuthService` 支持登录、注册、恢复和退出；`AppState` 登录后会获取 upload token 并刷新旧云端 Dashboard | 明确登录后的本地优先门禁；禁止把获取 session 当成绑定或上传授权 |

## 3. 非目标与冻结范围

本片不做以下事情：

- 不实现云端记录导入、首次双向同步、增量传输、冲突合并或 Outbox 上传；本片只定义增量游标和冲突的契约语义；
- 不新增或修改 Supabase 表、RPC、Edge Function、RLS 或生产迁移；
- 不把收入、运动、睡眠、饮食、阅读等域接入本地同步；
- 不改变 PWA；PWA 继续维护模式；
- 不引入 Apple 登录、手机号登录或新的身份提供商；
- 不把本地图片、原图、AI 上下文或 API Key 随登录上传；
- 不执行生产部署、迁移、TestFlight 或远端分支清理。

## 4. 状态模型

### 4.1 LocalWorkspace 与绑定归属

当前 `local_profiles` 行就是一个 `LocalWorkspace`：

```text
LocalWorkspace
├── workspaceID = local_profiles.id
├── local facts: expenses / accounts / entries / tombstones
├── binding: unbound / bound(remoteUserID)
└── sync metadata: generation / checkpoint / outbox
```

本地事实属于 workspace，不直接属于 Supabase 用户。登录得到的用户 ID 先是一次性的候选身份，只有用户确认“合并并开启同步”后才写入 `cloud_user_id` 作为绑定关系。

- `signedOut` 不删除 workspace 或其业务事实；
- 已绑定 A 的 workspace 在 B 登录时不得自动改绑、上传或读取为 B 的同步副本；
- B 可以继续使用本地页面，但必须显示“本机 workspace 已绑定其他账号，云同步未开启”，直到未来提供显式 workspace 切换/解绑流程；
- 未绑定 workspace 的本地 Outbox 可以保留，但没有明确绑定目标时不得上传。

### 4.2 正交状态轴

业务页面只依赖本地事实，不以 `isSignedIn` 选择另一套页面树。实现需要分别表达：

| 状态 | 值 | 含义 |
|---|---|---|
| 本地事实 | `localDatabase` | 当前设备 GRDB 是即时事实来源，新增/编辑/删除先在此完成 |
| 云端身份 | `signedOut` / `signedIn(userID)` | 是否持有当前 Supabase 会话；不代表 workspace 已绑定 |
| workspace 绑定 | `unbound` / `bound(userID)` / `mismatch(boundUserID, signedInUserID)` | 当前 workspace 是否已有确认绑定，以及登录用户是否匹配 |
| 同步授权 | `disabled` / `enabled` | 用户是否明确允许当前 workspace 与匹配的云端用户同步 |
| 冲突状态 | `none` / `unresolved` | 是否存在需要人工处理的实体级冲突 |

同步运行态另行表达：

```text
signedOut + unbound + disabled
  --Authenticate--> signedIn + unbound + preview
preview --暂不开启同步--> signedIn + unbound + disabled
preview --合并并开启同步--> signedIn + bound + ready
ready --LOCAL-003D 开始首次同步--> syncing
syncing --本轮完成--> synced
syncing --网络/鉴权/服务器失败--> failed
syncing --不可自动处理差异--> conflict
failed --用户重试--> syncing
conflict --用户完成处理--> ready
signedIn + mismatch --禁止开启同步--> signedIn + mismatch + disabled
任意已登录状态 --退出当前账号--> signedOut + disabled
```

状态轴必须独立存储或可无歧义推导，不能把身份、绑定、同步和冲突压缩成一个不断膨胀的枚举。

### 4.3 Checkpoint 契约

同步进度不是一个“正在同步”的展示字段，而是可恢复协议的一部分。后续同步元数据至少包含：

```text
SyncCheckpoint
├── workspaceID
├── syncGeneration
├── pullCursor              # 云端同步流进度，默认是跨域 opaque cursor
├── lastSuccessfulSyncAt
├── activeAttemptID         # 当前/最近一次运行的稳定诊断 ID
└── pendingMutationCount    # 从当前 workspace Outbox 派生，不重复存储
```

- `pullCursor` 表示云端同步流的进度，不是 expense、income 或任何单一数据域的版本号；
- 如果服务端未来按域提供多个 cursor，模型必须显式带 `scope`，不能靠字段名猜测；
- `syncGeneration` 在绑定、退出、重置或 workspace 切换时递增，旧任务返回时必须校验；
- App 被杀或网络中断后，只能从已持久化的 checkpoint 恢复，不得用“已经差不多”推断进度；
- `pendingMutationCount` 由 `local_outbox_operations` 当前 workspace 的非 `sent` 行计算。

### 4.4 冲突契约

第一版采用实体级乐观并发，不做 CRDT、字段级自动合并或静默 last-write-wins：

- 同一稳定实体 ID 在本地操作产生时记录 `baseVersion`；
- 推送时远端版本不等于 `baseVersion`，或远端已经存在不兼容 tombstone，则进入 `unresolved`；
- 冲突保留本地候选、远端候选和版本证据，不覆盖任一事实；
- 账户、流水和还款冲突按操作/实体处理，禁止合并余额字段；余额仍由有效流水派生；
- 冲突列表与人工处理出口由 `LOCAL-003E` 实现，本片只固定判定条件和失败出口。

### 4.5 状态不变量

1. `signedIn` 不自动推出 `bound` 或 `enabled`，登录成功后同步授权仍为 `disabled` 或 `preview`。
2. `cloud_user_id` 只有在明确绑定后才持久化；登录候选身份不能成为本地事实归属。
3. `disabled` 状态不得读取或写入云端业务数据；认证所需的 session、法律同意和必要账号元数据不视为业务同步。
4. `preview` 阶段只读本地摘要和云端可用范围，不写本地业务事实、不写 Outbox、不上传本地业务数据。
5. 本地业务写入成功与否不依赖网络、登录或 AI；同步失败不撤销本地事务。
6. 退出登录保留 workspace、账户、消费、流水和 tombstone；只停止当前账号任务并清除云端会话凭据。
7. 账号切换时，旧账号异步结果必须被丢弃，不能刷新新账号或新 workspace 的列表、余额、设置和图片缓存。
8. `mismatch` workspace 不得被新账号自动改绑或上传；必须有未来的显式切换/解绑出口。
9. 账户余额仍由本地期初余额与有效流水派生；绑定预览和未来同步均不得写入云端快照覆盖本地余额。

## 5. 用户流程

### 5.1 未登录本地用户

1. App 启动创建/读取本地 workspace（当前实现为一个 `local_profiles` 行）。
2. Today、Records、账户和 `LOCAL-003B` 已覆盖的详情页面直接读取本地 Repository。
3. Settings 显示“本机数据”“未登录”“同步未开启”，提供“登录并管理云同步”入口。
4. 用户不登录时可以继续记录、编辑、删除和导出；不得因缺少 session 显示云端错误。

### 5.2 登录已有账号

1. 用户在 Settings 进入登录页并完成登录。
2. App 保存 session 到 Keychain，将当前云端用户作为候选身份；这一步不写入 `cloud_user_id`，也不改变 `sync_enabled`。
3. App 为当前 workspace 生成绑定预览：本地记录/账户数量、待上传操作数量、云端可用范围、图片/AI 默认不上传说明。
4. 在预览完成前，统一业务页面继续展示本地数据；不得用旧云端 Dashboard 覆盖本地列表、账户或余额。
5. 用户必须看到以下三个同步出口，另有独立的退出账号动作：
   - `暂不开启同步`：保持本地模式，保留 session 但同步授权为关闭；
   - `合并并开启同步`：记录用户授权，进入 `ready`，由 `LOCAL-003D` 执行首次同步；
   - `退出当前账号`：清除 session，保留本地数据并停止旧任务。

### 5.3 账号切换与重启

- 切换到不同云端用户前，先结束当前账号的预览/同步任务，再读取新用户身份；旧任务结果不得写回。
- 如果当前 workspace 已绑定其他账号，新的云端用户只能进入 `mismatch`，不得直接使用“合并并开启同步”；当前版本不自动创建第二 workspace，需保留明确的本地继续使用出口。
- App 重启后从本地 workspace 恢复本地页面；从 Keychain 恢复的 session 只能恢复身份，不得静默开启同步或导入云端业务数据。
- 如果 session 失效，本地页面继续可用；Settings 显示需要重新登录或同步暂停，不清空本地记录。

## 6. 绑定预览契约

后续实现应通过 Use Case 输出稳定的预览模型，而不是由 View 直接拼接多个 Repository：

```text
BindingPreview
  workspaceID: UUID
  candidateCloudUserID: String
  cloudEmail: String?
  currentBinding: BindingState
  localExpenseCount: Int
  localAccountCount: Int
  pendingOutboxCount: Int
  remoteScope: [RemoteDataScope]
  localOnlyNotice: String
  options: [BindingOption] // 暂不开启同步、合并并开启同步、退出当前账号
```

契约要求：

- 预览读取可以失败，但失败必须分层显示为“无法读取云端范围”，不能伪造为零条；
- 本地数量来自当前 workspace，不能读取其他 workspace；
- `pendingOutboxCount` 只统计当前 workspace 的未发送操作；
- `remoteScope` 只描述可用范围和是否需要后续导入，不返回未经用户授权的业务详情；
- 不在预览中返回 API Key、access token、refresh token、签名图片 URL 或原始 AI 内容；
- 预览对象必须带 `sessionGeneration`/等价身份标识，异步返回前后需校验仍属于当前 workspace 和云端用户。

## 7. Outbox、checkpoint 与实现边界

```text
Settings / LoginView
  -> AccountBindingFeature（状态与用户出口）
    -> BindingPreviewUseCase
      -> LocalWorkspaceRepository + LocalSyncMetadataRepository
      -> RemoteIdentityRepository（只读身份/范围）
    -> SyncCoordinator（本片只定义接口，不执行传输）
```

- View 不直接调用 Supabase 或 GRDB；
- `SupabaseAuthService` 只负责认证会话和 token 生命周期，不负责绑定、合并或本地写入；
- `LocalProfileStore`/Repository 负责 workspace/profile 的读取、候选绑定和授权状态持久化；
- 同步协调器必须以 workspace、cloud user、绑定状态和代次作为任务身份。若当前 schema 尚无 `sync_generation`、checkpoint 或 `baseVersion`，先在实现红灯中固定接口/测试，再由独立迁移切片补字段；
- Outbox 的 `profile_id` 就是 workspace 归属；`operation_id` 是稳定 UUID，`aggregate_kind` 必须支持多域，`aggregate_version` 表示本地操作版本；未确认绑定目标或绑定不匹配时不得上传；
- `pullCursor` 是跨域同步流的 opaque 进度；如果后端改为多域 cursor，必须显式声明 scope；
- `AppState` 保留兼容门面，但不再把 `isSignedIn` 当成同步状态；
- 禁止本片通过增加一个“云端页面”来绕过本地权威。
