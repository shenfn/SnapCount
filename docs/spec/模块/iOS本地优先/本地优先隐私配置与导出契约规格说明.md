# 本地优先隐私配置与导出契约规格说明

> 编号：LOCAL-DATA-002
>
> 更新：2026-11-11
>
> 状态：已拍板，链路已接入，待运行验收

## 1. 决策

App Store 首版以单设备本地优先为准，用户数据链路为：

```text
本地结构化事实
→ 本地 AI 记忆
→ 当前记录 + 同域精简记忆 + Planner 候选（按 Provider 设置发送）
→ AI Companion 陪伴结果
→ 完整本地备份与恢复
```

本版不提供新的云端业务同步能力。已有同步代码保持兼容，但不新增记录、收入或记忆的同步 outbox，不改 Supabase schema、RPC 或多设备冲突协议。

本地化不等于禁止所有 AI 请求。用户仍可使用现有 Hosted 或 BYOK Provider 生成识别和文案。长期记忆开启时，当前事实会与同域、限量的本地记忆摘要一起发送给 Companion Provider；关闭时不读取也不发送本地记忆。Hosted 经芥子服务端转发给模型服务商，BYOK 直接发送给用户配置的服务商。业务事实、记忆投影、Planner 候选和表达状态由本机负责编排和持久化；记忆不进入业务同步 outbox。

## 2. 用户设置契约

| 用户设置 | 首版默认值 | 行为 |
| --- | --- | --- |
| 云端同步 | 新 profile 关闭 | 本版不提供新的同步入口，不启动后台业务同步。已有明确绑定不自动改写。 |
| 云端原图 | 新用户关闭 | 关闭时不长期保留 Supabase Storage 原图；已有用户明确选择保持不变。 |
| AI 陪伴 | 开启 | 生成 Companion；关闭后仍保存结构化事实，不生成新的 Companion。 |
| 长期记忆 | 新账户默认关闭 | 仅在用户开启时读取、更新并发送有界的同域摘要；关闭时不读取、不生成或发送摘要，已有摘要留在本机，重新开启时按当前正式记录重建。 |

继续复用现有字段：

- `companion_enabled`
- `companion_memory_enabled`
- `keep_source_images`
- `image_retention_days`
- `ai_logs_enabled`
- `prompt_optimization_enabled`
- `expression_improvement_enabled`

不新增同义开关。开启 `companion_memory_enabled` 时，本机按当前事实同域提供最多 8 条、每条最多 240 字的摘要给 Companion Provider；关闭时不读取、不写入本地记忆，也不把记忆作为 AI 请求上下文。设置页必须说明 Provider 的传输路径和记忆用途。

## 3. 本地 AI 表达边界

### 3.1 Companion

本地表达上下文包含当前事实、近期事实摘要、有效记忆和 Planner 候选。开启记忆时 Hosted Companion 只接收同域、限量摘要；当前事实优先级最高。记忆只能帮助模型贴合表达角度和语气，不能创造当前事实或已选候选没有的金额、时间、商户、频率或健康结论。服务端只在当前请求内使用摘要，不保存、不写同步队列。

正式记录写入后，异步生成或刷新本地 `companion_message` 与 `ai_feedback`。快捷指令图片识别先只返回识别事实；自动正式入账后，由设备通过只读 Hosted action 单独生成 Companion。待确认记录在用户确认后才生成。Provider 失败时保留事实，并使用确定性反馈降级。

`companion_enabled` 关闭时不生成新的 Companion 或 Planner，但已有表达仍可作为历史数据展示。

### 3.2 Planner 候选域

本地 Planner 覆盖：

- `expense`
- `income`
- `food`
- `sleep`
- `sport`
- `reading`
- `wallet`

Planner 候选必须复用 `NativeAIFeedback` 的事实和渲染契约，至少包含 `candidate_id`、`semantic_key`、`claim_fingerprint`、`presentation_target`、`source = expression_planner`、`dimension`、`band` 和表达文本。

候选规则：

- 带 `local:` 标识的本地 `feedback_card` 候选只参与内部选择，不显示为独立反馈卡；PWA 云端 Planner 行为保持不变；
- `companion_message` 候选必须与可见陪伴语的 claim 一致；
- Planner 不覆盖已经展示的 Voice 事实；
- iOS 本地详情和收件箱只展示陪伴结果，不单独展示本地 Planner 反馈；
- 待确认候选只参与收件箱，不计入正式统计，确认后才进入正式事实范围。

详细的本地表达上下文和 Planner 接入见《本地 AI 陪伴与 Planner 候选域规格说明》。

## 4. 数据保存规则

### 4.1 结构化事实

识别成功并形成正式记录后，数据先写入本机，覆盖消费、收入、食物、睡眠、运动、阅读、钱包和待处理候选。业务记录写入不等待网络或 AI 成功。

### 4.2 本地记忆

本地记忆只保存结构化事实、用户偏好和聚合趋势。不得保存原图、完整 Prompt 或未经处理的模型响应。

记忆更新失败不能使业务事实失败；失败必须允许通过重建投影再次处理。

### 4.3 图片

- 本机识别期间可以暂存原图。
- 云端原图关闭时，不长期保存 Supabase Storage 原图。
- `recognize_only` 默认跳过云端 Storage 上传。
- 结构化事实、记忆和 Planner 候选不得依赖原图存在。

### 4.4 AI 诊断日志

- `ai_logs_enabled` 关闭时，不写 `ai_recognition_logs`。
- `prompt_optimization_enabled` 关闭时，不保存 `raw_response`。
- 原始模型响应不复制到本地业务库。

## 5. 导出与换机

完整备份至少包含：

- 本机结构化事实；
- 本机 AI 记忆；
- 已持久化的 Companion 与 Planner 表达结果；
- 账户、钱包、待处理候选和历史待核对材料；
- 用户隐私设置和记忆开关；
- 用户选择包含的本地图片。

本版不恢复云端登录绑定和同步授权。导入后同步保持关闭，用户需要新的登录会话重新绑定云端账户。

导出包不得包含登录凭据、Supabase 访问令牌、API Key 或临时签名 URL。旧版完整备份仍必须可导入，新增记忆表缺失时按空集合处理。

## 6. 实现顺序

1. 新增 `local-v33-*` 迁移和 `local_companion_memories` 约束。
2. 实现记忆 Repository，并复用 `LocalFactReader` 作为事实来源。
3. 建立本地表达上下文，接入 Companion 和本地 Planner。
4. 为正式记录、财务记录、staging 确认和待确认财务转正式路径统一接线。
5. 将本地详情和收件箱的 Planner 读取从远端依赖中解耦。
6. 将完整备份格式升级到 `29`，加入记忆、表达结果和设置恢复。
7. 运行旧库升级、关闭开关、七域表达、候选渲染和备份恢复回归。

## 7. 明确不做

- 不新增 `record`、`income`、`companion_memory` outbox；
- 不启用本版业务数据同步；
- 不新增生产 Supabase 业务 schema、RPC；本地记忆接线经用户单独授权后，已部署现有 `ingest-receipt` Edge Function v205。默认值迁移仅生成在本地，尚未应用到远端；
- 不实现多设备冲突和远端记忆；
- 不把 `.build/` 构建产物提交；
- 不先做设置页面视觉重构。

## 8. 验收条件

- 新用户云端原图默认关闭，已有设置不被覆盖；
- 七类本地事实均能生成 Companion 或确定性降级；
- iOS 本地详情和收件箱不显示独立本地 Planner 反馈卡；Planner 候选仍可进入 Companion 生成流程，PWA 云端页面不变；
- Planner 不重复覆盖 Voice，不产生无事实依据的表达；
- 关闭 Companion 后事实仍保存且不生成新的 Companion/Planner；关闭记忆后不读写记忆表，也不向 Provider 发送记忆；开启时 Hosted 只收到同域有界摘要；
- 完整备份恢复后事实、记忆、表达、候选、图片和设置保持一致；
- 旧版备份可导入，导出包不含凭据和 API Key。
