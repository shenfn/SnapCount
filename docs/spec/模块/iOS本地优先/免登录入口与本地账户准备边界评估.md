# iOS 免登录入口与本地账户准备边界评估

> 评估编号：LOCAL-002-UI-EVAL
>
> 日期：2026-08-23
>
> 基线：`origin/main@5f72366`
>
> 状态：已评估，待按规格实施

## 1. 结论

当前不能通过删除 `RootView` 的登录判断来实现免登录。应用层已经能在无 Supabase session 时保存本地消费，但 Root、月份读取、记录详情、账户、设置、Inbox 和 Insights 仍包含远端前提。直接放开现有五个 Tab 会得到一个大量页面可见、但操作后持续报缺少 session 的伪免登录版本。

本阶段应建立一个最小本地安全壳：

```text
无云端 session
  -> 本地记录 Tab
  -> 本地设置 Tab
  -> 显式创建本地账户
  -> 仅允许手工消费

已有云端 session
  -> 保持现有五 Tab 云端界面
```

这是 L1 的兼容过渡，不是长期双实现。L2/L3 完成迁移与同步后，已登录用户也应进入同一 Local-First 业务流。

## 2. 当前事实

### 2.1 Root 仍把登录当作应用入口

- `ios/SnapCount/Features/Root/RootView.swift` 在 `isSignedIn == false` 时只展示 `LoginView`。
- 现有 `tabRoot` 同时包含 Today、Inbox、Records、Insights 和 Settings。
- Tab 切换会调用 Dashboard 刷新；虽然 `refreshDashboardIfStale` 对未登录有 guard，但各页面自身仍有远端任务。

### 2.2 本地应用层已存在，但启动只准备 profile

- `AppState.bootstrap()` 会调用 `localExpenseUseCase.prepareProfile()`，不会读取本地账户和当前月份。
- `createManualRecord` 已在“未登录 + expense”时走 `LocalExpenseUseCase`。
- 本地创建成功后只刷新当前内存中的月份投影；应用重启后记录不会自动回到 Records 页面。

### 2.3 Records 仍混有远端读取和详情假设

- `loadRecordMonth` 对历史月份调用远端 `RecordRepository`；当前月份强制刷新调用远端 Dashboard。
- Records 行统一导航到 `RecordDetailView`，并统一预取远端详情。
- Records 的“账户”入口指向现有云端 `AccountsView`，“数据域”尚未本地化。
- 本地引用虽使用 `local-expense/<uuid>` 命名空间，但本阶段没有本地详情 UI。

### 2.4 手工表单允许本地路径无法兑现的操作

- `ManualRecordSheet` 会加载云端账户和财务词表。
- 表单允许 expense、income 和 universal；本地应用层当前只支持 expense。
- UI 允许“暂不绑定账户”，但本地消费表和 Use Case 要求一个属于当前 profile 的账户 UUID。
- 没有账户时，用户只能在保存后得到 `invalidIdentifier`，没有可操作出口。

### 2.5 账户数据库能力已具备，缺的是应用层和 UI

- `LocalExpenseRepository` 已支持 `createAccount`、`accounts(profileID:)` 和派生余额。
- `local_accounts` 当前只保存名称、类型、币种、期初余额和创建时间，没有默认账户字段。
- 因此本阶段不能伪造“默认账户”语义，也不应静默创建账户。

### 2.6 现有 Accounts 和 Settings 不能直接复用为本地页面

- `AccountsView` 的列表、详情、创建、归档和还款全部连接云端账户 Repository/RPC。
- `SettingsView` 启动即加载云端设置，并展示云端导出、AI、快捷指令、云端账户删除和退出登录。
- 未登录本地模式需要独立的安全投影，不能靠大量失败提示降级。

## 3. 产品边界

### 3.1 本地安全壳

未登录用户首次启动直接进入 Records，不展示注册登录墙。只开放：

- 本地消费记录列表和月份切换；
- 手工新增消费；
- 最小本地账户列表与创建；
- 本地设置中的存储说明、外观、法律文档和版本信息。

Today、Inbox、Insights、云端数据域、截图上传、AI、快捷指令、云端导出、云端账户删除和远端详情在本地模式隐藏，而不是展示后报错。

### 3.2 显式账户准备

首次新增消费且没有本地账户时，先展示账户准备表单。用户明确填写：

- 账户名称；
- 账户类型：现金、钱包余额、储蓄卡；
- 期初余额，允许 0，首片不允许负数；
- 币种固定 CNY。

创建成功后只为当前消费草稿选中新账户，不把“第一个账户”写成跨会话默认规则。默认账户需要独立字段、迁移和规格后再实现。

### 3.3 登录与同步

L1 的本地设置不提供普通登录入口。原因不是拒绝登录，而是同步尚未实现：此时登录会切到旧云端界面，使本地记录从当前 UI 消失，容易被误解为数据丢失。

登录入口应在 L3 的“开启云同步”流程中出现，并同时说明绑定、上传范围、冲突和关闭同步后的行为。已有 session 的旧用户继续使用现有云端界面，避免 L1 破坏当前生产用户。

## 4. 依赖方向

```text
RootView
  -> 本地安全壳 / 现有云端壳

本地 Records / 本地账户准备
  -> AppState 兼容门面
       -> LocalExpenseUseCaseProtocol
            -> LocalExpenseRepositoryProtocol
                 -> LocalDatabase
```

- View 不直接访问 GRDB 或 Local Repository。
- AppState 不创建账户行、不解析金额、不计算余额。
- 本地账户投影可复用 `NativeAccount` 作为 UI DTO，但映射必须集中在 mapper，不得让云端账户语义反向进入本地数据库。
- 本地模式的读取、表单准备和保存不得调用 Supabase Auth、HTTP、RPC、Storage 或云端 Repository。

## 5. 实施切片

### LOCAL-002-UIA：本地安全壳与读取

1. 显式区分本地安全壳和现有云端壳。
2. 未登录默认选中 Records，只展示 Records 与本地 Settings。
3. 启动、下拉刷新和月份切换读取本地消费。
4. 本地记录行不进入远端详情，不触发远端预取。
5. 已登录旧用户的五 Tab、导航和远端加载保持不变。

### LOCAL-002-UIB：账户准备与新增消费

1. Use Case 暴露当前 profile 的账户查询和显式账户创建命令。
2. 没有账户时，新增消费先进入账户准备。
3. 本地表单只显示消费，不加载云端词表，不允许无账户保存。
4. 创建账户和保存消费均以本地事务成功为 UI 成功，不等待网络或 AI。

## 6. 风险与非目标

- 本阶段不实现本地记录详情、编辑、删除 UI；底层 DB2 能力继续保留。
- 不实现收入、数据域、图片、AI、BYOK、同步、现有云端用户迁移或 TestFlight。
- 不把 `isSignedIn` 当作长期数据模式；它只用于 L1 保护旧云端用户。
- 不静默创建“现金”账户，不新增未经规格定义的默认账户字段。
- 不复用云端账户管理 RPC 来写本地账户。

## 7. 验证建议

- Node 源边界：本地 Root 不暴露云端 Tab；本地表单不加载远端词表；本地引用不进入远端详情。
- XCTest：无 session 启动、本地月份读取、账户创建、当前草稿选中、无账户拒绝保存、network spy 为 0、退出登录后本地事实仍可恢复。
- 回归：现有登录用户 Root、五 Tab、云端账户和完整 XCTest 不变。
- 最终证据：GitHub macOS Simulator Build、完整 `SnapCountTests`、治理和架构门禁。
