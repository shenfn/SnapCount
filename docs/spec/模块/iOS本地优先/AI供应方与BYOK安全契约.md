# AI 供应方与 BYOK 安全契约

> 规格编号：LOCAL-AI-001
>
> 状态：提议，L4 实现前置契约

## 1. 能力模型

图片识别与表达生成使用独立接口，避免把不同隐私和失败语义混为一体：

```text
VisionProvider: Disabled / Hosted / BYOK
ExpressionProvider: Disabled / Hosted / BYOK
```

业务 Use Case 只依赖结构化输入输出，不感知 OpenAI、Gemini、Qwen 或其他供应商名称。

## 2. 数据发送原则

### LOCAL-AI-001：默认关闭不外发

用户未开启 AI 时，不上传图片、OCR 文本、记录历史或个人上下文。

### LOCAL-AI-002：最小必要数据

启用 AI 时只发送完成当前任务所需的数据。默认不发送完整历史、账户余额、无关数据域或整份个人上下文。

### LOCAL-AI-003：发送前可解释

设置页必须说明请求发送给谁、是否经过项目服务器、会发送哪类数据、结果保存在哪里。高敏感数据首次发送前应有明确确认。

## 3. BYOK

### LOCAL-AI-004：Key 存储

用户 API Key 只存 iOS Keychain。Key 不进入本地业务数据库、Supabase、日志、分析、崩溃报告、导出包或剪贴板持久记录。

### LOCAL-AI-005：直连边界

只有供应商 SDK/API 支持客户端安全调用，且隐私和审核条件经验证后，才能声明 BYOK 请求不经过项目服务器。否则必须明确提示需要中转，不能使用误导性文案。

### LOCAL-AI-006：撤销与失败

用户可随时删除 Key。Key 无效、额度不足、供应商超时或拒绝时，本地记录不回滚，并提供手动录入或稍后重试出口。

## 4. Hosted AI

- 项目 Key 只存在服务端安全环境，不进入 App 包。
- Hosted AI 可要求登录、订阅或额度，但这些权限判断不改变本地数据模型。
- 服务端默认不持久化原始请求和模型响应；若为诊断需要留存，必须脱敏、可关闭、有限期限并明确披露。

## 5. App Store 审核

- 核心手动记录和本地查看不得依赖审核员自备 API Key。
- 提供不含真实隐私数据的内置 Demo/Mock 路径。
- 如需展示 Hosted AI，提供审核专用账号和有限额度，Key 仍只保存在服务端。
- 审核说明准确区分本地数据、云同步、Hosted AI 和 BYOK 的网络路径。

## 6. 验证

- Keychain 读写、删除和用户切换 XCTest。
- 网络拦截测试证明 BYOK 不访问项目 Edge，Hosted 不泄露服务端 Key。
- 日志和崩溃报告扫描不包含 Key、图片正文或完整 prompt。
- Disabled 模式下 AI 网络请求计数为零。
- 使用冻结 Stub 验证事实契约，不把某句生成文案固定为唯一正确答案。
