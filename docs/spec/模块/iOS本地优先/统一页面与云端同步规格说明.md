# iOS 统一页面与云端同步规格说明

> 规格编号：LOCAL-003
>
> 状态：提议，进入规格评审
>
> 上游：`LOCAL-DATA-001`、`LOCAL-002`、`ADR-036`、`ADR-038`

## 1. 目标

将 L1 的“本地安全壳 / 旧云端壳”过渡实现收敛为一套业务页面和一套本地事实来源：

- 未登录用户可以使用核心记录能力；
- 已登录用户仍能访问原有云端数据；
- 登录不会把页面切换成另一套业务 UI；
- 本地新增、编辑、删除始终先写入本机数据库，不等待网络；
- 云端只作为用户主动开启后的同步副本和需要身份的托管能力；
- 同步失败、鉴权失败或 AI 失败不能撤销已成功的本地事实。

## 2. 非目标

本规格不直接完成以下事项：

- 不在本片迁移收入、运动、睡眠、饮食、阅读等其他数据域；
- 不实现完整的多设备冲突自动合并；
- 不把 PWA 改造成离线或本地数据库客户端；
- 不新增 Apple 登录、手机号登录或第三方身份提供商；
- 不改变 Supabase 表、RPC、Edge Function 或生产部署；
- 不在本片决定 Hosted AI 的额度和商业套餐；
- 不把图片、原图或 AI 上下文默认上传到云端。

## 3. 核心模型

### 3.1 页面与数据权威分离

页面不根据登录状态选择两套业务树。所有业务页面通过同一组 Use Case 读取本地 Repository：

```text
统一 App Shell
  -> Feature / Use Case
    -> Local Repository（GRDB，本机事实）
      -> Sync Coordinator（可选）
        -> Remote Repository（Supabase 副本）
```

`isSignedIn` 只表示当前是否有云端身份，不再决定 Records、账户或详情页面是否存在。页面可见能力由本地数据域和同步/AI 能力状态决定。

### 3.2 三个正交维度

| 维度 | 值 | 说明 |
|---|---|---|
| 数据事实 | `localDatabase` | 当前设备即时可见事实，所有本地写入首先落在此处 |
| 云端身份 | `signedOut` / `signedIn` | 是否拥有云端用户身份，不改变本地页面 |
| 同步状态 | `disabled` / `ready` / `syncing` / `synced` / `failed` / `conflict` | 是否已授权、正在同步或需要处理异常 |

AI Provider 另行建模，不进入页面数据 Repository 分支。

### 3.3 同步状态机

```text
disabled
  --用户打开云同步并登录--> ready
ready --开始同步--> syncing
syncing --本轮全部成功--> synced
syncing --网络/鉴权失败--> failed
syncing --发现不可自动解决差异--> conflict
failed --用户重试且条件满足--> syncing
conflict --用户完成处理--> ready
signedOut --退出账号--> disabled
```

状态迁移要求：

- `disabled` 不读取或写入远端业务数据；
- `signedIn` 不等于 `syncEnabled`，登录后必须由用户确认开启同步；
- `failed` 和 `conflict` 不回滚本地已提交事务；
- 退出登录会停止该账号的同步任务，但保留本地数据；
- 任何旧账号任务完成后都必须检查 profile、cloud user 和同步代次，过期结果不得写回。

## 4. 页面契约

### 4.1 统一 App Shell

统一页面至少包含：

- Today：由本地读模型提供；云端字段未同步时显示真实空状态或“尚未同步”，不直接发起远端读取；
- Inbox：本地中转记录和待处理状态由本地模型提供；未迁移的云端中转能力在同步规格明确前保持不可见；
- Records：本地消费、收入和其他已迁移域使用同一列表、筛选、月份和详情入口；
- Insights：只展示本地已有或已同步的读模型，不因未登录而切换成另一套页面；
- Settings：统一展示本机存储、云端身份、同步状态、AI Provider、隐私和导出。

首个实现切片只要求 `Records + accounts + expense detail` 使用统一本地页面；其他 Tab 可在数据域尚未迁移时显示明确空状态，但不得回退到第二套业务 Repository。

### 4.2 本地保存

统一页面的新增、编辑、删除行为必须：

1. 在一个本地数据库事务中写入业务事实、账户流水和必要 Outbox；
2. 事务成功后立即更新页面；
3. 网络不可用时仍然成功；
4. 同步失败时显示待同步或失败状态，不把本地记录标为失败；
5. 账户余额由期初余额和有效流水确定性派生，不同步覆盖 `current_balance`。

### 4.3 本地与云端数据共存

用户登录已有账号时，页面不切换到旧云端壳。若当前 profile 存在本地数据，必须先展示绑定预览：

- 本地 profile 标识；
- 待上传的记录和账户数量；
- 云端将被读取的范围；
- 图片/AI 数据默认不上传的说明；
- 合并、仅下载云端或暂不启用同步的出口。

在用户确认前，不上传本地业务数据，不改变 `sync_enabled`。

## 5. 绑定与首次同步

### 5.1 登录不是绑定

登录只建立 `cloud_user_id` 会话。只有用户在同步确认页明确同意后，才执行 profile 绑定和首次同步。

### 5.2 首次同步策略

第一版采用可回滚的“本地先合并、远端幂等写入”策略：

- 本地记录保留原稳定 UUID；
- 云端记录映射为本地记录，并保存 `remote_id` / 同步游标；
- 相同稳定 ID 视为同一事实；
- 仅本地存在的记录进入 Outbox；
- 仅云端存在的记录写入本地；
- 同一记录两边都被修改时不静默覆盖，进入 `conflict`；
- 账户余额、流水和还款按操作顺序同步，禁止直接覆盖余额快照；
- 首次同步失败可重试或撤销绑定，不删除本地数据。

### 5.3 用户出口

绑定流程必须提供：

- `暂不开启同步`：保留本地模式；
- `仅下载云端数据`：只读导入，暂不上传本地数据；
- `合并并开启同步`：执行双向同步；
- `退出当前账号`：停止同步并回到统一页面的本地数据。

## 6. 数据模型增量

现有本地表继续作为基础，不复制云端表结构。LOCAL-003 只增加同步所需的最小元数据：

### `local_profiles`

- `cloud_user_id`：绑定后的云端用户 ID，可空；
- `sync_enabled`：用户是否明确开启同步；
- `sync_generation`：每次绑定、退出或重置时递增，阻止过期任务回写；
- `last_sync_cursor`：云端增量游标，可空。

### 本地业务实体

后续迁移的 `local_expenses`、`local_accounts` 和其他域至少需要：

- 稳定本地 UUID；
- `local_version`；
- `updated_at`；
- 删除 tombstone；
- 可空的远端映射 ID；
- 来源设备标识或等价同步元数据。

### `local_outbox_operations`

现有 `pending / processing / failed / sent` 状态继续保留；同步协调器必须以 `sequence` 顺序处理同一 profile 的操作，并以 `idempotency_key` 防止重复写入。

## 9. 完成定义

LOCAL-003 不得以“登录按钮出现”作为完成标准，必须同时满足：

- 未登录和已登录看到同一套核心页面；
- 本地保存、编辑、删除、重启和断网均可用；
- 登录、退出和账号切换不丢失、不混入本地数据；
- 首次同步前有范围预览和用户确认；
- 重复同步、重复导入和重试不会产生重复事实；
- 账户流水顺序和余额派生不漂移；
- 同步失败、冲突、低存储和迁移失败都有可见出口；
- 网络闸门、macOS XCTest、iOS Build、治理和架构门禁全部通过。
