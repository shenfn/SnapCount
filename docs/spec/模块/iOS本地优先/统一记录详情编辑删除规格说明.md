# LOCAL-003B 统一记录详情、编辑、删除规格说明

> 状态：规格草案，待评审
>
> 上游：`LOCAL-003`、`LOCAL-003A`、`ADR-039`

## 1. 目标

补齐 LOCAL-003A 统一页面中 `expense + accounts` 的本地详情、编辑、删除和余额投影，使本地记录不因点击详情或执行修改而回到云端专属路径。

本片只处理已经存在于 GRDB 的本地消费和本地账户，不实现首次绑定或双向同步。

## 2. 范围

### 包含

- `local-expense/<stable-uuid>` 记录引用的详情读取和展示；
- 本地消费详情的编辑，包含金额、商户、平台、分类、支付方式、日期、备注和账户；
- 本地消费删除确认、业务事实删除、账户流水级联和 tombstone/outbox 保留；
- 本地账户列表、余额和流水从本地 Repository 读取；
- 编辑、删除成功后列表、详情和余额立即从本地读模型刷新；
- 登录状态不改变上述页面和本地写入语义。

### 不包含

- 首次绑定、云端导入、Outbox 上传、冲突合并和同步状态机；
- 收入、运动、睡眠、饮食、阅读等其他域的本地迁移；
- 云端记录的编辑删除规则改变；
- 账户类型迁移、还款编排、钱包快照和云端余额覆盖；
- 图片签名、AI 陪伴和表达反馈在本地离线运行。

## 3. 事实来源和边界

```text
RecordDetailView / AccountsView
  -> AppState unified detail/edit/delete facade
    -> LocalExpenseUseCase
      -> LocalExpenseRepository (GRDB transaction)
        -> local_expenses / local_accounts / local_account_entries / outbox / tombstone
```

- 引用以 `local-expense/<UUID>` 作为稳定本地标识；不能把本地 UUID 当作 Supabase 记录 ID 查询远端。
- 本地详情必须由本地事实构造 `NativeRecordDetail` 或等价展示模型，字段缺失时显示明确的本地空值，不发起远端请求。
- 云端 `expense/<id>` 仍走现有远端 Repository；统一门面根据引用类型选择本地或远端 Use Case，页面不能按 `isSignedIn` 分支。
- 本地账户余额只能由期初余额与未作废账户流水派生；编辑金额/账户必须在同一事务中重建受影响流水。

## 5. 状态和失败出口

- 保存/删除开始后禁止同一实体的并发重复提交；使用现有 busy 状态或等价 Use Case 状态。
- GRDB 事务失败时不得更新内存读模型，不得显示“已保存/已删除”。
- 读模型刷新失败与事务成功分开表达：事实已写入但刷新失败时，页面显示事实已保存并提供重新加载，不重复写入。
- 版本冲突、找不到本地记录、账户不存在和金额非法必须分别映射为稳定的用户可见错误。
- 退出登录不清除本地 profile、账户、消费、流水或 tombstone。
