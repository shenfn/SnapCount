# iOS 本地优先数据生命周期规格说明

> 规格编号：LOCAL-DATA-001
>
> 状态：提议，L0 基线

## 1. 范围

本文定义 iOS 本地身份、业务写入、同步、删除、导出、恢复和既有用户迁移的不变量。具体数据库 API 和表结构由后续切片决定。

## 2. 权威模型

- 未开启同步：本地数据库是业务事实的唯一持久来源。
- 开启同步：本地数据库是当前设备即时事实；同步协议协调多设备变化；Supabase 保存用户授权同步的副本。
- PWA 只读取云端副本，不读取 iOS 设备本地数据。
- 派生数据可以重建，不得覆盖其原始事实或操作日志。

## 3. 身份生命周期

### LOCAL-DATA-001：免登录首次启动

首次启动创建仅存在设备上的本地 profile。创建失败时显示可恢复错误，不静默创建 Supabase 匿名用户，也不上传业务数据。

### LOCAL-DATA-002：登录并开启同步

登录本身不自动上传全部本地数据。用户明确开启同步后，应用展示同步范围和影响，再将本地 profile 与云端用户绑定。

### LOCAL-DATA-003：退出登录

退出云端账号不自动删除本地数据。应用必须说明本地记录是否继续保留，并阻止旧账号的同步任务继续执行。

## 4. 写入与失败

### LOCAL-DATA-004：本地原子写入

新增、编辑或删除业务事实必须在本地事务中同时写入业务记录和必要的 outbox 操作。任一失败则事务整体失败，界面不得展示为已保存。

### LOCAL-DATA-005：同步失败隔离

网络、鉴权或云端冲突失败不撤销已成功的本地记录。失败必须进入可见的待同步状态，并提供重试或停止同步出口。

### LOCAL-DATA-006：AI 失败隔离

AI 不可用、Key 失效或用户关闭 AI 时，手动记录、本地保存、查看、编辑、删除和导出仍然可用。

## 5. 删除、导出与恢复

### LOCAL-DATA-007：删除语义

未同步记录可本地删除；已同步记录必须产生 tombstone 或等价删除操作，防止其他设备重新拉回。永久清除前必须有确认门禁。

### LOCAL-DATA-008：导出

导出包含版本、稳定 ID、业务事实和必要关系，不包含 API Key、认证 token、临时签名 URL、诊断日志和不可迁移缓存。

### LOCAL-DATA-009：导入

导入必须校验格式和版本；重复导入同一稳定 ID 不得产生重复记录。失败不能破坏导入前已有数据。

## 6. 既有云端用户迁移

### LOCAL-DATA-010：首次本地化

已登录老用户升级时，先只读拉取云端事实，写入本地数据库并建立同步基线。过程必须可断点续传，可识别已迁移记录，不静默修改账户余额。

### LOCAL-DATA-011：回滚

迁移未完成时保留当前云端读取路径作为受控回滚能力。只有迁移验证完成后，才允许本地 Repository 成为默认读取路径。

## 7. 同步最小契约

每条可同步实体至少具备：稳定 UUID、owner、版本或变化序号、创建/更新时间、删除标记、来源设备和幂等键。具体冲突策略必须在 L3 独立 Spec 中定义。

账户、流水和还款属于高风险实体：同步操作必须保留可审计顺序和幂等语义，不允许简单覆盖余额字段。

## 8. 完成定义

- 所有适用场景有脱敏 fixture 和自动测试映射。
- 断网、重启、低存储、迁移失败、重复导入和重复同步均有失败出口。
- 本地模式网络测试证明没有业务数据写入 Supabase。
- 未经用户明确开启，不发生业务数据云同步。
