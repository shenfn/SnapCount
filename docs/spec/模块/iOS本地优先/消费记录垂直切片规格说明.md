# iOS 消费记录本地优先垂直切片规格说明

> 规格编号：LOCAL-002
>
> 状态：LOCAL-002 首批数据库红灯进行中

## 1. 目标

用消费记录验证完整 Local-First 生命周期，而不是先迁移所有数据域。首片必须证明免登录、本地事务、重启恢复、导出导入和网络闸门可用。

## 2. 范围

包括：

- 本地 profile；
- 消费记录的新增、读取、编辑和删除；
- 一个支持消费归属的最小本地账户；
- 本地事务和 outbox 数据结构；
- JSON 版本化导出与导入；
- 本地/待同步状态展示；
- 后续云同步接线所需的稳定 ID。

不包括：

- 图片识别、Hosted AI 和 BYOK；
- 收入及其他生活数据域；
- 多设备自动冲突合并；
- PWA 本地数据库；
- 生产数据迁移和发布。

## 3. 场景矩阵

| 场景 | 行为不变量 | 首选验证层 |
|---|---|---|
| LOCAL-002A 免登录创建 | 不访问 Supabase 即可保存并立即展示 | Repository/Use Case XCTest + 网络 Stub |
| LOCAL-002B 重启恢复 | 进程重启后记录和账户关系保持 | 数据库集成 XCTest |
| LOCAL-002C 编辑 | 业务记录与 outbox 在同一事务提交 | 数据库事务测试 |
| LOCAL-002D 删除 | 本地删除可恢复；已同步状态预留 tombstone | Repository 测试 |
| LOCAL-002E 导出 | 版本、稳定 ID 和关系完整；不含凭据 | Fixture 测试 |
| LOCAL-002F 导入 | 重复导入不重复；失败不污染旧数据 | 数据库集成测试 |
| LOCAL-002G 断网 | 新增、编辑、删除和查看不依赖网络 | Use Case XCTest |
| LOCAL-002H AI 关闭 | 手动消费链路完整可用 | AppState/Use Case XCTest |
| LOCAL-002I 用户切换 | 云端 session 变化不串用本地 profile | AppState XCTest |
| LOCAL-002J 余额派生 | 消费影响来自本地流水/操作，不直接覆盖余额 | 领域纯逻辑 + 数据库测试 |

## 4. 依赖方向

```text
SwiftUI View
  -> AppState
  -> Expense Use Case
  -> Expense Repository Protocol
  -> Local Repository
  -> Local Database
```

Supabase、HTTP、Keychain 和具体数据库框架不得进入 Domain Model。Sync Engine 不由页面直接调用。

## 5. 红灯顺序

1. 本地数据库重启后不能恢复记录。
2. 业务写入成功但 outbox 缺失或反之。
3. 重复导入产生第二条记录。
4. 本地模式仍触发 Supabase 业务请求。
5. 消费记录通过直接余额覆盖而不是可审计流水影响账户。
