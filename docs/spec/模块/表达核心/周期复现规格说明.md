## 1. 目标

将同名记录的上一次间隔候选迁入生产拥有的纯函数目录：

```text
supabase/functions/_shared/expression-core/recurrence-candidates.mjs
```

Planner Lab 保留原导入路径作为兼容 wrapper，Edge 生产入口直接依赖 `_shared`。本切片只迁移周期复现候选，不迁移 comparison、cross-record、generic-domain 或实体配置。

## 2. 场景与不变量

| 场景 | 固定不变量 | 测试层 |
|---|---|---|
| CORE-031 | 只选择当前记录之前、同 normalized name 且 `count_in_facts=true` 的最近独立记录 | Node + Deno 共享 fixture |
| CORE-032 | `known_at` 晚于当前记录的历史记录不能作为因果上的 previous | Node + Deno 共享 fixture |
| CORE-033 | 两端都有精确时间时输出分钟级间隔和可审计 duration | Node + Deno 共享 fixture |
| CORE-034 | 任一端为 date-only 时降级为本地日间隔，不制造分钟事实 | Node + Deno 共享 fixture |
| CORE-035 | 同一天 date-only 或非正间隔返回空数组 | Node + Deno 共享 fixture |
| CORE-036 | 同 observation_group 或完全相同精确观测会被排除，但仍可回溯更早独立记录 | Node + Deno 共享 fixture |
| CORE-037 | pending/不计入事实的记录不能成为 previous | Node + Deno 共享 fixture |

| CORE-039 | Planner Lab wrapper 与生产核心公开 API 为同一导出绑定，生产 `tools/` 依赖减少 1 条 | 兼容测试 + 架构 ratchet |

## 3. 输入输出契约

- 输入是已完成事实契约和商户归一化的事件；本模块不读取数据库、不加载别名配置、不猜测实体。
- 同名依据为 `merchant.normalized_key` 精确相等，不使用展示名模糊匹配。
- 因果顺序由 `known_at` 约束；当前 `known_at` 缺失时不阻断历史候选，历史必须早于当前已知时间。
- 精确时间只在两端 `event_time_precision` 属于 `minute`、`second` 或 `exact` 时使用；否则使用 `transaction_date` 或上海时区本地日期。
- 输出候选继续使用 `candidate-v0.1`，证据必须包含当前和 previous 两条来源，数字字段必须可审计。

## 4. 非目标

- 不迁移 comparison、category comparison、cross-record、generic-domain 候选或实体别名配置。
- 不调整事实契约、资格门、评分、选择或 render contract 的规则。
- 不修改 Prompt、数据库、PWA、iOS、迁移或生产部署。

## 5. 纯函数与依赖约束

- 生产实现零 IO、零 Supabase/HTTP 依赖，只依赖生产核心已有的 `parseFiniteNumber`。
- Planner Lab 原路径只 re-export wrapper，不保留第二份周期复现实现。
- Node 与 Deno 对同一 fixture 的结构化结果一致。
