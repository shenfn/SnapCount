## 1. 目标

将支出记录事实、日聚合事实和商户首次出现候选迁入生产拥有的纯函数目录：

```text
supabase/functions/_shared/expression-core/fact-candidates.mjs
```

Planner Lab 保留原导入路径作为兼容 wrapper，Edge 生产入口直接依赖 `_shared`。本切片只迁移候选构造，不迁移实体别名解析、周期候选或比较候选。

## 2. 场景与不变量

| 场景 | 固定不变量 | 测试层 |
|---|---|---|
| CORE-024 | 日聚合只使用 `count_in_facts` 且金额有限的事件，按上海时区过滤日期，明确保留金额 0 | Node + Deno 共享 fixture |
| CORE-025 | 当前记录候选保留待确认状态、分类待确认标志和允许 surface，不进入日聚合 | Node + Deno 共享 fixture |
| CORE-026 | 已确认且有分类的当前记录不生成“分类仍待确认”提示 | Node + Deno 共享 fixture |
| CORE-027 | 商户首次出现候选以 entity 首次观察为依据，输出稳定证据、编号和曝光 key | Node + Deno 共享 fixture |
| CORE-028 | 已有实体的新别名不被误判为新的用户事件 | Node + Deno 共享 fixture |
| CORE-029 | 缺少事件 ID、有限金额或首次观察时，候选生成返回空数组，不制造事实 | Node + Deno 共享 fixture |
| CORE-030 | Planner Lab wrapper 与生产核心公开 API 为同一导出绑定，生产 `tools/` 依赖减少 1 条 | 兼容测试 + 架构 ratchet |

## 3. 输入输出契约

- 输入是已经完成事实契约和商户归一化的结构化事件；本模块不读取数据库、不加载别名配置、不猜测实体。
- `generateCurrentExpenseRecordCandidate` 输出 `expense_current_record_context`，保留金额、时间、分类、账户无关事实和待确认状态。
- `generateFactCandidates` 输出日计数和金额结构两个聚合候选，事件按本地日期和 `count_in_facts` 过滤。
- `generateMerchantFirstOccurrenceCandidate` 只接受 `entity_first_seen=true`，别名首次出现不能单独产生用户候选。
- 输出候选继续使用 `candidate-v0.1`，证据和 numbers 必须可审计，不能包含模型文案以外的隐含事实。

## 4. 非目标

- 不迁移 recurrence、comparison、cross-record、generic-domain 候选或实体别名配置。
- 不调整事实契约、资格门、评分、选择或 render contract 的规则。
- 不修改 Prompt、数据库、PWA、iOS、迁移或生产部署。

## 5. 纯函数与依赖约束

- 生产实现零 IO、零 Supabase/HTTP 依赖，只依赖生产核心的数值和金额函数。
- Planner Lab 原路径只 re-export 生产核心，不保留第二份事实候选实现。
- Node 与 Deno 对同一 fixture 的结构化候选结果一致。

## 6. 迁移顺序

1. 写共享 fixture、跨运行时断言器、wrapper 兼容测试和生产核心测试，先证明目标模块缺失的红灯。
2. 将现有纯函数实现迁入 `_shared/expression-core/fact-candidates.mjs`。
3. 将 Lab 文件改为 re-export wrapper，Edge 入口切换到 `_shared`。
4. 运行事实候选、核心回归、资格/评分/选择、完整 Planner、Edge 检查和架构 ratchet。
5. 更新执行记录、阶段索引和交接快照；CI 通过后再评估 recurrence 或 comparison。
