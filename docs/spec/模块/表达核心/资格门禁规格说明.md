## 1. 目标

将候选硬性事实门禁、商户活跃日实质性判断、surface 资格阈值和周期候选路由迁入生产拥有的纯函数目录：

```text
supabase/functions/_shared/expression-core/eligibility-gates.mjs
```

Planner Lab 保留原导入路径作为兼容 wrapper，Edge 生产入口直接依赖 `_shared`。本切片只改变规则归属和依赖方向，不改变候选的 `eligibility` 输出。

## 2. 场景与不变量

| 场景 | 固定不变量 | 测试层 |
|---|---|---|
| CORE-013 | 缺少语义键、结构值、证据、数值推导、置信度或覆盖率时，候选在 claim 和所有 surface 上均不可用，拒绝原因保持可审计 | Node + Deno 共享 fixture |
| CORE-014 | 商户活跃日对比只从 current/baseline 源指标重新计算实质性，不信任冗余 delta；金额边界按分处理 | Node + Deno 共享 fixture + Planner 回归 |
| CORE-015 | diagnostic 时间窗和同名记录间隔维持既有 surface 限制，不因迁移变成可打扰通知或周报 | Node + Deno 共享 fixture |
| CORE-016 | 周期候选只进入允许的 summary surface；record-event 上下文不得伪装成周期报告，非 period owner 不得占用周报 | Node + Deno 共享 fixture |
| CORE-017 | Planner Lab wrapper 与生产核心公开 API 为同一导出绑定，生产 `tools/` 依赖减少 1 条 | 兼容测试 + 架构 ratchet |

## 3. 输入输出契约

### 3.1 输入

- 候选必须是已生成的结构化对象；本模块不生成、补写或推断候选事实。
- `planningContext` 默认保持 `surface_preview`；Edge record-event 编排显式传入 `record_event`。
- surface 集合和置信度、覆盖率阈值保持现有四类配置。

### 3.2 输出

- `evaluateCandidateEligibility` 保留原候选字段，并只新增或覆盖 `eligibility`。
- `eligibility.eligible` 只表示 claim 级硬门禁，不因某个 surface 不可用而变为 false。
- `materiality` 只对 `merchant_daily_vs_active_day_median` 计算。
- `surface_eligibility` 必须包含四个 surface，每项保留 `eligible` 和去重后的 `blocked_reasons`。
- `summarizeEligibility` 继续分别统计 claim 和各 surface 的可用数量。

## 4. 非目标

- 不迁移或修改确定性评分、候选生成、候选选择、render contract、实体别名配置。
- 不调整阈值、实质性策略版本、拒绝原因名称或 planning context。
- 不修改 PWA、iOS、Prompt、数据库迁移、生产部署或模型行为。
- 不把资格门与评分合并；评分继续消费资格门的结构化结果。

## 5. 纯函数与依赖约束

- 生产实现零 IO、零环境 API、零 Supabase/HTTP 依赖，不读取 `tools/` 或配置文件。
- Planner Lab 原路径只 re-export 生产核心，不保留第二份规则。
- 共享 fixture 只使用虚构候选、金额、时间和标识，不包含真实用户数据或模型文案。
- Node 与 Deno 对同一 fixture 的结构化结果一致。

## 6. 迁移顺序

1. 写共享 fixture、跨运行时断言器和生产核心测试，证明目标模块缺失的红灯。
2. 将现有纯函数实现原样迁入 `_shared/expression-core/eligibility-gates.mjs`。
3. 将 Lab 文件改为 re-export wrapper，Edge 入口切换为 `_shared` 导入。
4. 运行新增测试、旧资格门回归、兼容测试、Planner 回归和架构检查。
5. 更新执行记录、阶段索引和交接快照；CI 通过后再评估评分模块。
