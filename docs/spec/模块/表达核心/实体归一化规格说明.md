# 表达核心实体归一化规格说明

> 模块编号：CORE-009
>
> 状态：规格已建立，待实现

## 1. 目标

将商户实体归一化与历史名称变体判定的确定性规则迁入生产共享核心，并让 Edge、Planner Lab 和 fallback 使用同一份生产规则与公开配置。

## 2. 范围

- 迁移 `compileMerchantAliases`、`resolveMerchant`、`summarizeMerchantObservation`；
- 继续从 `expression-core/index.mjs` 引用 `normalizeEntityText`；
- 将公开别名 JSON 放入生产共享配置目录，保持版本和 schema；
- Lab 原导入路径保留 wrapper；
- Edge 直接引用生产核心和生产共享配置；
- 用同一份 fixture 验证 Node 与 Deno。

## 3. 非目标

- 不修改 `normalizeEntityText` 的 NFKC、大小写、空白和标点规则；
- 不联网、不读取数据库、不自动写入永久别名、不改变用户记录；
- 不放宽行政前缀、法律尾缀或歧义匹配规则；
- 不迁移候选生成、评分、选择、比较、跨记录关系或 render contract；
- 不把公开配置和纯函数实现合并成“核心自动读配置”。

## 4. 行为场景

| 编号 | 行为不变量 | 测试层 |
|---|---|---|
| CORE-056 | NFKC、空白、大小写和标点归一结果保持 CORE-001 行为 | Node/Deno fixture |
| CORE-057 | 配置 canonical name 和 alias 映射到同一 entity，保留 raw_name | Node/Deno fixture |
| CORE-058 | 无配置匹配时生成稳定的 normalized fallback，不伪造确认实体 | Node/Deno fixture |
| CORE-059 | 唯一行政前缀/法律尾缀变体归入历史实体并标记高置信依据 | Node/Deno fixture |
| CORE-060 | 多个历史实体都匹配时返回歧义，不合并任一实体统计 | Node/Deno fixture |
| CORE-061 | 非行政营销前缀不触发历史实体合并，保留真正首次状态 | Node/Deno fixture |
| CORE-062 | Lab wrapper 与生产核心导出保持同一函数引用，Edge 不再引用 `tools` 规则或配置 | Wrapper + 静态契约 |

## 5. 完成定义

1. 生产核心文件只包含纯函数，边界检查通过。
2. 生产共享配置存在且 Edge/Lab 使用同一版本结构。
3. 目标文件缺失时共享 Node runner 有效红灯，最小迁移后转绿。
4. Node/Deno fixture、旧 7 项实体测试、完整 Planner 和 Edge 静态契约通过。
5. 生产对 `tools/` 的规则与配置反向依赖均被移除，且没有新增反向依赖。
6. 阶段索引、ADR、执行记录和交接快照更新，环境失败与未验证项单独列出。
