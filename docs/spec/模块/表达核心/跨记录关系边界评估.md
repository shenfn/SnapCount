# 表达核心跨记录关系边界评估

> 任务：CLEAN-001/A2
>
> 评估对象：`tools/ai-validation/expression-planner/lib/cross-record-relationships.mjs`
>
> 日期：2026-08-15

## 结论

cross-record 适合作为 CORE-008 独立迁移到生产共享核心。当前实现是约 140 行、无外部 import 的纯函数，输入、输出和边界规则都已集中在一个文件内；不需要先抽取公共 primitives，也不应与 comparison、generic-domain 或 render contract 合并。

迁移应保持机械一致：

- `supabase/functions/_shared/expression-core/cross-record-relationships.mjs` 成为生产权威实现；
- Planner Lab 原路径改为兼容 wrapper；
- Edge Shadow/Delivery 继续负责查询和来源装配，Planner 直接引用生产核心；
- fallback 与 Planner 仍是两条编排路径，但共享同一候选规则；
- 不在本切片改变查询窗口、字段投影、置信度公式或候选结构。

## 边界证据

| 项目 | 只读结果 |
|---|---|
| 依赖 | 无 import、无数据库/HTTP/文件 IO、无 Deno/Node 专属 API |
| 输入 | `currentRecord`、`relatedRecords`、可选 `maxGapMinutes`；记录含 id、域、事件时间、创建时间、对象文本和状态 |
| 规则 | NFKC 文本归一化、对象词重合、related 先于 current、最多 180 分钟、创建可见性、失败状态排除、置信度至少 0.75 |
| 输出 | 仅 `hypothesis` 候选；包含两条证据、匹配词、时间间隔和 `beneficiary: null` |
| 调用 | Edge Shadow 与 Delivery 使用同样的三表来源查询；expense 与 generic Planner 入口传入同一 `relatedRecords` 结构 |
| 测试 | 4 项直接特征测试覆盖对象+时间、仅时间、缺少事件时间、未来才获知记录 |

## 已知边界与风险

1. `timeZone` 目前只是调用方传入的兼容参数，函数本身按 ISO 时间戳计算间隔；本切片不把它扩展成时区规则。
2. 函数没有强制 `domain_key` 必须不同；同域记录在满足重合、时间和置信度时仍可能产生候选。迁移必须保留现状，若产品要禁止同域关系，另立场景和 Spec。
3. Edge 来源查询只投影交易的商户/备注、收入来源名和数据域标题/摘要/payload；扩大字段或查询范围会改变候选覆盖，另行评审。
4. `maxGapMinutes` 默认 180，且置信度公式与低于 0.75 的过滤共同决定候选数量；不得用更新 fixture 期望值掩盖公式差异。

## 处置建议

建立 CORE-008 Spec 后，先新增共享 Node/Deno fixture 和有效红灯，再机械迁移实现。迁移完成后生产对 `tools/` 的反向依赖预计由 5 项降至 4 项；A2 仍未完成，暂不进入 PWA/iOS 业务架构拆分。
