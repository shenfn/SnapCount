# 表达核心通用域规格说明

> 模块编号：CORE-010
>
> 状态：实现完成，待 PR CI

## 1. 目标

将通用域候选规则从 Planner Lab 迁入生产共享核心，保留现有 Planner 门面和候选语义，并把钱包安全比较规则与普通领域指标隔离。

## 2. 范围

- 迁移 `prepareDomainRecords` 的因果可见性和睡眠去重规则；
- 迁移收入、食品、睡眠、运动、阅读和钱包候选生成；
- 以兼容门面保留三个现有公开入口；
- 抽取共享数值、时间、payload、证据和候选构造 helper；
- 保持 `domainProfile` 作为调用方注入的纯数据；
- 新增 Node/Deno 共享 fixture、门面测试、Edge 静态契约和 Planner 回归。

## 3. 非目标

- 不改变任何候选 semantic key、结构化字段、证据字段、置信度或选择提示；
- 不修改 Edge 查询、用户过滤、来源 DTO 装配或 fallback 编排；
- 不推断工资周期、运动效果、饮食因果、还款或消费因果；
- 不把钱包余额变化解释为消费、还款、转账或偿债行为；
- 不在核心读取 profile、JSON、数据库、环境变量或设备 API；
- 不在本切片拆解 PWA、iOS 或 Edge `index.ts`；
- 不顺手迁移 `render-contract.mjs`，它另立 CORE-011 边界评估。

## 4. 对外契约

| 入口 | 输入 | 输出 | 兼容要求 |
|---|---|---|---|
| `prepareDomainRecords` | `domainKey`、records、currentRecordId | 因果可见且按睡眠事件去重的 records | 当前记录保留；历史必须严格早于当前已知时间 |
| `generateIncomeCandidates` | income records、currentRecordId | 当前收入、月累计、来源重复候选 | 金额非法时返回空；月份按当前记录归属 |
| `generateBuiltinDomainCandidates` | domainKey、records、currentRecordId、domainProfile | 当前事实、允许的比较和领域候选 | 保留当前 semantic key 与证据结构 |

## 5. 行为场景

| 编号 | 行为不变量 | 测试层 |
|---|---|---|
| CORE-063 | 当前记录始终保留，其他记录只使用严格早于当前已知时间的记录 | Node/Deno fixture |
| CORE-064 | 睡眠完全相同的事件只保留一条，非睡眠域不启用该去重 | Node/Deno fixture |
| CORE-065 | income 当前金额、当月累计和来源重复候选保持现有字段与月份口径 | Node/Deno fixture |
| CORE-066 | sport/reading 使用合法时长生成当前事实，缺失或非法数值不伪造零 | Node/Deno fixture |
| CORE-067 | food 保留餐次、菜品、宏量营养和热量缺失时的上下文候选 | Node/Deno fixture |
| CORE-068 | food 历史餐次或 profile 样本不足时不生成中位数比较 | Node/Deno fixture |
| CORE-069 | sleep 保留时间、评分、阶段的部分覆盖语义，缺失阶段不补零 | Node/Deno fixture |
| CORE-070 | chronotype 比较只使用 profile 中可解析的典型时间，迁移不新增样本量门槛 | Node/Deno fixture |
| CORE-071 | wallet 金额来源冲突时保留当前事实但阻断变化比较 | 钱包契约 fixture |
| CORE-072 | wallet 比较不得跨用户、账户 ID、账户名或 asset/liability 类型 | 钱包契约 fixture |
| CORE-073 | wallet 只接受严格更早快照；同时间和未来快照不得比较 | 钱包契约 fixture |
| CORE-074 | liability 只描述待还金额变化，不生成还款、消费或偿还因果 | 钱包契约 fixture |
| CORE-075 | Lab wrapper 与生产门面导出保持兼容，Edge 不再引用 `tools` | Wrapper + 静态契约 |
| CORE-076 | 同一 fixture 在 Node 和 Deno 输出一致，核心无运行时专属 API | 双运行时 + boundary check |

## 6. 实施顺序

1. 文档 PR 合并：本边界评估、Spec、ADR、执行记录和交接快照。
2. 实现 worktree：新增共享 fixture，确认目标生产模块缺失时出现有效红灯。
3. 最小迁移：先共享 helper 和门面，再迁 income/food/sleep，最后迁 wallet 独立模块。
4. Lab 原路径改为 wrapper，Edge 直接引用生产门面。
5. 依次运行 Node fixture、旧通用域测试、Planner 集成、Edge 静态契约、治理检查；Deno 由 PR CI 验证。
6. 只在所有证据归档后收口 A2 当前任务，不进入端侧模块化。

## 7. 完成定义

- 生产不再从 `tools` 导入通用域规则；
- 公开门面和现有 Planner 行为保持兼容；
- CORE-063 至 CORE-076 有共享 fixture 或静态契约映射；
- Node/Deno、旧回归、Planner 和边界检查通过；
- 环境失败、未验证项和剩余风险明确登记；
- 阶段索引、执行记录、ADR 和交接快照已更新；
- 未执行生产部署、数据库迁移、PWA/iOS 改动或 worktree 清理。
