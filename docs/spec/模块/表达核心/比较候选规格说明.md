```text

```

Planner Lab 保留兼容 wrapper，Edge 直接依赖生产核心。本切片迁移整个 comparison 权威模块，但不重构内部统计公式。

## 2. 场景与不变量

| 场景 | 固定不变量 | 测试层 |
|---|---|---|
| CORE-040 | 商户日基线至少需要 3 个历史活跃日，基线使用活跃日 count/total 中位数 | Node + Deno 共享 fixture |
| CORE-041 | 商户周同比使用周一开始、与上周相同已过天数，且只路由 weekly_report | Node + Deno 共享 fixture |
| CORE-042 | 金额解析拒绝 null、空白和非有限值，明确保留 0 | Node + Deno 共享 fixture |
| CORE-043 | 分类比较只使用相同 comparison cohort 的 confirmed 记录，pending 和无效金额进入 coverage 而非汇总 | Node + Deno 共享 fixture |
| CORE-044 | 分类比较使用上海时区的同一周内截止时刻与上周同期时刻 | Node + Deno 共享 fixture |
| CORE-045 | total/count/average 的方向、差值、百分比和对称分解保持内部一致 | Node + Deno 共享 fixture |
| CORE-046 | 商户周比较与分类周比较共享周期摘要 cadence/diversity 约束，period owner 可审计 | Node + Deno 共享 fixture |
| CORE-047 | 输入不足、无有效当前/基线数据或当前记录不可比较时返回空候选 | Node + Deno 共享 fixture |
| CORE-048 | Planner Lab wrapper 与生产核心两个公开 API 为同一绑定，生产 `tools/` 依赖由 6 减至 5 | 兼容测试 + 架构 ratchet |

## 3. 输入输出契约

- `generateComparisonCandidates` 消费已确认、已归一化的商户记录和当前日事实事件。
- `generateCategoryComparisonCandidates` 消费带 `fact_contract.comparison_cohort` 和 `comparison_scope` 的因果记录。
- 输出继续使用 `candidate-v0.1` 和 `period_baseline`，数字、证据、时间窗口、数据覆盖率和路由提示必须可审计。
- canonical text 只反映结构化结果；测试重点固定结构化事实和禁说边界，不把某一句文案作为唯一答案。
