## 1. 目标

建立生产拥有的纯函数核心目录：

```text
supabase/functions/_shared/expression-core/
```

第一切片只迁移最小、可被 Edge 与 Planner Lab 同时调用的事实规则，解除生产入口对 `tools/` 的新增依赖，同时保留 Planner 编排和确定性 fallback 两条运行路径。

## 2. 第一切片范围

第一切片包含四类纯函数：

| 能力 | 目标 API | 事实职责 |
|---|---|---|
| 数值解析 | `parseFiniteNumber(value)` | 只接受有限数字或可解析数字字符串；非法值返回 `null` |
| 金额归一 | `roundMoney(value, digits = 2)` | 只做确定性数值归一，不改变原始记录 |
| 商户文本归一 | `normalizeEntityText(value)` | NFKC、空白/标点和大小写归一，不联网、不写别名 |
| 支出事实契约 | `buildExpenseFactContract(record)` | 根据状态、分类和已确认业务类型决定事实/统计范围 |

别名配置的加载、候选生成、排序、渲染和数据库访问不属于第一切片；别名 Map 由调用方注入，核心不读取 JSON、环境变量或 Supabase。

## 3. 非目标

- 不在本切片迁移完整 `expression-shadow-planner.ts`。
- 不迁移跨记录关系、周期候选、比较候选、资格门、确定性评分或 render contract。
- 不删除 `tools/ai-validation/expression-planner`，不把 Planner Lab 变成生产依赖。
- 不修改 Prompt、模型供应商、数据库迁移、RPC、PWA、iOS 或通知文案。
- 不把 fallback 合并或删除；fallback 只绕过 Planner 编排，仍调用同一事实核心。

## 4. 输入输出契约

### 4.1 数值

```text
parseFiniteNumber(12)        -> 12
parseFiniteNumber(" 12.50 ") -> 12.5
parseFiniteNumber("")        -> null
parseFiniteNumber("NaN")     -> null
parseFiniteNumber(Infinity)   -> null
```

`roundMoney` 只对有限数字工作；非法值不得被转成 0。金额闭环仍由上层事实门禁负责，本模块不解析自然语言金额。

### 4.2 商户文本

```text
normalizeEntityText(" 星巴克（西湖店） ") -> "星巴克西湖店"
normalizeEntityText(null)                 -> ""
```

归一结果不是实体确认。`resolveMerchant` 的别名匹配和歧义处理在后续切片中使用调用方注入的 Map，不能在核心内自动联网、持久化或猜测用户别名。

### 4.3 支出事实契约

`buildExpenseFactContract` 必须保持已有 `expense-fact-contract-v0.1` 语义：

- `pending`/`pending_review`：`fact_status=pending_review`，现金流、支出总额和比较范围不得计入已确认事实；
- `business_kind=liability_repayment`：计入现金流但排除普通消费总额和可选消费干预；
- `business_kind=housing_rent`：计入现金流、支出总额和固定支出范围；
- 其他已确认记录：按分类建立比较 cohort；缺分类时保持待确认，不猜测。

输出必须是可序列化的普通对象，不包含函数、日期对象、错误对象或运行时句柄。

## 5. 纯函数与运行时约束

- 零 Supabase、HTTP、文件系统、环境变量和全局可变状态访问。
- 实现使用 Node 22 与 Deno 2 都支持的 ESM JavaScript；第一切片不依赖 Node/Deno 专属 API。
- 相同输入向量在 Deno 和 Node 中输出字节等价的 JSON（对象键按测试规范稳定化）。
- 核心不产生日志、不吞异常、不读取 Planner Lab 相对路径。
- 生产入口、Planner Lab 适配器和 fallback 可以各自编排，但事实规则只能从该核心导入。

## 6. 场景与测试映射

| 场景 | 固定不变量 | 测试层 |
|---|---|---|
| CORE-001 | 有限数值、空值、非法数字的解析结果稳定 | Node + Deno 纯逻辑 |
| CORE-002 | 金额只做数值归一，非法金额不变成 0 | Node + Deno 纯逻辑 |
| CORE-003 | NFKC/空白/标点归一不等于实体确认 | Node + Deno 纯逻辑 |
| CORE-004 | pending、偿债、房租、普通支出的事实范围不混淆 | Node + Deno 纯逻辑 |
| CORE-005 | 同一份 fixture 在 Deno/Node 输出一致 | 双运行时契约测试 |
| CORE-006 | 核心目录不得导入 Supabase、HTTP、Node/Deno 专属 API 或 `tools/` | 静态依赖检查 |
| CORE-007 | Planner 与 fallback 复用核心，但两条编排路径均可独立降级 | Edge/Planner 集成回归 |

测试不得把某一句模型文案当成正确答案，只断言结构化事实、证据范围、数值和失败出口。

## 7. 迁移顺序

1. 先建立 `supabase/functions/_shared/contracts/表达核心-v0.1.json` 共享 fixture 和 Node/Deno 测试入口，先得到红灯。
2. 在 `_shared/expression-core/` 实现最小函数，测试转绿。
3. Planner Lab 通过 adapter 复用核心，保留离线专用配置和编排。
4. Edge 生产入口只替换第一切片对应导入，其他 `tools/` 导入继续作为 A1 基线。
5. fallback 路径以同一核心执行，验证 Planner 不可用时输出事实边界不变。
6. 更新架构基线：移除已迁移的例外，确认没有新增反向依赖。
