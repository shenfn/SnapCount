# 表达核心跨记录关系规格说明

> 模块编号：CORE-008
>
> 状态：规格已建立，待实现
>
> 关联计划：CLEAN-001/A2

## 1. 目标

将跨记录关系候选的确定性规则迁入生产拥有的 `expression-core`，保持 Planner Lab、Edge Shadow、Edge Delivery 和 fallback 的事实边界一致。候选只能表达“可能相关”，不能把关系升级为已确认因果或受益人事实。

## 2. 范围

- 迁移 `generateCrossRecordRelationshipCandidates` 的完整实现；
- 保留对象词归一化、事件先后、时间间隔、创建可见性、状态排除和置信度门槛；
- Lab 原导入路径保留兼容 wrapper；
- Edge 生产入口直接引用 `_shared/expression-core`；
- 用同一份 fixture 分别验证 Node 与 Deno。

## 3. 非目标

- 不改变三张来源表的查询字段、数量上限或用户隔离；
- 不新增实体别名配置、长期关系记忆、用户确认交互或历史回填；
- 不修改 comparison、generic-domain、render contract、资格、评分和选择；
- 不把 `timeZone` 参数扩展为新的时间语义；
- 不因“跨记录”命名而擅自禁止同域候选。

## 4. 行为场景

| 编号 | 行为不变量 | 测试层 |
|---|---|---|
| CORE-049 | 对象重合、related 先发生且间隔不超过 180 分钟时，可生成 hypothesis 候选 | Node/Deno fixture |
| CORE-050 | 仅有时间接近、没有对象重合时不生成候选 | Node/Deno fixture |
| CORE-051 | current 或 related 缺少有效事件时间时不生成候选 | Node/Deno fixture |
| CORE-052 | related 的创建时间晚于 current 已知时间时不作为证据 | Node/Deno fixture |
| CORE-053 | pending、failed、deleted、discarded、rejected 等 related 状态不生成候选 | Node/Deno fixture |
| CORE-054 | 候选的关系状态始终为 `hypothesis`，受益人始终为 `null` | Node/Deno fixture |
| CORE-055 | 迁移前后的候选 ID、证据来源、匹配词、时间间隔和置信度保持一致 | Lab wrapper + Planner 回归 |

## 5. 完成定义

1. 生产核心文件存在且无运行时专属 API。
2. Lab wrapper、Edge 直接导入和共享 fixture 均已更新。
3. 新增测试先在目标文件缺失时有效失败，再在最小迁移后通过。
4. Node/Deno CORE-008 fixture、旧 4 项回归和完整 Planner 测试通过。
5. `tools/` 依赖计数下降一项，且没有新增反向依赖。
6. 阶段索引、ADR、执行记录和交接快照已更新；未验证项明确标注。
