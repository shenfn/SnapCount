## 1. 目标

将候选重要性、相关性、置信度、新颖度、用户偏好、曝光惩罚、表面阈值和排序摘要迁入生产拥有的纯函数目录：

```text
supabase/functions/_shared/expression-core/deterministic-scoring.mjs
```

Planner Lab 保留原导入路径作为兼容 wrapper，Edge 生产入口直接依赖 `_shared`。评分继续消费 CORE-003 产出的资格结果，不重新计算资格。

## 2. 场景与不变量

| 场景 | 固定不变量 | 测试层 |
|---|---|---|
| CORE-018 | 评分公式、版本和表面阈值保持稳定，精确新事实能按既有阈值通过通知表面 | Node + Deno 共享 fixture |
| CORE-019 | 曝光按全局、表面和 dedupe key 分层读取；重复曝光降低新颖度和分数，不污染其他表面 | Node + Deno 共享 fixture |
| CORE-020 | 用户偏好受 `0.6..1.2` 上限约束，表面语义偏好只影响对应 surface；旧 rendering snapshot 仍兼容 | Node + Deno 共享 fixture + Planner 回归 |
| CORE-021 | 不满足资格的 surface 不重新评分，保留 `score=null` 和可审计拒绝原因；实体不相关时相关性按既有系数下降 | Node + Deno 共享 fixture |
| CORE-022 | `scoreCandidates` 与 `summarizeScores` 保持批量输出和各 surface 排序摘要 | Node + Deno 共享 fixture |
| CORE-023 | Planner Lab wrapper 与生产核心公开 API 为同一导出绑定，生产 `tools/` 依赖减少 1 条 | 兼容测试 + 架构 ratchet |

## 3. 输入输出契约

- 输入必须包含 CORE-003 的 `eligibility`；评分不生成候选、不放宽资格、不修改事实证据。
- `scoreCandidate` 保留候选字段，只新增 `scoring`；输出保留 `deterministic-score-v0.2`、公式、组件、曝光和四类 surface 评分。
- 评分采用现有确定性公式：`100 × importance × relevance × confidence × novelty × user_preference - repetition_penalty - interruption_cost`。
- 表面阈值保持：shortcut 75、PWA 卡片 65、record detail 45、weekly report 35。
- `summarizeScores` 只汇总已通过资格的候选，按分数降序，不生成新的事实或文案。

## 4. 非目标

- 不迁移候选生成、实体别名配置、比较、跨记录关系或 render contract。
- 不调整重要性表、评分公式、阈值、曝光 key、偏好上下限或旧 snapshot 兼容语义。
- 不把评分与资格门合并，不在评分层补救资格拒绝。
- 不修改 Prompt、数据库、PWA、iOS、迁移或生产部署。

## 5. 纯函数与依赖约束

- 生产实现零 IO、零环境 API、零 Supabase/HTTP 依赖，不读取 `tools/` 或配置文件。
- Planner Lab 原路径只 re-export 生产核心，不保留第二份评分规则。
- 共享 fixture 使用虚构候选和曝光记录，不保存真实用户数据或模型文案。
- Node 与 Deno 对同一 fixture 的结构化评分结果一致。

## 6. 迁移顺序

1. 写共享 fixture、跨运行时断言器、wrapper 兼容测试和生产核心测试，先证明目标模块缺失的红灯。
2. 将现有纯函数实现迁入 `_shared/expression-core/deterministic-scoring.mjs`。
3. 将 Lab 文件改为 re-export wrapper，Edge 入口切换到 `_shared`。
4. 运行评分特征测试、资格/选择回归、完整 Planner、Edge 检查和架构 ratchet。
5. 更新执行记录、阶段索引和交接快照；CI 通过后再评估下一组候选规则。
