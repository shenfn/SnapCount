# Expression Planner 反馈学习与灰度决策 v0.1

状态：实施中，待发布验收
日期：2026-07-26
适用范围：记录详情、AI 卡片、快捷通知、周报中的候选选择与用户反馈
不包含：真实用户素材、生产凭据、线上数据导出和具体用户画像

## 1. 文档目的

这份文档解决三个容易混淆的问题：

1. 当前规则候选什么时候可以展示给用户并接受点评。
2. 什么叫开始 Bandit 阶段，什么叫让 Bandit 在线接管。
3. 需要记录哪些数据，未来的学习排序才不会把事实错误、模板风格和用户偏好混在一起。

本文是产品决策和工程准入契约。实现、灰度、回放和发布验收均以本文为共同边界；阶段名称不再单独作为上线依据。

## 2. 产品初心

芥子不是另一款以分类、预算和图表为中心的记账软件。它要把用户随手留下的截图和记录，转化为可信、持续积累、可以被用户纠正的个人生活上下文。

一条有价值的反馈应逐步回答：

1. 这次记录真实发生了什么。
2. 它放进用户自己的历史后意味着什么。
3. 这是偶然事件、重复习惯，还是正在形成的变化。
4. 现在有什么值得留意，但证据还不足以说明什么。

算法不以“每条记录都说很多”为目标，而以“在合适的位置说一件可信且有用的事”为目标。

跨域分析只能描述有证据的关联，不能把同时发生写成因果。例如可以说“较短睡眠日与外卖记录同时出现较多”，不能直接说“睡眠不足导致消费增加”。

## 3. 本轮决策

采用两条并行路线：

### 3.1 用户可见路线：规则版 owner-only 闭环

- 代码生成、校验、评分并选择结构化候选。
- 记录详情默认展示一个主候选。
- 目标态允许用户通过“换个角度”查看另一个合格候选；首轮灰度先上线单主候选和点评，不以切换功能为阻断项。
- 每个真正可见的候选单独确认曝光，并允许正向、负向或纠错点评。
- 当前阶段直接展示候选的规范文本，不额外调用大模型。
- 大模型表达层以后接在稳定的候选选择之后，并按候选指纹缓存。

### 3.2 算法实验路线：Bandit-ready Shadow

- 现在开始补齐决策日志和结果日志。
- Bandit 可以在后台回放和 Shadow 计算，但不改变用户实际看到的候选。
- 在样本、日志和稳定性门槛达标前，不允许 Bandit 在线探索。
- 当前确定性规则继续作为基线、warm start 和随时可恢复的兜底策略。

因此，“开始第二阶段”在本项目中表示开始 Shadow、采数和离线评估，不表示立即把线上选择权交给 Bandit。

本文中的 `owner-only` 指项目维护者明确配置的测试账号白名单，不是“只要记录属于当前登录用户”或“只要用户开启改进计划”就自动进入灰度。白名单必须由服务端校验，并提供独立于客户端的关闭开关；现有 `improvement consent` 只表示允许采集，不等于 owner 灰度授权。

## 4. 职责边界

```text
结构化记录
  -> 事实契约与完整性判断
  -> 候选生成
  -> Eligibility Gate
  -> 确定性评分与组合
  -> 用户可见候选
  -> 曝光确认
  -> 用户点评和行为结果
  -> 规则偏好聚合 / Shadow 学习策略
  -> 后续候选选择
```

| 层 | 负责内容 | 不负责内容 |
| --- | --- | --- |
| 识别层 | 从截图提取字段和置信度 | 判断候选是否值得展示 |
| 事实层 | 数字、时间、实体、方向和历史依赖 | 自由发挥文案 |
| 候选层 | 生成可解释的分析角度 | 绕过缺失字段和证据门槛 |
| Gate | 阻止方向错误、证据不足和 Surface 不适配 | 学习用户喜好 |
| 排序层 | 在合格候选中选择角度 | 修复事实错误 |
| 表达层 | 把已选事实说自然 | 新增数字、实体、方向或因果 |
| 反馈层 | 区分质量、语义偏好和表达偏好 | 把所有负面反馈压成同一个 reward |

长期目标仍是“代码负责算，大模型负责说”。规则候选直接展示是采集排序监督的过渡形态，不是永久取消表达层。

## 5. 用户可见契约

### 5.1 完整记录

记录详情只展示一个主候选，最多提供一个低干扰的次候选入口。不得把候选 ID、内部维度名、分数、探索概率或 Gate 信息展示给普通用户。

主候选必须满足：

- 所有事实字段均有可追溯来源。
- 当前记录和历史依赖仍然有效。
- 适合当前 Surface。
- 未超过语义去重和曝光上限。
- 相比 `fact_only` 确实增加了信息价值。

### 5.2 待补充记录

待补充不等于页面空白，也不等于允许猜测。它可以展示只依赖已确认字段的候选，例如当前事实、记录时间或识别状态。

合成示例：

> 已识别到 32 元和记录时间，消费分类仍待确认。

待补充状态不得生成：

- 依赖未确认分类的同类消费比较。
- 依赖未确认实体的同名记录间隔。
- 消费强度、异常程度或行为评价。
- 因缺失历史或字段而无法验证的趋势判断。

用户补全字段后，必须重新计算候选指纹和历史依赖；不能继续复用补全前的候选。

### 5.3 没有高价值候选

每条记录可以有可见反馈，但不是每条记录都必须有“洞察”。不同 Surface 的兜底动作是：

| Surface | 允许的兜底动作 |
| --- | --- |
| 记录详情 | `fact_only`，展示可信当前事实 |
| AI 卡片 | `fact_only` 或不展示 |
| 快捷通知 | `silence`，不为凑内容打断用户 |
| 周报 | 延迟到周期信息完整后再选择 |

`fact_only` 和 `silence` 都应作为可审计动作进入决策日志，不能在统计中消失。

### 5.4 切换角度

“换个角度”不是把调试列表暴露给用户，而是提供有限选择：

- 初始只展示主候选。
- 用户主动操作后才展示第二候选，并为第二候选创建独立曝光。
- 切换行为记录为 outcome，但单次切换不直接等同于负面评价。
- 用户切回、停留、点评或纠错后，才形成更完整的偏好证据。

## 6. 点评契约

点评首先回答“用户在评价什么”，然后才决定是否影响排序。

| 类型 | 示例 | 影响范围 |
| --- | --- | --- |
| 候选价值正向 | 有帮助、这个角度不错、正是我想看的 | 候选语义和 Surface 偏好 |
| 候选价值负向 | 没什么帮助、不相关、有点重复 | 候选语义、重复容忍度和 Surface 偏好 |
| 事实质量 | 数字不对、识别错误、推断过头 | 质量队列和 Gate，不得作为“不喜欢该角度” |
| 表达偏好 | 太长、太短、语气不喜欢 | Renderer 和风格配置，不得降低事实候选价值 |
| 时机偏好 | 现在不需要、通知打扰 | Surface 和打断成本 |
| 自由文本 | 用户补充原因 | 保留原文供人工分析，结构化标签需可追溯 |

规则：

1. 没有点评表示 reward 未观测，不得自动当作负反馈。
2. 事实错误优先阻断语义偏好更新，避免错误内容污染兴趣画像。
3. 同一曝光的改评要保留修订关系；Bandit 结果日志不得只保留最后一次覆盖值。
4. 点评必须绑定真实 `exposure_event_id`、`candidate_id`、`surface` 和当时可见字段。
5. 待补充记录上的“识别不准”进入识别质量，不进入候选偏好。

## 7. 当前算法与学习算法的关系

当前确定性规则不是临时废代码。它承担四个长期职责：

1. 事实和安全 Gate。
2. Bandit 的候选空间定义。
3. 学习策略的 warm start 和对照基线。
4. 异常时的 kill switch 回退策略。

未来学习排序只允许调整合格候选之间的选择。不得学习绕过数字证据、方向一致性、历史样本量、Surface 容量和隐私规则。

Bandit 的动作不是任意文本，而是：

```text
eligible candidate semantic action
or fact_only
or silence when the surface permits it
```

表达风格不与候选语义共用同一个 action。否则无法区分用户不喜欢分析角度，还是只不喜欢一句话的写法。

## 8. Bandit-ready 决策日志

当前曝光记录只描述“最终展示了什么”还不够。未来每次选择必须先写一条不可变的 decision 记录。

本轮采用不新增新表的最小实现：记录详情 GET 生成 decision 并放入一小时有效的 `expression_delivery_snapshots.delivery_plan`；客户端确认内容真实可见后，ACK 才把 decision 和记录详情策略可选 action set 固化到 `expression_exposure_events.metadata`，数据库再从该可信曝光复制 `decision_id` 到点评 metadata。未 ACK 的预览只保留短期快照，不算真实曝光，也不进入可学习的持久日志。

这个实现只覆盖记录详情的确定性规则基线。它还不是独立、追加式的 decision/outcome 事件模型，也没有覆盖 AI 卡片、快捷通知和周报；确定性日志中的选中动作概率为 `1`、其他动作为 `0`，不能替代未来探索策略的真实 propensity。

### 8.1 必填标识与版本

```text
decision_id
user_id
record_id
surface
decided_at
policy_name
policy_version
scoring_version
candidate_schema_version
renderer_version
profile_revision
source_revision

```

### 8.2 决策上下文

只保存经过批准的结构化特征，不复制截图、识别原文、完整商户名或自由文本：

```text
domain
record_completeness
account_stage
time_bucket
history_sample_bucket
recent_surface_exposure_count
recent_semantic_exposure_count
recent_feedback_summary
candidate_feature_schema_version
```

时间相关特征必须携带 `as_of`，避免使用决策发生后的记录造成未来信息泄漏。

### 8.3 完整动作集合

日志必须保存决策当时所有可被该策略选择的 action，而不只是最终主候选：

```text
action_id
candidate_id
semantic_key
dimension
candidate_fingerprint
dependency_fingerprint
feature_vector
deterministic_score
rank_before_policy
gate_results
exposure_key
dedupe_key
fact_only_or_silence
```

未通过 Surface Gate、价值阈值、固定内容覆盖或硬去重冷却的候选不进入 action set；只因容量或多样性组合而落选的候选仍是可替代动作。其他不合格候选可以按 reason code 聚合统计；不得将包含敏感原文的完整候选对象写进分析日志。

当前记录详情的 `decision.action_set` 保存动作 ID、候选实例指纹、通用语义键、维度、claim 类型、确定性分数、阈值状态、确定性状态/原因、去重与曝光键指纹、排序和选择概率。动作 ID 基于版本化的“域 + 语义键 + 维度 + claim 类型”，用于跨记录聚合同类动作；候选实例指纹用于追溯本次具体候选，两者不再混用。该 action set 不保存候选正文、OCR、结构化事实、商户原名、原始候选 ID、原始曝光键或原始去重键；整个 decision 对象有 64 KiB 序列化硬上限。确定性指纹只是用于稳定关联的无原文字段标识，不等同于匿名化或加密保护。

这项限制只描述 `decision.action_set`。现有交付快照仍需保存最终主候选正文，曝光事件仍需保存实际渲染内容以及选中候选的原始 exposure/dedupe key，供审计、点评和在线去重使用；这些字段继续受现有用户隔离、删除和保留策略约束。上下文特征、依赖指纹、完整 Gate 结果、其他 Surface 的动作集合，以及进一步减少原始去重键存储仍属于后续工作。

### 8.4 最终动作

```text
chosen_action_id
selection_probability
selection_mode
exploration_rate
reason_codes
decision_latency_ms
```

`selection_probability` 必须表示当前策略在当时上下文和动作集合下选择该动作的真实概率。确定性基线可以记录为 `1`，但仅有确定性日志不能无偏评估从未展示的动作。

## 9. Outcome 与 reward 日志

结果日志与 decision、exposure 分开，采用追加写入：

```text
outcome_event_id

outcome_type
observed_at
feedback_choice
issue_codes
reward_component
reward_value
observation_window

```

首批 outcome 类型：

- `explicit_feedback`
- `angle_switched`
- `angle_returned`
- `detail_expanded`
- `record_corrected`
- `record_completed`
- `notification_dismissed`

首批只把显式点评作为主要监督。停留、展开、切换等隐式行为先记录，不立刻赋予长期 reward，避免把误触、页面停留和真正有用混为一谈。

reward 数值和观察窗口必须在实验开始前登记版本，不能看完结果后反向调整口径。

## 10. 阶段与准入门槛

### 阶段 A：规则闭环发布准备

目标：让用户可以看到可信候选并完成曝光、点评、改评和删除闭环。

交付：

- 记录详情单一主候选。
- 待补充记录的事实型候选。
- 正向、负向、质量和表达反馈分流。
- 候选曝光与点评精确绑定。
- 删除记录时清理相关曝光、反馈和画像来源。

准入：

- 固定回放事实方向错误为 0。
- 重复验收覆盖用户实际看到的 Surface。
- ACK、点评、改评和删除具备跨层测试。
- 数据库迁移、Edge 部署和客户端版本具备顺序与回滚说明。

### 阶段 B：owner-only 规则灰度

目标：验证真实端到端稳定性并采集第一批在线反馈。

限制：

- 先接记录详情，再接 AI 卡片。
- 快捷通知保持现有安全策略或 `silence`，不做探索。
- 规则排序决定用户可见结果。
- 首轮只展示单一主候选；稳定后再增加有限的“换个角度”，并分别记录曝光。
- 学习策略/Bandit 只计算 Shadow 结果。
- 仅服务端 owner 白名单账号可进入；撤销白名单或关闭开关后立即回到现有稳定链路。

准入下一阶段前至少满足：

- 连续 7 天无主流程故障。
- 曝光和反馈写入成功率不低于 99.9%。
- 质量问题误入偏好信号为 0。
- 写入幂等，重试不制造重复曝光和重复点评。
- 人工抽查未发现事实方向错误扩大。
- kill switch 和确定性回退可用。

### 阶段 C：离线学习与 Shadow 评估

目标：证明学习策略比规则基线更好，而不是只证明它可以运行。

最低数据准备：

- 100 至 200 条分层人工标注并完成标签一致性检查。
- 真实曝光和点评能关联到不可变 decision。
- 完整 action set、选择概率和策略版本可用。
- 质量、语义、表达和时机反馈已分流。

100 至 200 条是开始评估的门槛，不是允许在线 Bandit 的充分条件。若候选族、Surface 或用户分层后的有效样本仍不足，应继续使用规则或合并动作空间。

评估顺序：

1. 确定性规则基线。
2. 简单逻辑回归或 Learning to Rank 基线。
3. LinUCB 或 Thompson Sampling Shadow。
4. 使用预先登记的指标比较，结果不达标则不进入在线探索。

进入阶段 D 必须单独评审，并同时满足：

- 阶段 B 的 7 天稳定性、写入、幂等、质量分流和回退门槛全部通过。
- 至少 100 至 200 条分层标注，其中不少于 20% 经过独立复核，关键标签一致率不低于 85%。
- 可参与学习的决策完整保存 action set、上下文、策略版本和真实 propensity；decision、exposure、outcome 可关联率不低于 99.9%。
- 在预先冻结的留出集上，学习策略的硬事实错误为 0、重复率不高于规则基线，排序质量达到预登记阈值；未证明改进时继续 Shadow。
- 离线评估不得只依赖确定性策略历史曝光；必须结合完整动作标注，或使用具备覆盖度的探索日志做 IPS/DR 等 OPE。
- 服务端 owner 白名单、探索率硬上限、监控告警和 kill switch 已通过演练。

### 阶段 D：owner-only 小比例在线探索

目标：在最低打断成本的 Surface 验证探索与利用。

限制：

- 只在记录详情启用。
- 只在通过全部 Gate 的候选之间探索。
- 初始探索率由配置控制并设置硬上限；未经新评审不得扩到通知。
- 每次选择记录真实 propensity。
- 任何事实、安全、重复或写入异常立即回退规则策略。

### 阶段 E：逐步扩大

只有在记录详情稳定后，才评估 AI 卡片。快捷通知最后进入，因为它具有最高打断成本。周报继续使用独立的周期所有权和趋势逻辑，不与逐笔候选共用简单 Top-1 策略。

## 11. 指标体系

### 11.1 硬质量指标

- 数字或方向错误率。
- 无证据实体和时间出现率。
- 历史依赖失效后继续展示率。
- 质量错误进入偏好率。
- 删除后残留曝光、反馈和画像来源数量。

硬质量指标恶化时，无论正向点评是否增加，都不得扩大灰度。

### 11.2 候选价值指标

- `有帮助`、`这个角度不错`、`正是我想看的`占比。
- `没什么帮助`、`不相关`占比。
- 相同语义在同一作用域的重复曝光率。
- 用户主动切换角度后产生正向反馈的比例。
- `fact_only` 和 `silence` 被规则选择的比例。

### 11.3 运行指标

- 决策、曝光、点评写入成功率。
- ACK 和点评幂等冲突率。
- 决策到展示延迟。
- Shadow 与线上规则结果差异率。
- kill switch 生效时间。

## 12. 隐私与数据保留

- 决策日志只保存学习所需的结构化特征和版本，不保存原图、OCR 原文、完整阅读内容或自由文本副本。
- 自由点评沿现有用户数据边界保存，不复制到可提交回放或通用训练集。
- 本地真实回放继续放在 Git 忽略目录，不进入仓库、PR 和 CI artifact。
- 候选、日志和画像数据必须受用户隔离策略约束。
- 删除记录和删除账号时，decision、exposure、outcome、反馈和派生画像的清理责任必须明确。
- 未来若用于跨用户模型训练，需要单独的同意、匿名化、保留期限和退出机制评审；本文不授予该权限。

## 13. 缓存与表达层

未来启用大模型表达时，缓存键至少包含：

```text
surface
+ selected_candidate_fingerprint
+ style_fingerprint
+ renderer_version
```

`selected_candidate_fingerprint` 必须包含当前记录事实、候选 ID、历史依赖摘要和结构化证据。以下变化会使缓存失效：

- 当前记录编辑或补全。
- 历史依赖记录变化。
- 最终选中候选变化。
- 用户表达风格变化。
- Renderer 或 Prompt 契约版本变化。

重复打开且上述输入未变时不得重新调用模型。

## 14. 最小实现切片

按以下顺序推进，每一批只改变一个主要层次：

### Slice 1：冻结规则候选与反馈契约

- 完成规则候选的跨 Surface 回归。
- 修复曝光去重、历史依赖失效和点评归因问题。
- 验证待补充记录只使用可见且可信字段。
- 增加交付回归：主候选的 `surface + dedupe_key` 达到上限后，必须选择下一条合格候选。
- 增加依赖回归：影响周期或个人基线的历史记录变化后，旧快照必须失效或重新计算。

### Slice 2：补 decision/outcome 日志

- 已在本地复用现有 JSONB 字段，保存记录详情确定性 decision、策略可选 action set 和 chosen action；整个 decision 对象具备 64 KiB 硬上限。
- 已为记录详情规则基线记录 policy/version/确定性 propensity，并将 ACK 曝光和点评关联到 decision。
- 待新增独立、追加式 outcome/reward 修订历史；当前改评仍覆盖旧反馈语义。
- 待补其他 Surface、删除链路和跨层用户隔离验收；真实 Bandit propensity 必须在探索策略实现后记录。

### Slice 3：owner-only 用户体验

- 记录详情只展示主候选。
- 增加有限的角度切换。
- 明确提示用户评价“这条发现是否有用”。
- 保留正向、负向、事实质量和表达偏好入口。

### Slice 4：离线基线与 Shadow

- 在固定快照上训练或拟合简单排序基线。
- 运行时并行记录学习策略的 Shadow 选择。
- 对比规则与 Shadow，但不改变实际展示。

### Slice 5：受控在线探索

- 单独评审 reward、探索率、停止条件和回滚。
- 先在 owner-only 记录详情启用。
- 达标后再决定是否扩大，不自动进入下一阶段。

## 15. 本轮不做

- 不让 Bandit 直接控制生产候选。
- 不用大模型自由生成候选事实。
- 不把未标注的生产回放记录称为训练标签。
- 不因用户未点评就推断为负反馈。
- 不把事实错误学习成“不喜欢这个维度”。
- 不在通知 Surface 做早期探索。
- 不提交或上传真实回放素材。

## 16. 阶段性发布验收清单

以下项目按目标阶段逐项勾选，只有在对应客户端、Edge Function 和数据库链路完成集成验收后才算完成；本地单元测试通过不等于已经发布完成。“换个角度”和学习日志不阻断首轮单主候选灰度，但会阻断后续相应阶段。

- [ ] 完整记录能展示一个真实曝光绑定的主候选。
- [ ] 待补充记录能展示可信事实候选，且不使用缺失字段比较。
- [ ] 用户可以给出正向反馈。
- [ ] 事实错误与语义偏好分流。
- [ ] 切换角度后两个候选分别记录曝光。
- [ ] decision 保存完整的策略可选 action set，并验证容量上限。
- [ ] chosen action 保存真实 selection probability。
- [ ] outcome 采用追加写入并支持修订关系。
- [ ] 无点评不被记录为负 reward。
- [ ] 删除记录后相关学习来源可验证清理。
- [ ] Shadow 结果不改变 owner-only 实际展示。
- [ ] kill switch 可恢复确定性规则。
- [ ] 发布前门禁、迁移顺序和回滚文档齐全。

## 17. 决策摘要

当前最优路线不是“规则还是 Bandit”二选一，而是：

1. 用规则候选建立可信、低成本的用户反馈闭环。
2. 从第一天开始向 Bandit-ready 契约补齐决策与结果日志；未完成的 outcome 不提前宣称已具备。
3. 先让学习策略在 Shadow 中证明价值。
4. 最后才在低打断 Surface 交出有限选择权。

这条路线同时保护三个长期资产：用户信任、真实反馈数据和可回退的算法基线。
