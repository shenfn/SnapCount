# PWA 视觉资产盘点

更新时间：2026-07-24

## 盘点结论

PWA 目前仍使用自己的 Classic 视觉体系，没有接入 `trae-design-system` 的生成产物。这套体系并不是临时样式堆叠，已经形成了比较明确的产品语言：暖纸色背景、深绿色主色、金橙色提醒、较高的信息密度，以及围绕“事实证据”组织的记录和中转站界面。

用户喜欢的 PWA 配色、节奏和组件可以沉淀为长期资产。当前阶段先把它记录为“PWA Classic”参考基线，等待 iOS 视觉定稿后再决定是否统一 Token；本次不修改 `src/**`，不加载 iOS 生成 CSS，也不改变任何业务逻辑。

## 来源与加载关系

PWA 入口在 `src/main.js` 中按顺序加载：

1. `src/styles/main.css`：全局 Token、页面基础结构、常用卡片和列表样式。
2. `src/styles/components/app-shell.css`：平台加载、错误、下拉刷新、图片预览等应用壳层状态。
3. `src/styles/components/nav-fab.css`：底部导航、中央 FAB、快捷操作面板。
4. `src/styles/components/shared-ui.css`：按钮、表单、弹窗、通用提示等共享控件。
5. `src/styles/pages/*.css`：首页、认证、数据域、账户、设置、中转站、记录详情、报告和未绑定账户等页面样式。

当前没有加载：

- `trae-design-system/dist/tokens.css`
- `trae-design-system/dist/tokens.js`
- iOS 的 `JieziTheme+Generated.swift`

因此后续讨论 PWA 时，应把 `src/styles/**` 视为实际运行基线，不要假设 iOS Token 已经自动影响了 PWA。

### 版式与节奏

- 页面最大宽度为 `480px`，以手机单列阅读为主要场景。
- 底部导航高度为 `72px`，同时考虑 `safe-area-inset-bottom`。
- 常用内容间距为 `4/8/12/16/20/24/32px`。
- 卡片圆角主要落在 `10/12/14/16/18/20/22px`，全圆角用于胶囊、标签和状态条。
- 主体字体使用中文系统字体，金额和统计数字优先使用 `DM Sans`。
- 卡片常用半透明白底、细描边和浅阴影；页面背景使用暖白渐变，整体不是纯白后台风格。
- 重要数据采用“标签 + 数值 + 一句解释”的三层结构，长文本允许换行，不依赖固定宽度。

这套节奏的价值在于：首页能快速扫读，记录页仍能容纳较多事实，中转站则把“图片/文字证据”和“需要用户处理的事项”放在同一张卡片里。

## 可沉淀的组件资产

### 应用壳层

来源：`src/styles/components/app-shell.css`、`src/styles/main.css`

- 启动加载态：品牌标记、浮动动画、进度轨道。
- 友好错误态：错误原因、用户可执行步骤、重试按钮和错误代码。
- 下拉刷新提示：准备刷新、刷新中和结束状态。
- 图片全屏预览：黑色遮罩、等比展示和关闭按钮。
- 顶部 Toast/Flash：短暂反馈，不打断当前页面。

这些状态是跨页面复用的基础资产，后续如果统一 Token，只需要替换颜色、描边和阴影，不应改变状态文案或触发逻辑。

### 首页和数据域

来源：`src/components/pages/PageHome.vue`、`src/styles/pages/home.css`、`src/styles/main.css`

- `stat-card` / `today-card`：摘要数值和今日重点。
- `trend-pill`：趋势或变化幅度的轻量提示。
- `domain-quick-card` / `domain-card`：数据域入口，图标、名称、摘要、数量和箭头。
- `section-header`：左侧标题、右侧进入详情的动作。
- `home-timeline`：按日期、时间和事实摘要排列的记录流。
- 财务快照：净额估算、可用现金、待还、自动扣款提醒和近 7 日支出柱状图。
- 首页组件管理 Bottom Sheet：允许用户选择首页展示哪些域及排序。
- `home-daily-card`：按天聚合的多域摘要，信息密度高但仍保持可扫描。

首页的“组件可配置”是产品能力，不是纯视觉效果。后续视觉调整只能改变层级和呈现，不能删除用户配置、排序或数据口径。

### 记录、账单和详情

来源：`src/components/BillRow.vue`、`src/components/pages/PageRecordDetail.vue`、`src/styles/pages/record-detail.css`

- `timeline-item` / `bill-item` / `income-item`：统一的列表行节奏。
- `domain-card`：数据域列表入口。
- 证据图片卡：原图、图片占位和全屏查看。
- 字段详情行：标签、值、数值格式和多行文本。
- 账户影响卡：推荐账户、已绑定账户和待绑定状态。
- AI 摘要、AI 陪伴和事实字段分区。
- 编辑、删除、补充信息等底部动作区。

详情页的核心资产不是卡片本身，而是“证据在前、字段在中、AI 解释在后、操作在底”的信息顺序。迁移到新主题时必须保留这个顺序。

### 中转站与待处理

来源：`src/components/pages/PagePending.vue`、`src/styles/pages/pending.css`

- 顶部筛选胶囊：全部、待分类、待确认、AI 失败、账单补充。
- `pending-record-card`：缩略图、标题、金额、来源、状态、摘要和置信度。
- 图片证据卡：有图时显示原图；无图时保留文字事实和可理解的占位提示。
- 置信度条：把模型不确定性变成可扫读的状态，不直接把内部字段名暴露给用户。
- 错误区：识别失败原因和重试入口。
- 归档区：归档为消费、收入或其他数据域。
- 批量处理栏：选择、批量归档和批量销毁。
- 账单待补充字段胶囊：平台、分类、支付方式等字段状态。
- 已处理折叠区：查看已归档或已销毁的记录。

这里已经具备“证据墙 + 状态处理”的基础资产。账单待补充当前仍有单独的列表视觉和字段胶囊，但不要在 PWA 端先行重做，等 iOS 的待补全体验确认后再统一信息层级。

### 图表与反馈

来源：`src/components/ChartPanel.vue`、`src/components/AiFeedbackCard.vue`、相关页面 CSS

- `ChartPanel` 有 `placeholder`、`light`、`solid` 三档成熟度，适合数据积累不足时仍给用户明确反馈。
- `AiFeedbackCard` 支持正向、留意、兜底、时机等语义带，并可折叠判断依据。
- 图表和反馈卡都支持备注、时机标签和渐进显示，能承接“数据还少，但产品已经开始工作”的体验。

这两个组件应作为跨域资产保留，尤其是三档图表状态，不应为了统一视觉改成无数据时一片空白。

## 交互资产

### Bottom Sheet

来源：`src/composables/useBottomSheet.js`、`src/styles/components/shared-ui.css`

当前行为包括：

- 打开时锁定 body 滚动，关闭时恢复原滚动位置。
- 支持向下拖拽关闭和向右滑动关闭。
- 有未保存修改时拦截关闭，并显示放弃修改确认。
- 输入框、按钮、图片、选择胶囊等交互目标不会误触拖拽关闭。
- 支持关闭动画和状态复位。

这是现有 PWA 体验的重要组成部分，但嵌套滚动、长列表和横向手势仍是后续需要重点回归的区域。视觉迁移时不要把 Sheet 改成普通弹窗，也不要改变保存/放弃门禁。

### 下拉刷新

来源：`src/composables/usePullToRefresh.js`

- 只在滚动容器位于顶部时接管下拉手势。
- 有阻尼和最大下拉距离。
- 达到阈值后执行异步刷新，并在完成后复位。
- 主动阻止 iOS Safari 的原生下拉刷新。

它属于交互资产，不属于颜色 Token。后续修复滚动跳动或刷新冲突时，应优先调整手势边界和滚动容器，不要用 CSS 遮盖问题。

## 当前不一致点与迁移风险

### Token 没有完全收口

`main.css` 已经有一组全局变量，但页面 CSS 和 Vue scoped style 中仍存在较多直接颜色、渐变、阴影和圆角。当前主要缺口：

- 颜色语义与具体颜色混用，例如 `accent`、`warning`、财务金橙色有重叠。
- 账户、AI 反馈、财务等页面有自己的状态色，未全部映射到全局变量。
- `ChartPanel.vue` 和 `AiFeedbackCard.vue` 内含 scoped 样式，不能只改全局 CSS 就完成迁移。
- 部分组件使用 inline style，例如账单图标背景、置信度条宽度和颜色。
- `main.js` 是显式 CSS 加载清单，新增 PWA 生成产物前必须明确加载顺序。

粗略盘点为 13 个 CSS 文件、约 50 个全局 CSS 变量、约 1,100 个样式规则和数百处直接颜色值。这个规模适合分阶段收口，不适合一次性全量替换。

### iOS Token 不能直接覆盖 PWA

iOS 设计系统提供 9 套主题，PWA 当前只有一套已经稳定的暖纸绿基线。两者的层级、圆角、导航高度和平台交互不同：

- iOS 使用原生 TabView；PWA 使用 `72px` 底部导航和中央 FAB。
- iOS 卡片 Token 偏大，PWA 当前信息密度更高，不能直接把所有圆角改成 iOS 的卡片圆角。
- iOS 主题中的 `paper/brand/light/space/ink/muted/coral` 可以作为未来语义映射，但不应把 9 套主题全部暴露给 PWA。
- PWA 的图表、Bottom Sheet、图片预览和下拉刷新需要保留 Web 端自己的交互实现。

## 后续接入建议

等 iOS 效果确认后，再按以下顺序处理 PWA：

1. 先选定一个默认主题和一组 PWA 语义映射，不立即接入 9 套运行时主题。
2. 把 PWA 当前已稳定的变量与设计系统语义 Token 做映射表，保留旧变量名作为兼容层。
3. 先迁移应用壳层、按钮、标签、列表行和卡片，再迁移页面级特殊状态色。
4. 把中转站、记录详情和首页作为三条关键回归路径，逐页替换，不跨页面批量替换硬编码颜色。
5. 每一阶段都保留图片有/无、识别失败、低置信度、空态、长文本、未保存修改和删除确认等状态。
6. 最后再决定是否把 PWA 变量生成改为 `tokens.css`；在此之前不修改生成器和 PWA 入口。

推荐长期保留的“PWA Classic”资产：

- 暖纸色背景和深绿色主操作。
- 首页的统计卡、趋势摘要、数据域横向入口和按天摘要。
- 记录列表的高信息密度行布局。
- 中转站的证据缩略图、文字摘要、置信度和处理动作。
- `ChartPanel` 的三档数据成熟度。
- Bottom Sheet、下拉刷新、图片全屏查看和友好错误态。
