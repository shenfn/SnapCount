# ADR-013：渲染与曝光契约归属生产共享核心

> 状态：已接受（CORE-011 边界评估决策）
>
> 日期：2026-08-15
>
> 关联任务：CLEAN-001/A2、CORE-011

## 决策

1. surface 配置、渲染计划投影、曝光事件构造和曝光历史编译整体归属 `supabase/functions/_shared/expression-core/render-contract.mjs`。
2. 生产核心导出 `SURFACE_RENDER_CONTRACT_VERSION`，Planner、Delivery 和 Shadow 运行时代码引用同一版本事实。
3. Planner Lab 原路径保留薄 wrapper，重新导出生产核心全部公共入口。
4. Edge Planner 直接依赖生产 `buildRenderPlans`；Delivery/Shadow 只复用版本常量，不改变现有持久化编排。
5. SQL fixture 中的版本字面量作为历史数据库测试数据保留，不视为第二份 JavaScript 规则实现。

## 原因

当前模块小而内聚，四个导出共享同一 surface 和 exposure 语义。整体迁移既能消除最后一条生产反向依赖，也避免把字段可见性、曝光状态和新颖度历史拆成互不一致的实现。版本常量同时被交付校验和曝光持久化使用，继续硬编码会让契约升级出现静默漂移。

## 禁止事项

- 不得改动任何现有 surface、slot、字段路径、delivery state 或版本值；
- 不得把未知 surface 从抛错改成静默忽略；
- 不得放宽 preview/novelty/lifecycle 三重过滤；
- 不得把 Lab 模拟曝光函数接入生产数据库写入；
- 不得移除 `occurredAt` 缺失时的既有时钟 fallback；
- 不得修改 SQL fixture 的历史字面量来伪造“单一来源”；
- 不得在 CORE-011 中开始 PWA/iOS 或 Edge 编排重构。

## 回滚

若共享 fixture、旧 render 测试、完整 Planner 或 Edge check 出现行为差异，恢复 Edge 旧 import 并保留失败证据；不得先修改 surface 字段、生命周期白名单或历史断言再宣称迁移通过。
