# ADR-021：PWA 正式记录分层收拢

> 日期：2026-08-16
>
> 状态：已决定，PWA-052 至 PWA-055 已由 PR #83 实现

## 决策

1. 不建立同时拥有交易、收入、通用域、账户、钱包快照和删除的“大 Record Repository”。
2. 下一片只收拢正式记录读取 transport 与 DTO，`useStore` 保留并发、用户/run guard、局部降级和页面读模型。
3. 财务保存继续以 `save_transaction_with_account`、`save_income_with_account` 为原子权威；客户端不得拆回多步写入。
4. 中转来源继续由 Staging 原子归档负责；普通通用记录、wallet 快照和统一删除分别单独评估。
5. 已处理中转目标必须按显式记录类型读取，未知类型不得通过同时查询三张表猜测。

## 原因

这些行为虽然都在 `useStore`，但一致性要求不同。读取可以渐进下沉而不改变服务端事实；财务保存影响账户流水和余额；wallet 快照跨越记录、账户和还款周期；删除还包含表达与图片清理。按文件或表名合并会掩盖事务边界，增加半状态风险。

先迁读取能继续减少页面直连，同时把回归面限制在查询参数、DTO 和旧请求隔离。后续写入切片可以复用同一个读 DTO，但必须围绕各自权威入口建立 Feature，而不是追求一个万能 CRUD 层。

## 禁止事项

- 不在 Record Repository 中计算账户余额、创建或作废账户流水。
- 不把 wallet 快照当作普通 `data_records` CRUD。
- 不把 Staging 归档 RPC 包装进正式记录 Repository。
- 不把查询失败统一伪造成空数组。
- 不以删除 `useStore` 或减少文件行数作为完成标准。
