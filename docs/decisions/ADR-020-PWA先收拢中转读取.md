# ADR-020：PWA 先收拢中转读取

> 日期：2026-08-16
>
> 状态：实施中，PWA-047 评估 PR #80 已合并

## 决策

PWA-042 至 PWA-046 合并后，下一片先处理 `staging_records` 的开放队列和已处理列表读取 transport/DTO 映射。正式记录读取与写入、图片签名和还款候选不与该片混做。

## 原因

中转的三个主要写动作已经分别有 Repository/Feature 边界，但 `useStore.loadData` 仍直接查询两类中转列表并负责数据库列映射。把这两个查询先下沉，能消除一个明确的页面直连，同时保留当前 Store 的并发、用户/run guard 和补充加载时序，回归面可控。

正式记录读取同时服务首页、月份筛选、待补全账单和多域展示；图片签名涉及多个实体的权限策略；还款候选依赖账户周期。它们都不是中转读取 transport 的自然职责，提前混入会扩大切片并掩盖失败出口。

## 约束

- Repository 只负责查询参数、DTO 和传输错误，不计算 repayment candidate、不签名图片、不写页面数组。
- Store 保留 `loadData` 并发编排和 current user/run guard，旧请求不得覆盖新用户状态。
- 本片不修改数据库、Edge、iOS、生产配置或正式记录业务。
- 只有 PWA-047 至 PWA-050 的实现测试与回归证据完成后，才进入正式记录边界评估。
