# ADR-040：LOCAL-003 收缩为单设备 + 云端写入者同步

状态：已决定，进入实现

日期：2026-09-05

## 背景

LOCAL-003 当前协议把本地 iPhone、第二台 iPhone、PWA 和云端任务都视为可并发写入者。实际产品阶段只有本地 iPhone 的手动记账与云端 AI/维护写入是稳定存在的场景，第二台设备并发编辑尚无真实用户需求。现有多主协议还存在账户无版本投影、冲突无出口、批次毒丸回滚和派生流水投影漂移风险。

## 决策

Phase A 固定为“一个 profile 同一时刻只绑定一台设备 + 云端 AI/PWA 写入者”。绑定第二台设备时采用替换语义：以云端为准重新拉取，本地未上传事实不承诺跨设备合并。多设备并发编辑、人工冲突合并和跨设备写入保留到 Phase B，不得作为当前模板能力宣称。

Phase A 的同步不变量：

1. 单个批次按操作隔离失败；单操作失败写入 `rejected(reason)`，不能回滚同批已成功操作，也不能制造无法诊断的批次毒丸。
2. `version_conflict` 自动采用云端事实：丢弃受影响本地 outbox 操作并保留“云端已更新，请复核”诊断原因，应用同批远端快照，冲突状态在同步成功后归零，下一次同步可继续。历史遗留的 `unresolved` 状态不得永久阻断同步；用户通过提示重新检查记录，不提供人工 resolve UI。
3. 本地账户投影记录 `origin`（`local`/`remote`）。只有 `local` 账户可由待处理消费补偿账户 outbox；远端导入账户不得被再次上传。Phase A 不为账户引入客户端版本协议。
4. `remote_account_entries` 不再作为同步响应契约；流水是派生投影，本地从有效本地 expenses 重算，服务端余额继续由有效云端流水重算。
5. 生产 RPC 不包含可被 authenticated 用户触发的 `expired`/`force_failure` 测试钩子；金额转换必须四舍五入，时间解析必须支持 fractional seconds。

## 验证

先用生产 schema 同构 fixture 固定以下行为：单操作 rejected 不影响同批其他操作、冲突后可继续同步、远端账户不产生 outbox、活跃流水投影稳定、RPC 无测试钩子。随后在 GRDB 内存库与 PostgreSQL fixture 上运行确定性操作序列测试；真机只作为一次绑定替换和 AI 下行回归确认，不作为主要协议证明。

## 非目标

- 不在 Phase A 实现第二台设备并发编辑、CRDT、字段级合并或人工冲突解决界面。
- 不合并/清理现有根工作区，不执行生产迁移、部署或 TestFlight。
