# ADR-035：iOS 主产品与 PWA 维护模式

> 状态：已接受
>
> 日期：2026-08-23
>
> 关联任务：LOCAL-001

## 决策

芥子后续以 iOS 作为主产品和商业化主线，推进免登录、本地优先、可选云同步和可插拔 AI。PWA 保留现有云端架构并进入维护模式，不参加本轮本地数据库重构。

PWA 维护模式允许：

- 安全、兼容性和关键业务缺陷修复；
- 登录、云端数据查看、管理、导出和同步兼容维护；
- 共享业务契约、Supabase API 和数据库迁移的必要兼容调整。

PWA 维护模式暂停：

- 新数据域和非必要新功能；
- IndexedDB/SQLite WASM 本地优先重构；
- 为追平 iOS 而进行的新页面、AI 交互和商业化功能开发。

## 背景

当前 PWA 与 iOS 都以 Supabase 为业务事实来源。若两端同时改造为本地优先，需要并行建设两套本地存储、离线队列、同步冲突、导入导出和 BYOK 安全实现，显著扩大风险和验证成本。

iOS 是当前发布和商业化重点，也更适合依托 Keychain、系统文件保护和原生数据库构建隐私优先体验。PWA 已具备稳定的云端管理能力，可以作为同步后数据的浏览器入口继续存在。

## 备选方案

- 方案 A：PWA 与 iOS 同时改造为本地优先。能力一致，但改造面和双端漂移风险最高。
- 方案 B：彻底停止或删除 PWA。注意力最集中，但会失去现有云端管理入口和浏览器用户。
- 方案 C：iOS 主线、PWA 维护模式。保留已有价值，同时把本地优先风险集中在一个客户端验证。

## 选择原因

选择方案 C。它减少并行架构迁移，保留现有云端能力，并允许先在 iOS 完成完整垂直切片后再评估 PWA 的长期定位。

## 影响与边界

- PWA 未被废弃，不得以“冻结”为由删除其代码、测试、部署或后端兼容契约。
- iOS 未同步的本地数据不会出现在 PWA；产品界面必须解释此差异。
- 存储实现允许不同，但金额、时间、状态、账户流水、AI 事实和同步载荷契约仍必须单一来源。
- 商业套餐不得直接进入领域模型；套餐只组合本地、同步、Hosted AI、BYOK 等能力。
- 本决策不授权生产迁移、部署、TestFlight、第三方依赖引入或现有云端数据迁移。
