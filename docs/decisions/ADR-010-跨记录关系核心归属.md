# ADR-010：跨记录关系归属生产共享核心

> 状态：已接受（CORE-008 规格前置决策）
>
> 日期：2026-08-15
>
> 关联任务：CLEAN-001/A2、CORE-008

## 决策

1. `generateCrossRecordRelationshipCandidates` 归属 `supabase/functions/_shared/expression-core/cross-record-relationships.mjs`。
2. Planner Lab 原路径保留薄 wrapper；Edge Shadow 与 Delivery 直接依赖生产核心。
3. Edge 继续拥有跨表查询、用户过滤和来源 DTO 装配；生产核心不引入 IO。
4. 保留当前候选规则和输出结构，包括 hypothesis、`beneficiary: null`、180 分钟默认窗口、0.75 置信度门槛以及同域候选的现状行为。
5. 不抽取跨记录公共 primitives，不把关系规则并入 comparison 或 generic-domain。

## 原因

当前实现已经是独立纯函数，输入输出边界清楚，直接测试覆盖核心反例。把它迁到生产核心可以消除 Edge 对 Planner Lab 的一条反向依赖，同时不需要改变查询编排或产品语义。

## 禁止事项

- 不得在迁移中扩展 `timeZone` 语义或改写时间计算；
- 不得把 hypothesis 改成 confirmed、补推 beneficiary 或因果链；
- 不得扩大来源查询、改变状态过滤或凭 fixture 调整掩盖行为差异；
- 不得以“跨记录”命名为由顺手禁止同域候选；该产品决策需另立 Spec。

## 回滚

若共享 Node/Deno fixture、旧回归或完整 Planner 发现行为差异，恢复 Edge 旧导入并保留失败证据；不得先改断言再宣称迁移通过。
