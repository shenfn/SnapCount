# ADR-018：复用中转原子归档 RPC

> 日期：2026-08-16
>
> 状态：已确认方向，待分片验证

## 决策

1. `archive_staging_record` 是中转归档唯一写入权威，不新建第二套客户端补偿事务。
2. 先补数据库行为 fixture，再迁移 PWA；两个关注面使用独立分支和 PR。
3. PWA 通过 Staging Repository/Feature 调用 RPC，`useStore` 只保留兼容门面和读模型收敛。
4. 财务字段缺失时进入人工补全，不得以 `0.01`、默认平台或默认支付方式制造业务事实。
5. 生产迁移 `20260808054219` 与仓库 `20260808120000` 的版本差异继续登记；只读函数证据可证明能力，但不得据此擅自修复迁移历史。

## 原因

现有 RPC 已提供行锁、用户隔离、账户保存、唯一关系、中转终态和路由反馈的单事务边界，iOS 与 PWA 部分路径也已使用。继续扩展客户端多步流程只会增加半状态和重复写风险。数据库行为测试必须先于客户端接线，因为客户端测试无法证明事务回滚、账户流水和租户隔离。

## 禁止事项

- 不让 PWA 直接更新 `staging_records.status = archived`。
- 不让 PWA 为中转归档直接插入正式表或 `user_routing_feedback`。
- 不用默认值绕过金额或必填字段校验。
- 不在同一切片处理生产迁移 repair、历史孤儿和 iOS 重构。
- 不把静态源码正则当成事务行为证明。
