# ADR-011：实体归一化规则与公开配置分离归属

> 状态：已接受（CORE-009 规格前置决策）
>
> 日期：2026-08-15
>
> 关联任务：CLEAN-001/A2、CORE-009

## 决策

1. 实体归一化规则归属 `supabase/functions/_shared/expression-core/entity-normalizer.mjs`。
2. `normalizeEntityText` 继续唯一归属 `expression-core/index.mjs`，entity-normalizer 直接复用，不复制实现。
3. 公开别名配置归属 `supabase/functions/_shared/expression-config/entity-aliases.public.v0.1.json`，由调用方加载并传入 `compileMerchantAliases`。
4. Planner Lab 原路径保留 wrapper；Edge 直接引用生产规则和生产配置。
5. 配置数据与规则代码分离，核心模块不得自行读取 JSON 或任何 IO。

## 原因

规则函数无环境依赖且已有完整边界测试，适合独立迁移；但别名 JSON 是生产输入契约，继续留在 `tools` 会保留反向依赖。把配置放进共享配置目录可以同时保持纯函数边界和生产可追溯性。

## 禁止事项

- 不得复制 `normalizeEntityText` 或改变 CORE-001 的输出；
- 不得因提高匹配率而放宽行政前缀、法律尾缀和歧义门禁；
- 不得把配置加载、别名持久化或数据库查询放入 expression-core；
- 不得以当前配置为空为理由删除配置版本契约；
- 不得把实体归一化与候选、评分、比较或跨记录模块合并。

## 回滚

若 Node/Deno fixture、Planner 回归或 Edge 检查发现行为差异，恢复旧 wrapper/import 并保留失败证据；不得先修改实体边界断言再宣称迁移通过。
