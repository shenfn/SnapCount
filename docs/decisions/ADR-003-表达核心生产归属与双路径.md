# ADR-003：表达核心生产归属与双路径

> 状态：已接受（A2 规格前置决策）
>
> 日期：2026-08-15
>
> 关联任务：CLEAN-001/A2、CORE-001

## 决策

1. 生产规则的唯一权威目录是 `supabase/functions/_shared/expression-core/`。
2. Planner Lab 只能作为离线编排和评估入口，通过 adapter 复用生产核心；生产入口不得依赖 `tools/` 作为新权威来源。
3. Planner 编排和确定性 fallback 两条运行路径都保留，但金额、时间、实体、证据和禁说规则只实现一次。
4. 第一切片使用无环境依赖的 ESM JavaScript，并用同一份 fixture 在 Node 与 Deno 下验证。

## 背景

当前 `expression-shadow-planner.ts` 从 `tools/ai-validation/expression-planner` 导入多组规则。它能运行，但生产依赖实验目录，目录迁移或运行时变化会导致不可预期的打包风险。另一方面，线上不可依赖 Planner 永远可用，确定性 fallback 必须保留。

## 选择原因

- `_shared` 由生产 Edge 拥有，依赖方向稳定，也能被离线 Lab 复用。
- 保留双路径满足线上降级和可恢复性，不把“单一事实源”误解为“单一路径”。
- ESM 纯函数可以在 Deno/Node 使用同一份实现，避免双环境各写一份规则。

## 禁止事项

- 不得以“清理重复”为由删除 fallback。
- 不得让 `_shared/expression-core` 读取数据库、网络、环境变量或调用模型。
- 不得把 Planner Lab 目录重新设为生产权威，或在 PWA/iOS 复制事实计算。
- 不得在没有特征测试和迁移回归的情况下批量改写全部 Planner 导入。

## 回滚

每个迁移切片保留独立提交；若新核心输出与旧路径不一致，先恢复生产入口到上一提交，保留 Lab 对比结果和失败 fixture，不删除旧模块，直到差异有明确决策。
