# ADR-014：PWA 保留兼容门面并按业务边界收拢

> 状态：接受
>
> 日期：2026-08-16

## 决策

保留 `useStore` 作为阶段性兼容门面，内部按认证会话、正式记录、中转生命周期、账户还款、数据域读模型、设置隐私和表达反馈拆分。每个写入边界由 Feature State/Use Case 编排，通过 Repository 访问 Supabase/Edge；纯 Domain 不依赖 Vue 或传输层。

## 原因

- 24 个组件共享当前 Store API，一次性替换会把架构调整变成全应用行为重写。
- 当前 `src/domains` 已保持无 Vue/网络依赖，应沿用已有骨架。
- 服务端 RPC 已承载账户与记录事务权威，客户端 Repository 不应复制规则。
- 业务边界比“每个数据域一个 Store”更能控制跨域流程和依赖方向。

## 禁止

- 不以“拆小文件”为目标复制第二份业务规则。
- 不让 Repository 计算金额、时间、状态出口或账户影响。
- 不让 Feature 互相 import 形成环；跨边界协作通过门面或显式事件。
- 不为本次收拢引入新的全局状态框架。

## 回滚

每片迁移都保留 `useStore` API；如新 Feature 出现回归，可以通过普通 revert 恢复门面内部实现，不需要同步回滚页面。
