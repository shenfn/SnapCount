# ADR-038：L1 免登录采用本地安全壳与显式账户准备

> 状态：已接受
>
> 日期：2026-08-23
>
> 关联任务：LOCAL-002-UI

## 决策

L1 在无 Supabase session 时进入只包含本地 Records 和本地 Settings 的安全壳；首次账户必须由用户显式创建，不静默生成“现金”或任何默认账户。

已有有效 session 的用户暂时保留现有云端五 Tab，以避免在迁移和同步尚未实现时破坏生产用户。这个兼容表面必须在 L2/L3 完成迁移与同步后收敛到统一 Local-First 流程。

L1 本地设置不提供普通登录入口。登录只在后续“开启云同步”流程中出现，且必须同时说明绑定、上传和冲突边界。

## 原因

- 直接放开现有五 Tab 会暴露多个远端 session 依赖，形成伪免登录。
- 静默创建账户会制造用户未确认的余额事实，并掩盖默认账户字段尚不存在的问题。
- 同步未实现时登录会切换到旧云端 UI，使本地记录暂时不可见，容易被误解为数据丢失。
- 本地安全壳允许消费垂直切片先形成真实闭环，同时保持旧用户稳定。

## 禁止误读

- 不得把“本地安全壳 / 旧云端壳”扩展成两套长期业务 Repository。
- 不得以减少步骤为由静默创建本地账户或把第一账户当持久默认。
- 不得在 L1 加一个只负责登录、却没有同步说明和本地数据出口的按钮。
- 不得向未登录用户展示会调用云端后才失败的页面或按钮。

## 影响

- Root、Records、Manual Record 和 Settings 需要显式的本地展示边界。
- AppState 需要通过 Local Use Case 加载账户和月份；View 不直接访问 GRDB。
- 本地详情、同步登录、其他域和完整账户管理继续由后续切片承担。
