# ADR-039：iOS 统一页面与本地权威同步

> 状态：提议
>
> 日期：2026-08-23
>
> 关联任务：LOCAL-003

## 决策

iOS 采用一套业务页面和一套本地事实来源。登录状态不再选择本地页面或云端页面；它只决定云端身份和同步能力是否可用。

- GRDB 本地数据库是当前设备即时可见的业务权威；
- 所有页面通过本地 Repository / Use Case 读取和写入；
- Supabase 是用户主动开启同步后的云端副本，以及需要身份的托管能力；
- 本地写入通过事务同时写业务事实、账户流水和 Outbox；
- 同步由独立 Coordinator 编排，不进入页面和领域模型的登录分支；
- 登录前后页面不切换，首次绑定必须显示范围预览并由用户确认；
- 退出登录停止旧同步任务，但保留本地数据。

## 背景

L1 为了先完成免登录消费闭环，暂时保留了“本地安全壳 / 旧云端壳”。该过渡设计保护了已有用户，但在 TestFlight 真机上暴露出明显体验问题：本地用户无法回到原账号，且登录后若直接切换旧云端页面会让本地记录暂时不可见。

继续扩展两套页面会造成：

- 本地和云端行为长期分叉；
- 同一条记录存在两种保存、详情和余额语义；
- 登录、同步和 AI 供应方耦合到页面层；
- 后续每个数据域都需要重复实现本地/云端两套流程。

## 备选方案

### 方案 A：继续维护本地壳和云端壳

拒绝。短期改动少，但会把临时兼容路径固化成两套产品，无法稳定处理本地记录与原账号共存。

### 方案 B：登录后直接切换到云端页面

拒绝。会让本地记录暂时消失，且把云端可用性重新变成页面可用性的前置条件。

### 方案 C：统一页面，本地权威，可选同步

采用。它保留免登录体验，同时允许老用户登录、查看云端数据和逐步同步；同步失败不会破坏本地事实。

## 影响范围

### 正面影响

- 用户不需要理解“本地 App”和“云端 App”的差异；
- 页面、表单、详情和账户余额只有一套业务语义；
- 离线、本地隐私和云端同步可以独立演进；
- PWA 继续读取云端副本，不需要参加本地数据库重构。

### 成本与风险

- 需要补齐本地详情、编辑删除和统一读模型；
- 需要增加同步元数据、代次隔离、幂等和冲突出口；
- 首次绑定必须设计清楚，不能用一个普通登录按钮替代；
- 账户、流水和还款同步需要独立的高风险测试。

## 不可被“顺手清理”推翻的边界

- 不得为登录保留第二套长期业务页面；
- 不得以登录成功为由自动上传本地业务数据；
- 不得用云端余额字段覆盖本地流水派生余额；
- 不得用最后写入覆盖解决账户或财务冲突；
- 不得让页面直接调用 Supabase 或把同步状态散落在多个 View；
- 不得因同步失败撤销本地已提交事实；
- 不得在本片把其他数据域一起接入，必须逐域建立 Spec 和 TDD。

## 后续验证

实现必须以 `LOCAL-003` 规格中的场景矩阵为准，至少通过本地断网、重启、登录绑定、退出保留、重复同步、冲突出口、账户余额和旧用户回归测试。
