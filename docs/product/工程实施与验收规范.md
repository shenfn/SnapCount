# 本地优先工程实施与验收规范

> 版本：v0.1（精简流程基线）
> 目标：把设计、开发、测试和发布串成一条可复核的链路，避免文档数量超过实际需要。

## 1. 唯一主流程

```text
产品目标与范围
  → 高还原原型
  → 域级工作包（需求 + 必要技术方案 + Spec + 验收场景）
  → TDD/测试设计
  → 最小实现
  → 原型对照验收
  → 功能验收
  → 发布验收
```

原型先行是进入业务开发的门槛。没有明确范围、原型入口、场景编号和测试层映射，不开始实现；发现范围扩大时先暂停并重新评审。

## 2. 文档控制

长期只保留三份总文档：

1. `docs/product/本地优先产品总PRD.md`：为什么做、做什么、不做什么、阶段边界。
2. `docs/product/本地优先原型总览.md`：所有产品表面、页面和流程的设计与验收入口。
3. 本文：工程实施、测试层次、验收和发布规则。

每个数据域最多一个域级工作包，合并需求、Spec、原型链接、验收场景和开发状态。只有跨模块且需要长期约束的架构决策才新增 ADR；普通修复、评审意见和一次性过程记录不再拆成重复文档。

## 3. 验收分层

| 层次 | 核对内容 | 主要证据 |
|---|---|---|
| 原型一致性 | 页面结构、信息层级、流程路径、状态和反馈 | 原型链接 + 逐页/逐流程记录 |
| 业务功能 | 金额、时间、权限、幂等、删除级联、同步失败出口 | 场景化单测/集成测试、数据库契约测试 |
| 端到端 | iOS/PWA/Edge/Supabase 之间的真实数据流 | macOS XCTest、PWA/Edge/Release Validation |
| 发布 | 固定提交、迁移兼容、构建产物、真机核心路径 | CI 运行、构建号、真机验收记录 |

测试固定事实、不变量、边界和失败出口，不把某一句 AI 文案当作唯一正确答案。验证结果必须区分业务失败、环境失败和未验证。

## 4. 开发完成与验收通过

开发完成至少意味着：

- 原型中的主流程、关键状态和失败出口均已实现或有明确的设计变更记录。
- 对应场景在适用测试层通过；已有行为先固定，新增行为按红灯→最小实现→绿灯→回归执行。
- 本地数据、云端数据、图片、导入导出和重启/断网等承诺范围没有未说明的缺口。

验收通过还需要：原型对照通过、功能测试通过、发布门禁通过。任何一层未执行只能标记“未验证”，不能写成“完成”。

## 5. Worktree 与主工作区

- `D:\Business\count` 是长期主工作区；根目录现有 WIP 默认属于用户，保护、不覆盖、不清理、不擅自归类。
- 收拢前先只读审计每个 worktree 的分支、提交、未提交文件和归属，形成保留/归档/清理清单。
- 已合并或明确废弃的 worktree 逐个处理；最多保留一个必要的短期隔离 worktree，不使用批量清理命令。
- 任何代码任务开始前仍须读取 `AGENTS.md`、当前 Spec/ADR/交接快照，并检查 `git status --short --branch` 与 `git worktree list --porcelain`。

本规范只定义方向和门禁，不替代具体域的业务 Spec；具体行为以产品原型、域级工作包和现有跨端契约共同为准。
