# 芥子本地优先产品总 PRD

> 版本：v0.1（设计基线）
> 状态：用于原型设计与范围评审，未替代现有业务 Spec。
> 原则：先定产品边界和用户体验，再进入实现。

## 1. 产品定位

芥子是一个以个人记录为入口的 Personal AI Memory 产品。当前可见的记账能力只是第一个样板域，长期目标是把财务、运动、睡眠、饮食、阅读等生活数据沉淀为用户可控的长期上下文。

本地优先不是“离线也能打开”的附加选项，而是产品的隐私承诺：用户的核心记录应先在设备上可用，登录和云端能力是可选增强；云端 AI/PWA 可以参与处理，但不能让用户失去对本地数据的使用权、查看权和导出权。

## 2. 产品目标与边界

### 目标

- 不登录也能完成核心记录闭环。
- 记录、编辑、删除、查询和余额等核心结果在本地即时可用。
- 图片、导入导出、重启、离线、失败重试和数据删除都属于完整体验，而不是后补功能。
- 用户选择绑定云端后，能看到云端产生的记录，且本地编辑、云端 AI/PWA 写入和同步失败都有明确状态与出口。
- 体验以高还原原型为准，功能以稳定性、数据完整性和隐私边界为准，为后续商业化建立可信基础。

### 当前不承诺

- 两台设备并发编辑同一条财务记录。
- CRDT、多主冲突合并或复杂人工 resolve UI。
- 在所有数据域尚未完成本地核心体验前，扩展新的云端同步承诺。

## 3. 系统角色

| 角色 | 主要职责 | 本地优先边界 |
|---|---|---|
| iOS | 用户主要入口；记录、查询、编辑、删除 | GRDB 本地数据是本地体验的事实来源 |
| PWA | 云端维护入口；登录后管理记录和账户 | 不替代 iOS 本地能力；属于云端写入者 |
| Edge Function / AI | 图片识别、候选生成、云端创建记录 | 结果可下行到设备；失败必须可诊断、可退出 |
| Supabase | 认证、云端事实、同步接口和 RLS | 用户选择绑定后才参与同步；不作为离线唯一依赖 |

## 4. 第一阶段产品范围

第一阶段只把 Expense + Account 做成完整的本地核心样板域，再以同一标准复制到其他域。

1. 首次进入与本地使用：说明隐私边界、无需登录进入、创建本地账户。
2. 记录闭环：新建、编辑、删除、今日/月视图、详情、空态和错误态。
3. 账户闭环：余额、账户影响、归档/恢复等已承诺能力在本地可用。
4. 图片闭环：相册导入/拍摄、识别中、待确认、失败、缺图和本地展示状态可见。
5. 数据管理：导入、导出、恢复、删除和迁移提示，明确数据是否仍只在本地。
6. 云端绑定：登录、绑定预览、首次导入、云端写入下行、本地上传、同步中/失败/重试、退出登录和本地数据保留。
7. 生命周期：杀掉应用后重启、断网恢复、重复操作、部分失败和数据清理均有可验证出口。

“完成”不是按钮出现，而是上述流程从入口到结果可走通，并且与原型中的页面、状态和信息层级一致。

## 5. 后续范围

收入、钱包/负债、运动、睡眠、饮食、阅读和通用数据域先进入产品地图和原型排期；每个域必须先完成本地核心体验原型、边界和验收场景，之后才安排工程实现。除非重新评审，不把未来域提前接入复杂同步协议。

## 6. 变更与验收原则

- 原型决定用户看到什么、怎么走、有哪些状态；Spec 决定金额、时间、权限、幂等、删除和同步等业务规则。
- 原型与实际实现不一致时，不能以“功能可用”直接收口：要么修改实现，要么明确记录并重新评审设计变更。
- 功能验收、原型一致性验收和发布验收缺一不可；任何“未验证”都不能写成“已完成”。
