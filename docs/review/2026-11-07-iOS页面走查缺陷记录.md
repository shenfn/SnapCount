## 1. 结论

页面不是"只差视觉微调"。走查发现三类问题会直接影响上架：

1. **内部信息外泄**：设置首屏直接显示带 UUID 的刷新诊断原文；观察页把"待接入 / 已就绪 / 模板预览"这类构建状态当指标展示；迁移页引导用户"导出一份文档交给 AI 做整体分析"；227 条列表用数据库表名和字段名当原因说明。这类文案会被审核和用户同时判为"开发版"。
2. **同一事实在不同页给出互相矛盾的数字**：迁移摘要写"当前已读取待核对 0"，下一页就是"本机已保留 227 条"；摘要写"已缓存图片 73"，入库表只有 13 条、磁盘 12 个文件；摘要写"当前已读取正式记录 7"，另一个页面写"本机已确认消费 886"。这比"227 条 unresolved"本身更危险——用户和审核都无从判断哪个是真的。
3. **227 条未解析记录是死路**：能看、能滚，不能补全、不能忽略、不能批量、不能导出，也没有按原因分组。四域、收入、钱包都正常，唯独这一块把用户永久卡在"历史数据没迁完"的状态里。

此外全站金额格式三套并存（`¥-787.22` / `-¥15.68` / `¥17041.02` 无千分位），域 key 直接渲染（列表副标题 `food` / `life`，AI 摘要"分类 food"），超大字号下记录行碎成竖排。这些不是"再美化一下"，是"看起来不像成品"。

## 3. 逐条明细

### UI-01 设置首屏展示内部刷新诊断（P0）

- 现象：设置最底部"本机列表刷新诊断"卡片直接打印：
  > 本机列表刷新失败。数据已保存；当前列表尚未刷新。原因：原数据已保存但本机列表尚未刷新 只重试读取本机列表不要重复执行原保存操作 诊断编号：937f8f4b-a0b7-4d4e-a37e-cbe4245b3f6f。
- 三个问题叠在一起：面向开发的原文、无标点的堆叠句、会话级 UUID。
- 代码：`SnapCount/Features/Settings/SettingsView.swift:865` 起 `localProjectionRefreshDiagnostic` 分区无条件渲染。
- 同源数据：`Library/Application Support/JieziLocalData/history-migration-diagnostics.json`，本次走查库里 11 条 `SYNC-TRANSPORT` / `LOCAL-POST-COMMIT-REFRESH` 记录，全部会进 UI。
- 验收：默认态不出现；只有"关于 → 版本号连点"或独立诊断入口可见；对外文案必须是人话（"本机列表没能刷新，数据已保存，可重试"），UUID 保留在导出包内。

### UI-02 云同步三态自相矛盾（P0）

- 现象：同一张卡片内
  - 本机数据 → 保存在此 iPhone
  - 云端身份 → **未登录**
  - 云同步 → **账户与消费已同步**
- 未登录却"已同步"，用户无法判断数据到底在哪。下方还有一段 12pt 说明：
  > 普通同步范围：账户与消费；账户流水由本机消费投影维护。收入、四域记录、钱包快照、候选和还款不在此同步范围。"已同步"不代表历史全量迁入或云端完全一致。
- 代码：`SettingsView.swift` 数据与同步 Section。
- 验收：状态机三态互斥（未登录 / 已登录·未同步 / 已登录·已同步 N 项）；"已同步"必须带范围与时间；免责口径移到"同步说明"二级页。

### UI-03 / UI-04 迁移摘要数字与库、与同 App 另一页冲突（P0）

实测库（`Library/Application Support/JieziLocalData/jiezi.sqlite`）：

| 表 | 行数 |
|---|---|
| `local_expenses` | 890 |
| `local_records` | 253 |
| `local_income_records` | 27 |
| `local_pending_transactions` | 74 |
| `local_history_unresolved_records` | **227** |
| `local_image_intakes` | 13（磁盘 `images/intake` 12 个文件） |

页面说法：

| 位置 | 指标 | 值 |
|---|---|---|
| 历史数据迁移（摘要） | 当前已读取正式记录 | 7 |
| 同上 | 当前已读取待核对 | **0** |
| 同上 | 已缓存图片 | 73 |
| 同上 | 待补全账单 | 73 |
| 历史数据迁移（盘点表） | 本机·已确认消费 | 886 |
| 历史待核对 | 本机已保留 | **227** |

- 问题不在数字本身可能"口径不同"，而在**页面从不说明口径**，且同一 App 内 0 与 227 同时成立。
- 代码：`HistoryMigrationView.swift`（摘要区）、`HistoryImportSummary` 相关映射、`LocalHistoryUnresolvedRecordsView.swift`。
- 验收：每个计数旁标注口径（本次读取窗口 / 全库 / 云端）；"待核对"只允许一个真源，为 0 时明细页不得存在 227 条。

### UI-05 227 条未解析是只读死路（P0）

- 现象：每行形如
  > 历史候选
  > staging_records.status 缺失或没有当前迁移映射，记录 #f2f619ec36。
  > 历史数据记录
  > data_records.occurred_at 缺少可确认的真实日期，记录 #7cf0bd1a49；不会用 created_at 代替。
- 全页无筛选、无分组、无搜索、无操作按钮，227 条同质重复。
- 代码：`LocalHistoryMigrationUseCase.swift:156` 生成"`表名.列名` + 记录 #hash"；`LocalHistoryUnresolvedRecordsView.swift` 只渲染。
- 验收：
  1. 原因用用户语言分类（缺日期 / 缺数据域 / 图片不支持 / 金额无法解析 / 重复），每类给条数与一句话解释；
  2. 至少一种闭环：手动补全、标记忽略、批量忽略、导出 CSV；
  3. 顶部一句话说明"这些记录已保存在本机，不计入账目，可稍后处理"，替代当前技术说明。

### UI-06 观察页把构建状态当指标（P0）

- 证据文字："入库链路 → 待接入""展示组件 → 已就绪""趋势 → 模板预览"。
- 代码：`SnapCount/Models/NativeDomainPresentation.swift:88-89`（`NativeDomainMetric(label: "入库链路", value: … "待接入")`、"展示组件"/"已就绪"）、`…:55`（`trendScope: records.isEmpty ? "模板预览" : "本周"`）。
- 验收：无数据时只出现空状态文案与行动入口；"已就绪/待接入/模板预览"不出现在任何用户可见文案中。

### UI-07 域 key 直接进 UI（P0）

- 现象：记录列表副标题 `food`、`life`；AI 摘要"…渠道 美团，分类 **food**。"
- 代码：副标题来自 `NativeDayRecord.subtitle`，来源 `LocalFactReadModel.swift:41`（`subtitle: fact.summary`）与 `NativeDataService.swift:1119`（`row.summary ?? domainName(row.domainKey)`）；AI 摘要 `RecordsView.swift:745`。
- 验收：建立 `domain/category → 中文` 唯一映射；UI 层禁止出现 `expense/income/food/sport/reading/sleep/life` 等 raw key；补一条快照测试拦截。

### UI-08 金额格式三套并存（P1）

| 位置 | 实际渲染 | 问题 |
|---|---|---|
| 钱包 微信钱包 | `¥-787.22` | 负号在币符后 |
| 钱包 兴业银行 | `¥17041.02` | 无千分位 |
| 详情 顶部 / 抽取字段 | `¥15.68` vs `-¥15.68` | 同一笔金额正负不一致 |
| 记录列表 | `¥100`（日合计） vs `¥2.00` | 小数位不统一 |
| 观察 | `¥0` | 整数无小数 |

- 代码：`AccountsView.swift:120` `String(format: "¥%.2f", account.currentBalance)`；`LocalFactReadModel.swift:143/149`；`DomainsView.swift:214` `"%@¥%.2f"`；`InsightsView.swift:532-533`；`RecordsView.swift:261`。全站至少 12 处各自 `String(format:)`，没有统一 Formatter。
- 验收：唯一 `JieziCurrency`（千分位、`-¥1,234.56`、负数统一前置、列表/详情小数位规则一致）；负数、零、超大额三个快照用例。

### UI-13 迁移相关入口与标题重名（P1）

### UI-14 收件箱图片条目（P1）

- 12 张图全部 `shortcut-jpeg.jpg`；缩略图是快捷指令编辑界面（能读到"芥子-截图""上传 JPEG 到芥子"）；每条重复三个按钮，没有全选/批量丢弃/批量重试；卡片高度随缩略图参差。

### UI-15 不可恢复项仍给"重试识别"（P1）

### UI-17 手动记录表单模型（P1）
